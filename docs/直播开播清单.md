# YouTube 直播开播清单

> 2026-10-27 更新。只做 YouTube 单平台演示；正式链路不使用其他聊天中转或站外打赏。F9 模拟测试不等于真实直播验收。

## 一、一次性准备

1. 在 Google Cloud 新建项目，启用 **YouTube Data API v3**。
2. 创建 API 密钥，并把 API 限制设为 **YouTube Data API v3**。密钥由本机 Node 服务使用，不要按浏览器密钥设置“网站”限制，也不要公开。
3. 确认频道已开通 Super Chat / Super Sticker；未开通时，免费弹幕和增长积分仍可测试，但没有真钱入口。
4. 启动游戏开发服务。`npm run dev` 会同时启动本机 `127.0.0.1:8787` 的 YouTube 服务；也可单独用 `npm run live:youtube` 启动它。

## 二、每次开播

1. YouTube 直播延迟选“超低延迟”。
2. 在直播控制室依次进入“修改 → 实时聊天”，把“谁可以发送消息”设为“订阅者”，所需订阅时长选最短，保存。这样新订阅者即可发免费指令，不需要游戏逐个查询订阅关系。
3. 游戏里按 F9：
   - 第一次填写 API 密钥和本场直播网址，回车。
   - 以后只换本场直播网址，密钥留空即沿用。
   - 密钥和账务保存在本机 `.local/youtube-live/`，不进入浏览器配置或 Git。
4. 等 F9 显示“YouTube 官方聊天流已连接”和“频道增长数据正常”。用订阅账号发一条测试弹幕，确认“最近弹幕”更新。
5. 只保留一个实际接收事件的游戏页面，避免两个页面同时操作同一场战斗。
6. 另用一个**非订阅测试账号**验证 Super Chat 是否仍能发送；在实测前，不宣称真钱入口也只限订阅者。

## 三、当前口令与积分

- 开战后发 `1` 站攻方、`2` 站守方，再发 `攻 / 胜 / 敌 / 混 / 并 / 败` 放六计。
- 玩家参战且官职至少为斥候时，发 `技3` 表示出 3 积分释放玩家技；出价高者先放，同价先到先得。
- 普通弹幕只标记在场，不直接发积分；站队也不送积分。
- 积分只发给最近 10 分钟发过言的人：点赞新增满一档、订阅数增长、本场在线人数创新高时发放。
- 3 积分放一次六计，最多攒 10 积分，按天清零；未释放的六计或玩家技原数退回。
- Super Chat / Super Sticker 进入独立的真钱余额，不与积分互转。原始金额、币种和事件编号由本机服务保存。

## 四、恢复与排障

| 现象 | 检查 |
|---|---|
| 本地 YouTube 服务未启动 | 启动 `npm run live:youtube`，再刷新游戏 |
| 找不到直播视频或活动聊天室 | 确认本场正在直播、聊天已开启、网址是本场而非上一场 |
| 接口 403 | 检查 YouTube Data API v3 是否启用、密钥限制和当日配额 |
| 弹幕不到游戏 | 确认 F9 聊天流已连接、发送账号符合订阅者专享条件 |
| 刷新或断线 | 服务端会重发未 ACK 事件；已 ACK 事件凭事件编号去重，不重复入账 |
| 非美元付款余额 | 当前只按代码内固定游戏折算率计技能余额，不代表实际结算汇率；原始付款记录不丢 |

**真实验收标准：**必须用真实 API 密钥、真实直播视频 ID、订阅账号和一笔真实 Super Chat 分别验证；本地 F9 与自动化测试通过，不算真实直播已跑通。
