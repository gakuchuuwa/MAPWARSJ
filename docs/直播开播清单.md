# YouTube 直播开播清单

> 2026-10-27 晚按现行代码重写。只做 YouTube 单平台演示；正式链路不使用其他聊天中转或站外打赏。官职先做到将军，全部用积分。F9 模拟测试不等于真实直播验收。
> 目标与步骤见 `docs/直播目标计划.md`。

## 一、一次性准备

1. 在 Google Cloud 新建项目，启用 **YouTube Data API v3**。
2. 创建 API 密钥，并把 API 限制设为 **YouTube Data API v3**。密钥由本机 Node 服务使用，不要按浏览器密钥设置“网站”限制，也不要公开。
3. 启动游戏开发服务。`npm run dev` 会同时启动本机 `127.0.0.1:8787` 的 YouTube 服务；也可单独用 `npm run live:youtube` 启动它。

## 二、每次开播

1. YouTube 直播延迟选“超低延迟”。正式开播选**公开**（不公开的直播不算观看时数）；试播可以用不公开。
2. 在直播控制室依次进入“修改 → 实时聊天”，把“谁可以发送消息”设为“订阅者”，所需订阅时长选最短，保存。这样新订阅者即可发口令，不需要游戏逐个查询订阅关系。
3. 游戏里按 F9：
   - 第一次填写 API 密钥和本场直播网址，回车。
   - 以后只换本场直播网址，密钥留空即沿用。
   - 密钥和账务保存在本机 `.local/youtube-live/`，不进入浏览器配置或 Git。
4. 等 F9 显示“YouTube 官方聊天流已连接”和“频道增长数据正常”。用订阅账号发一条测试弹幕，确认“最近弹幕”更新。
5. 只保留一个主记账页面；其他打开的游戏页面会等待接管。主页面关闭后，另一页可接管，不能同时记账。
6. 在聊天里发下面「置顶留言」并置顶。

## 三、当前口令与积分（与代码一致，2026-10-27）

全体观众共同操作同一个主角。主角在战略地图上自己找武将投奔；只有主角本人在这一仗里、而且官职至少是斥候，才能放技。官职先做到将军（平民→斥候→探马→先锋→将军），全部用积分。

| 口令 | 什么时候能用 | 花多少积分 | 结果 |
|---|---|---|---|
| `技3`（数字 1～100） | 打仗时 | 数字就是出价 | 主角爆发技，一发 12 秒。出价高的先放，同价先到先放，放完一发才放下一发。范围和强度按官职，见下表 |
| `攻` `胜` `敌` `混` `并` `败` | 打仗时 | 每计 3 分 | 主角六计，**按先后放**，不看出价。每人同时只排一计，全场每 10 秒最多放一计，所以后来的人不会被挤到后面。效果和武将的计相同，范围按官职、范围内加倍：斥候 ×3、探马 ×2、先锋 ×1.5、将军全军 ×1（和武将一样）。攻、胜加在强度上，混加在时长上，敌、并、败加在兵数上 |
| `名 新名字 5` | 任何时候 | 要高于当天最高价 | 立刻改主角名。最多 6 个字，带网址、长串数字、违规词的直接拦下、不扣分 |
| `投1 3` | 主角离开势力、在战略地图上时 | 不写分数＝在当前最高价上加 1 | 面板列出最多 5 个去处，主角当场改道。别人出更高价可改选，被改掉的人原数退回；没人选就照常自动找武将。能选什么按资历（本局最高官职），见下表。离开势力后功劳清零，但官职按资历保留，**不从斥候重来**；只有新开一局才从头开始 |

### 按官职分

| 官职 | `技3` 谁吃加成 | 身边的兵吃多少 | 放完要歇 | 离队后能选（落点永远是武将） |
|---|---|---|---|---|
| 平民 | 不能放技 | — | — | 自动找武将，不能选 |
| 斥候 | 只有主角本人 | — | 不用歇 | 上次同文化的**势力**，势力内**武将随机** |
| 探马 | 主角＋本队 | 和主角一样 | 不用歇 | 上次同文化的**武将**，指定 |
| 先锋 | 主角＋本排 | 伤害×2.5、攻速×1.5、受伤×0.4，回半血 | 6 秒 | 同文化**武将指定**；也可选**全部势力的武将（随机）** |
| 将军 | 主角＋全军 | 伤害×1.5、攻速×1.25、受伤×0.6，回三成血 | 12 秒 | **全部武将**，指定 |
| 元帅 | 同上 | 同上 | 同上 | 同上 ＋ 竞价选军队攻击目标 ＋ 挑立绘（先选文化，再从该文化补齐 10 张里选） |

> 元帅两项 2026-11-07 已定设计（`docs/直播九官职-战略权限单一口径.md` §三），**尚未接入直播**：先做挑立绘、后做选目标。

- 主角本人不论官职都是最强档：满血、伤害×4、攻速×2、受伤只剩四分之一。
- 范围越大，兵吃得越少、放完要歇得越久，免得整军一发就赢。这些是起步值，上播后按战报调。
- 玩家技和武将技分开：武将自己满槽放的计仍是全军，不受这张表影响。

### 积分

- **怎么来**（2026-10-29 重定：要有助于增加播放量，一直在线就一直能玩）。「在场」＝最近 10 分钟在聊天里说过话，发口令也算；YouTube 不给观众名单，不说话的看客认不出来、发不了分。
  - **在场每 3 分钟 +1 分**：约 10 分钟一仗，一直在场每仗够放一计；口令本身就是说话，一直在玩就一直在场。
  - **第一次来送 3 分**（第一次在本频道说话，第一句发「攻」也够）；**每天第一次来送 3 分**（老观众隔天回来）。
  - 点赞每满一档，在场每人 +1 分（在线 10 人以下或读不到人数时一个赞就是一档；人多了一档＝在线人数的十分之一，最多 50 个；一次最多 +3）；
  - 频道订阅数每涨 1，在场每人 +3 分＝一计（一次最多 +9）；
  - 本场在线人数创新高，在场每人 +1 分（10 人以下每多 1 人、50 人以下每多 5 人、再往上每多 10 人算一次）。
- **查分**：发 `积分`，面板记录里显示自己现有多少分。
- 刷新游戏页面不影响在场和积分（都存在本机服务的账本里）。
- 积分**一直保留**，不按天清零；单次出价最多 100 分，超过的口令直接拒收、不扣分。
- 这一仗打完还没轮到的技和计，积分原数退回；已经放出去的不退。
- 主播一键否决恶意名字：HUD 主角名字旁的「否决」。名字立刻恢复成上一个，该词以后都拦下，**出价的积分不退**。

### 置顶留言（复制粘贴，不超过 200 字）

```
【弹幕操控主角】订阅后发言即在场，10分钟内说过话每3分钟+1积分；第一次来送3分，每天回来送3分；点赞、新订阅全场加分。打仗时发 技1 主角爆发（出分高先放），发 攻 胜 敌 混 并 败 放计（3分先到先放）。名 新名字 1 改名，主角离队时发 投1 选去处，发 积分 查分。
```

## 四、恢复与排障

| 现象 | 检查 |
|---|---|
| 本地 YouTube 服务未启动 | 启动 `npm run live:youtube`，再刷新游戏 |
| 找不到直播视频或活动聊天室 | 确认本场正在直播、聊天已开启、网址是本场而非上一场 |
| 接口 403 | 检查 YouTube Data API v3 是否启用、密钥限制和当日配额 |
| 弹幕不到游戏 | 确认 F9 聊天流已连接、发送账号符合订阅者专享条件 |
| 刷新或断线 | 服务端会重发未 ACK 事件；已 ACK 事件凭事件编号去重，不重复入账 |
| 观众说口令没反应 | 先看面板最近记录：没在打仗、主角不在这一仗、官职还是平民、积分不够，都会写明原因 |
| 观众说打赏了 | 现在玩法只用积分，打赏不换技能；本机照原样留了记录（`.local/youtube-live/state.json`） |

**真实验收标准：**必须用真实 API 密钥、真实直播视频 ID 和订阅账号验证「观众发口令 → 主角在画面里真的做出来、只做一次」；本地 F9 与自动化测试通过，不算真实直播已跑通。
