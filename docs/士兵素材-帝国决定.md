# 士兵素材 ③ 帝国决定（AoE2 DE）设定

> 来源：AoE2 决定版（Definitive Edition），SLD/SLDX 格式。
> 铁律：**套用哪套游戏，就按哪套游戏原生做法；发现与游戏不符 → 照游戏改。**

## 目录与命名

- 目录：`public/SUCAI/SAMURAI_DE/`、`public/SUCAI/SAMURAI_ELITE/`、`public/SUCAI/ARCHER/`（按兵种新建独立目录；SAMURAI_DE = 普通日本武士，SAMURAI_ELITE = 精锐武士）
- 命名：`{action}_{0-7}.png`（主图）+ `{action}_{0-7}.pc.png`（玩家色遮罩），action ∈ `idle / move / attack / death`

## 格式

SLDX（SLD），从 `resources/_common/drs/graphics/*.sld` 提取。
- 主图层：DXT1(BC1) 压缩
- 阴影图层：DXT4(BC4) 单通道（脚底投影）
- 玩家色遮罩：DXT4(BC4) 单通道（**尺寸/坐标与主图层完全一致**，header 无 w/h）

## 方向

DE 直接存 **16 方向**（22.5°/格，DAT `angle_count=16`），取偶数角得 8 主方向。

`GAME_DIR_TO_DE_ANGLE`（游戏 dir8 → DE 偶数角）：

```
0(NE)→14  1(E)→0  2(SE)→2  3(S)→4  4(SW)→6  5(W)→8  6(NW)→10  7(N)→12
```

## 动作

`idle / move / attack / death` 4 个，`DAMAGE`、`SHOOT` 均复用 `attack`。

## 帧复用（reuse previous frame，已复刻 ✅）

SLD 主/阴影/玩家色遮罩图层 header 的 `flag1 bit7` 置位时，skip 块**不是透明**，而是**复制上一帧「同 canvas 坐标」的像素块**（openage 权威：`same position, same layer`）。

- 未复刻的症状：待命动画帧 1–3 的小腿被掏空（skip 当透明）、帧 4+ 因 shadow offset 变化出现水平杂线。
- 实装：`sld_extract.place_blocks` / `aoe2de_unit_convert.decode_shadow_gray` 的 skip 分支，按「上一帧 offset 差异」对齐 canvas 坐标复制；主图层、阴影、玩家色遮罩三层都走同一条 reuse 链（2026-08-15 视觉验证通过：弓手 idle 60 帧小腿完整、无杂线）。

## 锚点对齐（hotspot 对齐，游戏原生 ✅）

AoE2 DE 每帧有 **hotspot**（frame header 的 `canvas_hotspot_x/y`，实测就是 **canvas 中心**，如 150 画布→(75,75)）。openage 官方文档：hotspot 是「鼠标指针锚点」，渲染时**把 hotspot 对齐单位位置**，而**脚底相对 hotspot 是逐帧浮动的**——攻击时身体起伏（脚底偏移 +1~+17）、死亡倒地时脚底大幅下移（+8→+52）。

- **❌ 禁止「脚底对齐」**：把脚底钉死会让「身体中心」随动作反向浮动，死亡倒地时身体整体上移、横躺帧装不进固定 box。
- **box 是动态的**：= 该动作该方向所有帧「内容边界相对 hotspot 的并集」（精锐武士 death 东/西向 120×64、南向 40×112，各方向不同，非正方形）。
- **提取器**：`anchor_x = -rel_x1, anchor_y = -rel_y1`（hotspot 对齐 box 的 (-rel_x1,-rel_y1)），`box = Wrel×Hrel`，并输出 `_meta.json`（每动作每方向 `{fw,fh,hx,hy}` + 帧数）。
- **引擎**：DE 目录（`/SUCAI/ARCHER/`、`/SUCAI/SAMURAI_ELITE/`）读 `_meta.json` 走「动态帧框」渲染：源 = `fr*fw,0,fw,fh`，目标 = `hotspot 对齐单位位置 + 统一缩放 s`（`s = 单位像素 / 64` 站立高度参考）；S10DB/征服版仍走「正方形帧 + 中心对齐」原逻辑，互不干扰。
- **血训（2026-08-15 主人三次纠错定稿）**：之前「固定 64px 正方形 box + 脚底对齐 + 居中/clamp」全是 AI 擅自发明 → 精锐武士东/西方向阵亡「瞬间消失」（横躺帧 120px 把站立帧推出 box 外整帧裁空）。**商业游戏不会有这种 bug，问题一定是没搞清游戏模式**——AoE2 就是「逐帧动态帧框 + hotspot 中心对齐」，照它做就全对。
- **血训 2（2026-08-15 尸体贴图错乱）**：大地图方阵 `LegionPhalanxDrawer` 里，死亡动画的**贴图朝向**是 `slot.deathDirection`（随机 0-7），但 dyn 帧框却用了**编队朝向 `effDir`**。death 各方向 box 尺寸差异巨大（SW 40×112 vs SE 120×64），朝向错配 → `frameW/frameH` 用错 box、`sx=fr*frameW` 跨帧切到邻帧内容 → 靠旗/身体被切碎、尸体贴图全乱（主人实锤「尸体贴图都不正确」）。**帧框必须跟着「实际贴图朝向」走**：死亡用 `deathDirection`、非死亡用 `effDir`（`Scene13WarLayer` 的 `img` 与 `dm` 同用 `v.dir`，本无此问题）。
- **血训 3（2026-08-15 尸体「一个都留不下」）**：`Scene13WarLayer.bakeCorpse`（把「保留 1/3」裁定的尸体烙进地面图）仍用 S10DB **正方形帧假设**（`dieFw = b.fh = 84`）切 DE 动态 sheet（fw 40~120 不等）→ 末帧切片 `(dieN-1)*dieFw` 越界（切空白）或错位（切到站立帧靠旗区域 → 烙出「垂直小旗」碎片）→ 保留的尸体视觉上全丢。**教训：dyn 动态帧框的每一个渲染/合成入口都必须走 dyn，漏一个坏一个**——渲染循环走了 dyn，`bakeCorpse` 漏了。修复：`bakeCorpse` 对 DE 走 `b.dyn?.die?.[c.dir]`，与渲染循环同一套 hotspot 对齐 + 动态帧框；S10DB 保持正方形帧原逻辑。**排查「某机制对 DE 素材失效」时，先找「还有哪个渲染/合成入口没走 dyn」**。

## 引擎渲染参数（非素材格式，随素材一并记）

- **攻击动画帧率**（`LegionPhalanxDrawer.ts` 帧循环）：原 150ms/帧（决定版武士 45 帧 = 6.75 秒一轮挥刀，太慢）→ 2026-08-15 主人「攻击速度提高一倍」改 75ms/帧（`frameMs = animState==='ATTACK' ? 75 : 150`，移动/受击保持 150ms 不变）。帧循环基准是 `tick=Date.now()`（毫秒）。

## 玩家色（游戏原生机制，已复刻 ✅）

AoE2 DE 玩家色 = **独立 DXT4 遮罩图层**（`.pc.png`），遮罩像素值 = 玩家色强度（0=非玩家色，255=纯玩家色，中间值过渡）。

游戏渲染 = **luminance-preserving hue shift**（保留主图亮度、色相换成玩家色）+ 按遮罩强度与主图混合（martondobos 11.5 / openage 权威算法）：

```
out = main × (1 - mask/255) + playercolor(保留主图亮度) × (mask/255)
```

MAPWAR 已实装：`SpriteTinter.applyMaskTint` —— 只染遮罩区域，脸/皮肤/金属/武器保持原色（2026-08-15 视觉验证通过）。
