# 🔴 警告：战略地图据点的围墙尺寸，不许动（2026-10-11 主人令）

> 主人原话：「只修复战略地图中的，不要动战术地图。」
> 事故：战术模式「1.0 尺寸」的改动，被写进了战略地图与战术模式**共用**的围墙函数，导致战略地图的大城、中城城墙被放大（长安等城墙远大于建筑）。已修复一次，随后又被别的 AI 整档覆盖改回去，再修一次。

## 现行口径（改之前先读，别凭印象）

文件：`src/systems/TerritorySystem.ts`、`src/systems/cityWallShared.ts`

| 城型 | 战略地图（不传 `native`） | 战术地图（传 `native`） |
|---|---|---|
| 小城墙圈 | **S=5** | S=9 |
| 中城墙圈 | **S=6** | S=11 |
| 大城墙圈 | **S=7** | S=13 |
| 城门占位 | **3 槽**（`k >= S-1 && k <= S+1`） | 1 槽（`narrowGate = true`） |

- 实现方式：`native ? 战术值 : 战略值`；`buildRingWallAndGate` 与 `computeFortifiedWallAndGate` 的可选参数 `narrowGate` 默认 `false`（＝战略原样），战术侧传 `!!native`。
- 战略值 7 / 6 / 5 自 2026-09-10 起一直如此，**不是 bug，不许改**。

## 铁律

1. **战术地图要改尺寸，只许改 `native` 为真的那一支**；战略那一支（`native` 缺省）的数值、门槽、地基、建筑尺寸一个字都不许动。
2. **不许把 `native ? A : B` 简化成一个常数**；不许删 `narrowGate` 参数；不许把门槽写死成 `k === S`。
3. **不许整档覆盖** `TerritorySystem.ts` / `cityWallShared.ts`：只许用 Edit 改具体几行，改前先 `git diff -- src/systems` 看当前内容。别的 AI 可能刚改过，整档写回会把别人的修复冲掉。
4. 改完把 `git diff -- src/systems` 的逐行结果贴给主人，并说明「战略分支没碰」。
5. 不确定某处是战略还是战术在用，先问，不要猜。

## 验收

- 战略地图里看长安（大城）、凤翔（中城）：城墙应紧凑地围着建筑，不应远大于建筑。
- `npx tsc --noEmit` 零错误。
