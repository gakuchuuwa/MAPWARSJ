# 13 战斗剧本规范（Choreography Spec）

> 状态：**待实施**（2026-08-10 定稿，取代「编队自主寻敌」）
> 适用范围：**13 战斗场景**（跟拍军团 + 双将战）。8/9/10 一个像素不许动。
> 前置结论见 `docs/02-design/combat-visual-overhaul.md` §0.1 铁律。

---

## 0. 为什么换

2026-08-10 一天打了五刀补丁，「被友军挡住」的编队数 5~11 → 0~3 → 14，每修一刀冒一个新死结。
三方（ANTI / CC / DS）独立复盘结论一致：

**病根 = 编队自主寻敌 + 认领上限 + 硬碰撞 + 无让位 + 无寻路。**
这是多智能体路径规划（MAPF），启发式堆叠在数学上不收敛，**死锁是常态不是意外**。

不是引擎问题（Canvas 2D 从没到瓶颈，换 Godot/Pixi 同样死锁）。
不是「以编队为单位」的问题（那个选择是对的，保留）。

**关键前提：胜负在 t=0 就由八环战力锁定。这个模拟不产出任何影响结果的信息，
它唯一的作用是让画面动起来。**既然如此，就不该用会死锁的自主决策去实现它。

### DS 的修正（必须记住）

剧本法**不消灭**「9 打 9、谁打谁」的分配问题，只把风险从「每帧解一次」挪到「开局解一次」。
真实收益是**没有运行时不确定性**，不是「难度降低」。

但我们的编制是**固定 3×3、角色固定**（`LegionComposition.ts`，全文化区同构），
所以分配不是求解问题，是**查表**——见 §2。

---

## 1. 总原则

| # | 原则 |
|---|---|
| 1 | **没有碰撞检测。**删干净，不保留任何「撞上就停」的分支 |
| 2 | **没有运行时寻敌。**谁打谁在开战第 0 帧算死，全程不变（目标阵亡除外，见 §4.3） |
| 3 | **位置 = f(起点, 终点, t)。**单值函数，同样的输入永远同样的输出 |
| 4 | **朝向只有一个来源**——剧本指定。不许再出现「移动方向 vs 面向目标」两个信号源 |
| 5 | **引擎零改动。**八环、t=0 锁定、`applySceneFixedDuration`、六计、武将技全部原样 |
| 6 | **野战与攻城共用四幕**，只有第一幕的起点几何不同（§5） |

## 2. 角色表（核心）

3×3 编制固定如下（`HUAXIA_MIXED_TIERS` / `GENERIC_MIXED_TIERS` / `HUIHUI_MIXED_TIERS` 同构）：

```
Row 0  枪/盾/轻步 ×3     格位 0,1,2
Row 1  骑 / 将骑 / 骑     格位 3,4,5
Row 2  弓/弩 ×3          格位 6,7,8
```

剧本按格位写死：

| 格位 | 角色 | 剧本 | 终点 |
|---|---|---|---|
| **0,1,2** | 前排近战 | 与对面前排**一一对位**，直线压上咬死 | 对面同序号前排的正前方，前缘故意交错 **20~30px** |
| **3** | 左翼骑兵 | 绕战线**左端**，从侧翼接敌 | 敌方战线左端外侧，与敌最左前排咬合 |
| **5** | 右翼骑兵 | 绕战线**右端**，从侧翼接敌 | 敌方战线右端外侧，与敌最右前排咬合 |
| **4** | 主将格 | **前排身后居中压阵**，幕四才压上；触发武将技时可前压做演出 | 己方前排身后 1 个格位纵深，居中 |
| **6,7,8** | 后排远程 | 在自己阵位放箭 | 跟整军刚体平移（见下方修订） |

> **2026-08-11 实现修订**（`Scene13Choreographer.slotPlanAt`）：
> 远程排改为**跟着刚体一起平移**，不是「原地不动」——原地会把军团纵深越拉越长，
> 队形散掉且镜头框不住。它们的「不动」只是相对队形不动，绝对位置随军团走。
> 两翼骑兵（3/5）在消耗幕 30%~48% 之间绕出侧翼，不是在冲锋幕，
> 目的是让前排先咬住、骑兵晚半拍再上——**这是「第二排对着空气砍」的解**。

**九个编队没有任何一个需要穿过另一个** → 挡路问题从定义上消失。

这套分工在史实上也是对的：前排顶、骑兵包抄、弓弩在后、主将压阵。不是为绕开技术问题硬凑的。

### 2.1 远程取消射程判定

远程**不再用射程决定走不走**。战斗在进行 = 放箭，箭矢由 `ProjectileRenderer` 飞向对面前排。

> 射程只管「能不能开火」，从来就不该管「要不要走路」。2026-08-10 实测的两个荒谬
> ——弓手在 1731px 外播放攻击动作、以及「够不着所以站着」——都出在这条规则上。

`SQUAD_STOP_DIST_PX` 在剧本法下只剩「远程是否参与位移」的布尔含义，可整表删除。

## 3. 四幕时间轴

总时长 = 引擎给的战斗时长（`applySceneFixedDuration`，双将 10~30s，援军 +10s/只，封顶 60s）。
**按比例切，不改任何时长常量**，因此不影响援军加时与胜负分布。

| 幕 | 占比 | 内容 | 动画状态 |
|---|---|---|---|
| **一 列阵** | 10% | 两军在起点静止对峙，互相面对 | IDLE |
| **二 冲锋** | 20% | 前排 + 两翼骑兵按各自终点直线补间；远程与主将不动 | MOVE（远程/主将 IDLE） |
| **三 消耗** | 60% | 到位后原地互搏；精灵按兵力曲线自前排向后逐个 DEATH | ATTACK |
| **四 崩溃** | 10% | 败方整体后退散开，胜方主将格压上 | 败方 MOVE + 胜方 MOVE |

- 幕二的补间用 `easeInOut`，骑兵可比步兵早 0.2×幕二时长起步（视觉层次，不影响到位时刻）。
- 幕次推进用**战斗自己的时钟**（13 独立时钟已实现，`isStrategyPausedByScene`），不用墙上时钟。
- 用户真按暂停键 → 幕次冻结。

## 4. 终点坐标怎么算

### 4.1 战线基准（复用已有实现）

`solveSceneFieldAlign`（2026-08-10 已落地）给出：全场唯一中轴 `dir`、中点 `mid`、
阵心距 `gap`、同侧多军团沿垂直方向排开的侧向偏移。**这一段保留，剧本法直接用它算起点。**

### 4.2 一次性求终点

开战第 0 帧，对每个参战军团：

```
起点  = solveSceneFieldAlign 给的 aligned + 本格位 grid 偏移
终点  = 按 §2 角色表算（前排对位 / 两翼绕端 / 主将压阵 / 远程原地）
```

存进 `Map<squadKey, {from, to}>`，**全程不再重算**。

### 4.3 唯一允许的运行时分支：目标阵亡

对位的敌方前排整队阵亡（兵力扣光）时，本编队的终点**平移到相邻仍存活的敌方前排**，
用 0.5s 补间过去。**只允许这一种重算**，且它是单调的（对手只会变少不会变多），不会震荡。

## 5. 野战 vs 攻城

**只有第一幕的起点几何不同，二三四幕完全共用。**

| | 野战 | 攻城 |
|---|---|---|
| 起点 | 双方沿中轴**镜像对称**，各退半个阵心距 | 城图固定；守军起点 = 城图边缘外侧列阵；攻方起点 = 城外 `SCENE13_ATTACKER_GAP_PX` |
| 幕二 | **双方相向对冲** | **只有攻方压上**，守军在城前据守不前压 |
| 幕四 | 败方后退 | 守军崩溃 → 攻方主将格继续压向城图（咬城收尾） |

> 攻城是主体（约 90% 的战斗），但野战几何简单，**先用野战验证四幕跑得顺，再套攻城**。

## 7. 实施方式

1. **新建 `Scene13Choreographer`**，`getSquadOffsets` 整个换掉——**不是在里面加分支**。
   今天最大的教训就是三代假设叠在同一个循环里，谁都看不清分支交互。
2. **野战先跑通 → 攻城套上。**
3. 动手前打标签 + 快照（照 `定档-20260809` 的先例）。
4. **只许一个 AI 改 `GlobalUnitRenderer.ts`。**

## 8. 验收判据（硬指标，不靠肉眼）

探针（`scratch/scene13_probe_latest.json`，DEV 每 2 秒自动落盘）应满足：

| 指标 | 要求 |
|---|---|
| 状态为 IDLE 且「距目标 − 停止线 > 0」的编队 | **恒为 0**（这类行在剧本法下不可能存在） |
| 幕二结束时仍未到位的编队 | **0** |
| 连续 60s 战斗中编队渲染坐标抖动 | 0（位置是 t 的单值函数） |
| 同一场战斗重复观看 | 走位完全一致 |
| 8/9/10 逐像素 | 不变（改动全部在 `isBattleScene13()` 闸门内） |

任一项不达标 → **砍掉 13，退回 zoom 10**（成品，零成本），不再打补丁。
