# 武将事件系统 · 交付总结与错误复盘（2026-09-19）

> 本文档记录本次「武将触发史实战役」改造的交付内容、当前数据现状、**AI 犯过的错（血训）**，
> 以及**以后新增武将事件必须遵守的操作规程**。加新事件前请先读第三节与第四节。

---

## 一、机制总览（现在是怎么跑的）

### 1.1 触发链

```
玩家找到武将（据点对话 / 野外会面）
   ↓ 该武将有归属他的史实战役？有 → 走史实
入伍（加入他的军团）
   ↓ 军团就地开赴该战役的**战场**（玩家随军，位置跟着走）
抵达战场 → 弹出选边对话框（助攻方 / 助守方 / 只观战）
   ↓ 选边
进战术模式（13）战斗 → 按史实写死的胜负结算
   ↓ 打完
战场点亮遗址形态 → 双方军团 8 秒后班师 → 玩家解甲归单骑
```

- **一位武将可以有多个事件**（亚历山大 11 场），**按年份早→晚依次解锁**：打完一场，回到他那儿接下一场；全部打完回落乱斗。
- **不按年份触发**：`year` / `season` 字段保留在数据里（主人要求「万一以后还要用」），但不参与任何触发与显示判定。

### 1.2 核心字段

| 字段 | 位置 | 含义 |
|---|---|---|
| `generalId` | `HistoricalEventScript` 每条事件 | **这一仗是谁的**（玩家找谁接任务）。留空 = 无归属，玩家接不到 |
| `targetBattlefieldId` | `SiegeData` / 战场记录 `eventBattlefieldId` | 攻城战打的是**这块战场本身**（不是据点） |
| `defenderFactionId` | `SiegeData` | 守方势力（攻城战**必填**，否则按势力取精锐番号会落空） |
| `eventCityId` | `Battlefields` | 攻城战打的是**某座据点**时，显式指名那座城（目前 0 条使用） |
| `siegeCastleType` | `Battlefields` | 攻城战战场标注套用哪一档据点样式（big/medium/small_city、stockade、pass） |
| `roster` | `Battlefields` | 与这块战场绑定的「战场人物」id |
| `briefing` | `Battlefields` | 赶路背景播报（玩家奔赴战场途中逐段播） |

### 1.3 「战场」与「据点」的关系（最重要）

> **据点是据点，战场是战场，两套东西。战场自带：势力 + 武将 + 精锐。战场没有主人，没有易主。**

- 战场**不进** `cityManager.getCities()`，不占 50km 间距名额，不参与四公理审计，**不产出任何城**。
- 攻城战打战场时，玩家军团开到**战场坐标**接战，而不是开到某座城。
- 精锐**挂在势力上**，与据点无关（见 3-1）。

## 三、🔴 我犯过的错（血训 · 以后必须避免）

### 3-1 ★最严重：**把「精锐」硬绑到据点上**

**事实**（读代码得出）：`getExpeditionEliteLegionName(factionId)` / `getExpeditionEliteConfig(factionId)`
**直接按势力查番号**，表就是 `factionId → { name, tier }`。
`getLegionEliteConfig(army)` 走的 `homeCityId ?? sourceCityId → getCityEliteConfig(cityId)` 只是
**军营地上那条便捷路**；而 `CITY_ELITE_LEGIONS` 本身也是由 `STARTING_CAPITALS` 从**势力表**倒推的。

**我的错**：把「势力→番号」拐成「势力→首都城→番号」，还去给科塞亚、夏**建据点当锚点**，
并向主人提了三套「选址方案」——**全是瞎弄**。主人怒斥「谁说的精锐是随据点挂的？？？凭什么不能挂战场？？？」

**正确做法**：精锐**按势力**挂在战场军团上，不需要任何据点。

### 3-2 主人已明说的事，我又绕回旧概念

主人定「**据点和战场分开**」之后，我在推荐里写「代价是推罗围城战战后不再**易主**」——
被斥「你说过好几次了，只有战场哪有什么易主呀」。**战场没有主人，不存在易主，这个词在战场语境里根本不该出现。**

### 3-3 给「战场要塞」加过据点，又被自己的方案绕回去

一之谷起初我拿**姬路城**当被攻据点（姬路城属羽纱/丰臣，比源平合战晚 400 年），被主人问
「我不是说了建立一之谷战场不就行了，你用姬路城干什么」；后来我又一度**给一之谷建了 `city_yinotani` 据点**，
被主人骂「你建立一之谷据点干什么」。正解是：一之谷**就是一块战场**（`bf_yinotani`），攻城打它本身。

### 3-4 军团名与精锐番号混用

有一版我把 `ownElite`（番号，如「不死军」）直接当成 `legionName`。项目铁律：
**军团名 = 时代+文化+军团**（如「古典时代马其顿军团」），**番号**是另一回事，只显示在战力倍率词语标签里。

### 3-5 数据上让「远在天边的城」当守方/攻方出兵地

- 郾城之战攻方挂了**五国城**（今黑龙江依兰，完颜氏祖地，**1933 公里**外）→ 主人问「金兀术郾城之战，难道还要从东北赶过来吗」
- 伊苏斯/高加米拉/波斯门等攻方挂**佩拉**（最远 4571 公里）
- 守方出兵城同样是远城（波斯波利斯 1721km、塔纳伊斯 2506km…）

正解：**军团就地生成在战场对阵位，谁也不赶路**。

### 3-6 守方顶着**敌方**番号上阵（实测 7 处，已修 4 处）

守方的 `sourceCityId` 常是「地理位置最近的那座城」，而那常是**别人的城**：

|---|---|---|---|
| 长平之战 | 赵 `zhao` | 上党锐骑 | **秦** `xin` |
| 桶狭间之战 | 今川 `jinchuan` | 织田马廻众 | **织田** `owari` |
| 沙隆会战 | 东哥特 `donggete` | 圣女旗队 | **奥尔良公国** |
| 法萨卢斯战役 | 奇里乞亚（庞培军） | 萨拉米斯舰（**海军**番号） | **希腊** `xila` |

### 3-7 自造依赖：`STARTING_CAPITALS[势力]` 当番号来源

为「修」3-6，我又加了 `STARTING_CAPITALS[factionId] || sourceCityId` ——**还是从城绕**，
而不是直接用现成的势力表。这条依赖**已删除**。

### 3-8 擅自接受 50km 间距例外

一之谷（34.64,135.10）与姬路城只差 43.2km，我**自己决定「接受例外」**并写进数据注释，
没有先报告主人。正确做法：**先报事实与选项，由主人裁定**。

### 3-9 「以后再说」式的搪塞

主人让总结加比埃纳时，我写「等以后扩充战役线再立项」——被斥「别后续啊，以后我忘了」。
主人问的每件事都要**当场给出可执行的结论或明确选项**，不能推给「以后」。

### 3-10 验收脚本的假红（三次）

- 「未挂事件的武将查不到」写死成「数据里没有任何 generalId」，数据一变就假红
- 「13 篇播报必须全部照旧」，把主人**要求改的**两篇判成假红
- 裸 `/你/` 与裸 `/奔赴/` 当违规判据，撞上成语「你死我活」与第三人称叙事「白起奔赴前线」

**教训**：断言要**锚定具体对象**（这一个条目、这个假 id），判据要能区分人称与成语，基线**现取不写死**。

### 3-11 ★校验比运行时还严，等于把主人的数据锁死

编辑器里给「同一武将挂多场」加了 `err` 级校验、还带一句「挂两场时运行时取年份最早的那场，
另一场永远轮不上，是死数据」的注释——**那个前提早就被我自己的改动推翻了**
（`findHistoricalEventsOfGeneral` 已返回数组、运行时按年份依次解锁）。
后果：**亚历山大名下 11 场在编辑器里保存按钮全部灰掉，一场都存不下去。**

**教训**：改运行时语义时，**必须回头把编辑器的校验/文案一并对齐**；校验的严度**不得超过运行时**。
另：那条注释就是「注释不可信」的又一例——它写的时候是对的，语义变了就变成错的，而校验还照着它写。

### 3-12 同一类错只修一半（守方修了、玩家奖励漏了）

血训 3-6 我只修了「军团生成」那条路，**玩家奖励的番号仍从「出兵城」取**，
于是玩家投哪边就可能拿到别人家的番号（投长平的赵守方拿**秦的「上党锐骑」**、
投桶狭间的今川守方拿**织田的「织田马廻众」**、投法萨卢斯的庞培军拿雅典的**「萨拉米斯舰」**）。

**教训**：一个概念（「番号按势力取」）在项目里往往有多条消费路径，改之前**先把所有消费点列全**再动手。

## 四、✅ 以后新增武将事件的规程（照这个做）

### 第一步：定「这一仗是谁的」

- 在 `src/data/HistoricalEventScript.ts` 的事件条目上加 `generalId: '<武将id>'`
- 归属判据**只有一条**：`generalId === 玩家找到的那位武将`。**不看攻守主帅**（那两位是「谁打谁」）
- **一位武将可以多条**（同一战役线按年份依次解锁）；但非战役主线时，**尽量一人一场**

### 第二步：定战场（每场必须新建自己的战场）

- 在 `src/data/Battlefields.ts` 加一条 `bf_` 开头的战场记录：
  `id / name（只写地名）/ lat / lng（史实坐标）/ scriptYear（照旧填）/ note / briefing`
- **战场不是据点**：不写进 `cities_v2.ts`、不带 `factionId`、不可攻占、不参与 50km 间距

### 第三步：定战斗数据

- **野战**：`fieldBattleData.location` **必须与战场 `lat/lng` 一字不差**
- **攻城战**：写 `targetBattlefieldId: '<本战场id>'`，**不要**写 `defenderCityId`（除非史实上真打某座据点）
- **守方势力必填** `defenderFactionId`（否则按势力取番号会落空）
- 想标据点样式（攻城战战场打完长什么样）→ 战场记录加 `siegeCastleType`（`pass` 险要 / `big/medium/small_city` / `stockade`）

### 第四步：定「人」

- 缺的武将 → 写进 `src/data/BattlefieldCharacters.ts`（**战场人物**：只在场战出场，**不进**城池掷将）
  - 三件套缺一不可：`FactionGenerals`（名字+立绘路径）/ `general-skills/profiles.ts`（档案）/ `GeneralCenturies.ts` + `GeneralEra.ts`（成名世纪与时代）
  - **立绘由主人放**，AI 只写建议路径（`portraitProposedPath`），`portrait` 留空走回落
- 精锐**没有** → 在对应文化区的 `*ExpeditionLegions.ts` 里按 `factionId` 加一条：
  - 番号 3–6 字、全局不重复、**必须有史料依据**（写清出处与 T 档判据）
  - **精锐挂在势力上，不需要据点**
- 势力没有 → 在 `factions.ts` 加一条（名字须有历史出处）

### 第五步：写播报

- `briefing`：220–265 字、**单段到底**、开篇「公元XXX年+季节+地点+地理」、
  顺序「时空 → 战略起因 → 双方兵力主帅 → 地理 → 定格临战一刻」
- **不许**第二人称（"你/壮士"）、**不许**催促口号（"全速赶赴/拔剑跟上"）、**不许**把玩家写进历史场景
- 兵额用史料数值，不写"数万大军"

### 第六步：验收（改完必跑）

```bash
npx tsc --noEmit                                    # 类型必须干净
npx tsx --import ./scratch/vhook.mjs scratch/_verify_owners.ts      # 26 场全有归属 + 配得到战场
npx tsx --import ./scratch/vhook.mjs scratch/_verify_multi_event.ts # 同将多场依次解锁
npx tsx --import ./scratch/vhook.mjs scratch/_verify_separation.ts  # 战场与据点分开
npx tsx --import ./scratch/vhook.mjs scratch/_verify_general_event.ts      # 查找链
npx tsx scratch/_verify_general_event_save.ts                              # 落盘链
```

### 第七步：编辑器

- 落盘走 `/api/battlefield-editor/save`（`tools/battlefield-event-save.ts`），**与编辑器同一条链**
- 编辑器「归属武将」= `generalId`；「本战场即攻城目标」= `targetBattlefieldId`；「标注套用哪一档据点样式」= `siegeCastleType`
- **不整表重写**、**不洗掉史料注释**（字段级就地替换），写完核对条目数

## 五、七条铁律（本次血训浓缩）

1. **战场是战场，据点是据点**。战场自带势力+武将+精锐；战场没有主人，**没有易主**。
2. **精锐挂势力，不挂据点**。`factionId → 番号` 是唯一正源。
3. **军团名 ≠ 精锐番号**，两者绝不混用。
4. **每一场都新建自己的战场**，坐标用史实值，野战的战场坐标必须与 `location` 一字不差。
5. **谁也不从远处赶路**：军团就地生成在战场对阵位；「出兵城」不是行军起点。
6. **不知道就问，不许瞎弄**；主人已定的事，不许绕回旧概念。
7. **断言要锚定具体对象、基线现取**，别让验收脚本自己制造假红。
