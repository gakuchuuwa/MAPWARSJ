> # 🔴 铁律 · 兵种归属只看「子分类 + 文化区挨不挨着」
>
> 判断一个兵种能不能进某支军团，**只看两条**：
>
> 1. **兵种子分类对不对** —— 近战骑兵 / 弓骑兵 / 枪骑兵 / 步弓手 / 重步兵 / 攻城器…
>    要补的是哪一类，就从那一类里挑。
> 2. **文化区在地理上挨着** —— 这个兵的本源文化区，和要用它的文化区，别隔太远。挨着就行，不必同族。
>
> 兵种 id 里的民族词（女真 / 波兰 / 越南 / 图皮 / 库曼…）、中文兵名、`age` 时代标签，**都不是判据**。
> 那是《帝国时代 2 DE》的出处标签，不是本作里这个兵属于谁。
>
> **正例**：铁浮屠是**近战骑兵**、本源**东北** → 朝鲜、北方、草原、契丹、女真、西夏、蒙古**都能用**。
> 　　　　西辽挨着蒙古、离女真远 → 西辽 4 档用**怯薛军**比铁浮屠更合适。
> **反例**：图皮黑木弓箭手（南美）给阿伊努（北海道）—— 子分类虽同是步弓，但隔着太平洋，**太远，不行**。
>
> **禁止**：只因为兵名里带别族的民族词，就说「跨国乱炖 / 不符合历史」。这条已被主人当场抓过三次：
> - 「契丹军团用女真铁浮屠 = 乱炖」→ **错**，同是东北近战骑兵，文化区挨着。
> - 「库曼钦察弓骑不该给东北民族」→ **错**。
> - 「捷克军团 4 档是波兰奥布奇战锤兵 = 乱炖」→ **错**，波兰捷克接壤。
>

> 只有改动前就是红的（格位不符阵型 / 兵种不存在 / 象攻城违规 / 战力离群）才准动，其余一律先问。

# 历史进程模式与前334年亚历山大脚本框架

> 本文是以后实现历史进程的唯一入口。当前只完成设计与仓库现状核对，**尚未实现启动选择、剧本导演器或亚历山大实体**。文中的接口名和字段名均为提案，不得当成已存在代码汇报。

## 一、主人已经定下的需求

1. 游戏启动前先选择模式：**历史大乱斗** / **历史进程**。
2. 选“历史大乱斗”后，现有世界、首发、AI、随机名将跟拍全部保持不变。
3. 选“历史进程”后，游戏从公元前334年开始。
4. 第一位历史主角是**亚历山大大帝**；历史进程启动后，镜头固定跟随他的军团。
5. 历史进程的镜头目标由剧本指定，不再使用乱斗模式的随机自动跟随。
6. 以后可以按年代更换主角，但只能由历史脚本明确切换，不能随机换人。
7. 历史进程第一版关闭独白：无旁白、无角色对白、无字幕说明、无叙事卡、无新增剧情语音。

## 二、模式边界

| 项目 | 历史大乱斗 | 历史进程 |
|---|---|---|
| 世界数据 | 继续读取现有全时代数据 | 读取剧本白名单和剧本覆盖层 |
| 首发军团 | 现有63文化区首发逻辑 | 只生成本章剧本登记的军团 |
| 初始跟拍 | 现有“名将优先、同档随机” | 强制解析本章 `protagonistRoleId` |
| 主角阵亡 | 现有延迟后自动换军团 | 不得随机换人；按剧本的失败/续章规则处理 |
| 军团目标 | 现有 AI 自由选择 | 主角走史实节点；非主角按本章规则活动 |
| 科技年份 | 乱斗现状不变 | 按历史年份门控 |
| 跨时代据点/人物 | 全部可同时出现 | 未在剧本白名单中的实体不出场 |
| ZOOM 8/9/10 | 保持现状 | 保持现状；历史模式只改变跟拍目标来源 |

### 2.1 绝对隔离

- 历史进程不能直接改写 `cities_v2.ts`、`FactionGenerals.ts`、`FactionCompositions.ts` 中的大乱斗实体来“凑”剧本。
- 同一历史人物、据点在两种模式下需要不同状态时，走**剧本覆盖层**，不覆盖乱斗原数据。
- 模式分流应发生在启动编排层，不为了历史进程修改 ZOOM 8/9/10 的渲染、缩放或战斗规则。
- 历史进程中的每一个真正据点仍须满配：一个真实势力、一个武将、一个精锐；不得出现 `panjun`。

### 2.2 据点、地点、战场必须分开

史料里出现一个地名，不等于要新建一个据点。

| 类型 | 用途 | 是否受“一据点一整套”约束 | 前334年例子 |
|---|---|---|---|
| `stronghold` | 可驻军、可攻占的城/要塞 | 是 | 萨迪斯、米利都、哈利卡纳苏斯 |
| `routeNode` | 行军转折、渡海落点 | 否，不进入城池表 | 塞斯托斯、赫勒斯滂渡口 |
| `battlefield` | 野战触发坐标 | 否，不作为城 | 格拉尼库斯河战场 |
| `landmark` | 只记录人物实际到访，不弹独白或字幕 | 否，不参与攻占 | 特洛伊、阿喀琉斯墓 |

这样可以避免为每个史料地名硬造势力、武将和精锐，也避免用“战场”冒充城池。

## 三、建议的启动流程

```text
网页加载
  ↓
显示模式选择（此时尚未 new GameApp）
  ├─ 历史大乱斗
  │    ↓
  │  以 mode=brawl 创建游戏 → 完整走现有启动链
  │
  └─ 历史进程
       ↓
     选择/默认剧本 alexander-334
       ↓
     以 mode=historical + scenarioId 创建游戏
       ↓
     基础地图与公共系统初始化
       ↓
     历史导演器校验剧本 → 应用世界白名单/覆盖层 → 生成角色与军团
       ↓
     解析主角军团成功 → 镜头锁定 → 等待玩家点“播放”
```

### 3.1 启动失败原则

历史模式若找不到亚历山大或他的军团，应明确报出“剧本主角未生成”，并保持暂停。**绝不能退回随机名将跟拍**，否则错误会被掩盖成另一场乱斗。

### 3.2 模式记忆

- 本轮选择只属于本次新游戏/存档。
- 存档必须记录 `mode` 与 `scenarioId`，避免历史存档被按乱斗规则载入。
- 不建议把上次模式静默设为永久默认；重新开新游戏时应再次展示选择。

## 五、建议的数据骨架（提案，不是现有字段）

```ts
type GameMode = 'brawl' | 'historical';

interface HistoricalScenarioDefinition {
  id: string;                       // alexander-334
  title: string;                    // 亚历山大东征·渡海入亚
  startYear: -334;
  protagonistRoleId: string;        // role_alexander
  cameraPolicy: 'scripted-locked';
  world: HistoricalWorldManifest;
  actors: HistoricalActor[];
  legions: HistoricalLegion[];
  chapters: HistoricalChapter[];
}

interface HistoricalWorldManifest {
  strongholdRefs: string[];
  routeNodes: HistoricalLocation[];
  battlefields: HistoricalLocation[];
  landmarks: HistoricalLocation[];
  aliases?: Record<string, string>; // 仅本剧本显示，不改乱斗真名
}

interface HistoricalActor {
  roleId: string;                   // 剧本稳定角色键
  generalId?: string;               // 有战斗实体时才需要
  displayName: string;
  campId: 'macedonian' | 'achaemenid' | 'local';
  entityKind: 'general' | 'ruler' | 'adviser' | 'governor' | 'narrative';
}

interface HistoricalLegion {
  roleId: string;                   // role_alexander_legion
  legionName: string;               // 必须以“军团”结尾
  commanderRoleId: string;
  factionRef: string;
  eliteName: string;                // 精锐番号不带“军团”
  sourceStrongholdRef: string;
  compositionRef: string;
}

interface HistoricalChapter {
  id: string;
  dateLabel: string;                // 只写史料能支持的精度
  trigger: HistoricalTrigger;
  actions: HistoricalAction[];
  nextChapterId?: string;
}
```

### 5.1 为什么人物要有 `roleId`

镜头不应记某次生成出来的临时 `army.id`。剧本始终跟随“亚历山大这个角色”，导演器再把角色解析为他当前的军团。这样换场、过海重建实体、读档后，镜头仍能回到同一主角。

### 5.2 为什么要有阵营 `campId`

前334年的安纳托利亚不是一张“波斯帝国只有一城”的地图。萨迪斯、以弗所、米利都、卡里亚都有各自的地方行政和人物，但总体处于阿契美尼德体系或倒向马其顿。建议用“本地势力一城”保持项目公理，再用 `campId` 表示它当前属于马其顿阵营、阿契美尼德阵营或地方中立。阵营不是第二个势力，也不另挂旗号。

## 六、镜头规则

### 6.1 前334年第一章

- `protagonistRoleId = role_alexander`
- `cameraPolicy = scripted-locked`
- 游戏开始并完成军团生成后，立即调用现有跟拍接口锁定亚历山大军团。
- 历史模式不调用现有 `pickBestAutoFollowLegion()`。
- 历史模式中取消跟随、阵亡换人、无目标五秒自动跟随，都不能把镜头交给随机军团。
- 亚历山大离开一个实体并在下一章生成新实体时，由角色键重新绑定。
- 只有章节动作 `setProtagonist` / `setCameraRole` 可以更换历史主角。

### 6.2 主角失败

第一版框架预留两种规则，但实施前只能选定一种，禁止两套同时暗中生效：

1. **史实锁定**：关键战役保证史实胜负，适合“历史进程”放映。
2. **失败停章**：战斗仍由引擎结算；若亚历山大阵亡，则暂停并提示重试本章。

无论选哪种，都不能在失败后随机跟随另一名将。

- 戈尔迪乌姆更适合作为前333年章节开端/衔接点，本章只预留，不抢进前334年已确定节点。
- 格拉尼库斯是河战场，不建成城；拉德岛是舰队锚地，不建成城。

### 写死胜负（现成能力，已接上）

`MultiLegionFieldBattle` 读 `data.result`，源码原话「事件链预设战果：该侧按 result 锁定胜负」，
`attackerShouldSurvive = data.result === 'attacker_win'`。脚本 `result: 'attacker_win'` → **马其顿必胜**。

### ⚠️ 本轮踩到的坑：`defenderGeneralId` 是**死字段**

`FieldBattleData.attackerGeneralId / defenderGeneralId` 在 `MultiLegionFieldBattle` 全文中**零引用**（实测 grep）；
它创建军团时主将取自 `HISTORICAL_LEGIONS`（按**军团名**索引的旧事件表）。
照那条路走，**阿尔西提斯不会出现在战场上**，而 13 战术模式准入要求「双方都有将 + 都有精锐」——
**这场仗连 13 都进不去**。

**对策**：剧本侧预先 `ensureDefenderLegion()` 建出守方（挂将 / 兵力 / 出发城达斯基利翁），
野战处理器按名找到现成军团会**复用**（`setTroops(25000)` 写死兵力、保留主将），并从达斯基利翁行军到战场。

### 据点易主（已实现）

走 `CityManager.updateCity(cityId, { factionId })` —— 全项目唯一正规易主接口，
会一并处理旗号刷新（`applyFactionChangeVisual`）、`fallenAtYear`、将/精名额重置与占城播报回调。
**不自己写 `city.factionId = ...`**（那样旗号与领土色块不会更新）。

### 停募兵 = 玩家面板开关（2026-09-11 **改定**，本节为最终口径）

## 15.9.2 剧本军团豁免行军减兵（2026-09-11 主人定）

> **主人原话**：「**剧本军团没有 15 秒兵力消耗。该修复的修复。**」

### 病根（实测，非推测）

`GameConfig.MARCH_ATTRITION`（`src/config/GameConfig.ts`）：

| 常量 | 值 | 含义 |
|---|---|---|
| `FREE_SUPPLY_SEC` | **15** | 出门带一季粮（1 季 = 15 游戏秒） |
| `ATTRITION_CHUNK_SEC` | **15** | **每 15 秒整跳扣一次** |
| `ATTRITION_CHUNK_RATE` | 0.15 | 首跳扣 15%，连续跳 30%、45%……递增 |
| `EXEMPT_CAMPAIGN_LEGIONS` | **false** | **2026-07-27 主人改**：远征军也吃行军减兵（注释原文「含岳飞脚本军」） |

剧本军团挂着 `expeditionTargetCityId`（= 远征军），而那条豁免已关 → **它正吃着这套减兵**。
后果是实的：跑过 15 秒免费期后每 15 秒掉 15%/30%/45%……，
剧本写死的 **35000 兵会在抵达战场前被啃光，甚至归零触发「战败销毁」→ 剧本整条断掉**。

### 修法

旗标 **`Army.scriptMarchNoEngage` 更名为 `Army.scriptMarchExempt`**（原名叫 `NoEngage` 却说不管减兵，名不副实，
本项目的铁律最恨这种假名字）。现管**四处豁免**：

| # | 落点 | 行为 |
|---|---|---|
| ① | `LegionFieldBattle.tryEngageFieldBattle` | 野战：本方不主动开战，**且对方也不能把它拖进战斗**（两边都判） |
| ② | `LegionManager.findHostileCityNear` | 敌城 ZOC 返回 null，不被"先处理该城"钉在城下 |
| ③ | `LegionManager.triggerSiege` | 攻城总咽喉返回 `'skipped'`，覆盖全部攻城路径 |
| ④ | **`MarchAttritionSystem.tickMarchAttrition`** | **不扣兵**（本次新增） |

**另修一处不彻底**：`LegionManager.tickMarchAttritionPipeline` 的 ① 计时也在跑
——豁免期间照记「断粮时长」，一旦解除豁免就会立刻吃到超高跳数。
现已改为 **豁免期间连表也停**（`!army.scriptMarchExempt`）。

**与远征豁免是两回事，勿合并**：`EXEMPT_CAMPAIGN_LEGIONS`（现 false）管的是全体远征军；
本旗标只管**剧本军团**，由剧本在派兵时点亮（`dispatchAttackerToBattlefield`）、
抵达战场开打时解除（`launchScriptBattle`）。

> ⚠️ **[2026-09-11 更正]** 上面最后半句「抵达战场开打时解除」**已作废** —— 解除时机见 §15.9.3，
> 现为「**只在剧本自己决定时解除，永不因"要去开打"提前解除**」。

## 15.9.3 剧本军「擅自攻打羊河」的两处根因（2026-09-11 主人报障）

> **主人截图**：战场面板显示「**羊河 攻防战**」，剧本军正在攻打羊河这座敌城。
> **主人原话**：「剧本军团擅自攻击洋河，你的脚本是怎么写的，**按行军路线抵达交战地点，其他不许发生战斗**。」

### 根因一：AI 自己写的漏洞 —— 豁免解除得太早（已修）

`launchScriptBattle` 原先在**还没确认野战打得起来之前**就执行 `army.scriptMarchExempt = false`。
一旦野战因故没打成，剧本军立刻变成【挂着远征目标 = **羊河这座敌城**、却已经没有豁免】的普通军团
→ 行为树按「攻占该城」办 → **当场攻打羊河**。

**修法**：豁免**只在剧本自己决定时解除，永不因"要去开打"而提前解除**。
守方建不出来就直接 `return`（不解除豁免、不开战、下一帧重试），军团顶多原地待命。

### 根因二：引擎既有的静默卡死 —— 无路可达战场时野战永远开不了（已修）

`MultiLegionFieldBattle.moveArmiesToBattleParallel`，原先：

```ts
} else {
    console.warn(`[MultiLegion] Army ${army.name} 无道路可达战场，停止行军`);
    army.setSpeedMultiplier(1.0);
    // ← onEachArrived() 永不调用！
}
```

`onEachArrived` 不调 → `arrivedCount` 永远到不了 `totalArmies` → `startRegionalBattle` 永不触发
→ **整场野战无声卡死、永远打不起来**。

剧本军正好踩中：野战场坐标 `(40.23, 27.24)` **在路网外约 10 km**（最近据点格拉尼库斯距它 10.9 km），
`roadRegistry.findPathOnRoad` 给不出路径。**这条卡死正是"擅长攻打羊河"的上游** ——
野战打不起来 + 豁免已被解除 → 军团回落常规 AI → 就近攻打羊河。

**修法**：与同函数内那条「极短距离即时抵达」（`directDist < 0.02`）同口径 ——
**无路可走即当场视为抵达**：贴得上路网就贴（`findNearestRoadPoint` < 2 km），
贴不上就直接落到**战场精确坐标**（剧本写死的交战地点）。绝不再静默停摆。

### 附带更正：回调签名

`FieldBattleManager.handleFieldBattleEvent(data, onBattleComplete?: () => void)` —— **回调无参**。
`(winnerFaction, winningArmies)` 是**内层** `handleMultiLegionBattle` 的回调签名，两者别混
（AI 本次就写错成 `(winner) => …`，被 `tsc` 当场抓到）。
成败不靠回调判断：**双方军团在派兵前已备齐**（守方建不出来就不打），
故处理器那条「缺少参战军团」错误路径不会再走到。

## 15.9.4 敌军改为「抵达目的地后，野战场就地刷兵」（2026-09-11 主人定）

**转头去攻打别的据点**。等于我在世界里放了一支不受控的敌军。

**它随即被野战处理器接管**：`collectArmies` 会 `stopMovement()`；
且因它**就在战场原地**，`moveArmiesToBattleParallel` 直接走

## 15.9.5 本阶段「不交战」：走完路线就停（2026-09-11 主人定）

> **主人原话（选择后）**：「**不交战**」——本阶段**完全不触发战斗**。
> （后补一句修正：「**我的意思是剧本军团抵达目的地后不交战**」——即军团要**走到终点**，到了才停，不是停在羊河。）

`HistoricalEventManager.SCRIPT_BATTLE_ENABLED = false`（开关，不是删除）：

- **false（当前）**：剧本军沿 佩拉 → 安菲波利斯 → 羊河 走完据点航点后，
  **解除远征锁、由剧本导演直接驱车赶到终点（野战场坐标 `(40.23, 27.24)`）**，抵达即停驻待命；

- **true（下一阶段）**：抵达终点后 → 野战场就地刷敌军 → 野战 → 写死胜负 → 据点易主。
  那套逻辑已在 `launchScriptBattle` / `ensureDefenderLegion` / `applyScriptCityUpdates` 备好，翻开关即恢复。

> 注：终点在路网外约 10 km，最后一段走 `roadRegistry.findPathOnRoad`；无路则就近贴路，
> 贴不上（<50 km 无路点）就**直接落位到终点精确坐标**——引擎的路网行军到不了没有路的地方。

## 15.9.6 玩家任务条显示真实历史目标（2026-09-11 主人定 **A 方案**）

> **主人原话**：「**A。真是历史剧本，还用问吗**」

### 病根

玩家任务条原先把剧本军显示成「**随亚历山大攻【安菲波利斯】**」。原因是**字段语义撞车**：
`PlayerQuestSystem` 取任务目标就一行 ——

```ts
const targetId = army.expeditionTargetCityId ?? army.siegeTargetCityId ?? army.getTargetCity()?.id ?? null;
```

剧本拿 `expeditionTargetCityId` 当**行军航点**（安菲波利斯是第一个航点），

**顺带一个坑**：不能简单把航点不再设成 `expeditionTargetCityId` ——
`joinMarchingArmy` 里「军团没有目标城 → 一句『所部暂无战事』把玩家挡在门外」，
**正是这个"假目标"让玩家能入伍**。

| 落点 | 改动 |
|---|---|
| `HistoricalEventManager.getScriptObjective(armyId)` | **新增**：只对**剧本主角军团**返回 `{ label, done }`；`label` 由「距终点最近的据点」取名 → 「进军格拉尼库斯」；`done` = 已抵达终点 |
| `PlayerQuest.scriptObjective?` | **新增字段**：有此字段即剧本任务 |
| `PlayerQuestSystem.joinMarchingArmy` | 剧本军**不再要求有目标城**（否则玩家入不了伍）；写入 `scriptObjective` |
| `PlayerQuestSystem.onMeetArmy` | 剧本军的会面对白改说真历史目标 |
| `PlayerQuestSystem.tick` | 剧本任务的**完成判定 = 剧本进度**（`done`），不是"某城归我方" |
| `PlayerQuestSystem.finishQuest` | 措辞改「…达成 / 中断」，不再是「攻克/出征失败」 |
| `PlayerHUD` | 任务条 → `随${generalName}${label}` ＝「**随亚历山大进军格拉尼库斯**」 |

`GameApp` 注入 `getScriptObjective: (armyId) => historicalEventManager.getScriptObjective(armyId)`。

## 15.9.8 战场（**独立地名，不是据点**）的形态与摆位（2026-09-12 主人定）

> **主人原话（按时间顺序，后者覆盖前者）**：

> ④ 「**战场没有主人，易什么主？**删除之前的错误逻辑」
> ⑤ 🔴 **最终定案**：「**要不然把战场独立出来，不做为据点，就叫战场。一个地名而已。类似奇观，万一缺少武将了，可以安置一个武将，但是不能出征，纯属剧情需要。**」

### 一、战场的硬口径（2026-09-12 主人逐条定死，**已全部落地**）

> 🔴 **本节曾被 AI 写错过两次**，别再错第三次：
> ① 原写「性质 = 有势力 / 武将 / 精锐，与普通据点同构」——AI 自己推的，被主人否掉（「**战场不用**」）；
> ② 又写成「**不挂**武将、不挂精锐」的一刀切禁令——也不是原话，被更正为「按需」；
> ③ 最终**整个架构推翻重来**：战场不再是据点。下表为**现行正确口径**，权威文本另见 `AGENTS.md` §2.1.3。

| 项 | 定案 | 依据 |
|---|---|---|
| **性质** | 🔴 **独立地名** = `src/data/Battlefields.ts` 的 `bf_*` + `src/map/BattlefieldLayer.ts` 独立图层（**类似奇观** `MonumentLayer`）。**不是 `city_*`、不进 `cities_v2`、不进 `cityManager.getCities()`** | 主人：「**把战场独立出来，不做为据点，就叫战场。一个地名而已。类似奇观**」 |
| **为什么要独立** | 混在据点里时它带着一个照抄守方的 `factionId` → 全项目 **30+ 处 `getCities()` 消费者**都看得见它，只能到处打补丁（`GameAppCityLoader` / `TerritorySystem` / `RecruitmentSystem` / 3 个审计脚本），还得把 `City.troops` 改成可选 + 6 处 `?? 0`。独立后**整类补丁消失** | 实测：独立后据点 1088 → **1086** 座，`tsc` 只需还原类型 |
| **没有势力、没有兵力** | 战场表里**根本没有** `factionId` / `troops` / `type` 字段 | 主人：「战场没有主人」+「**不是0，是没有兵力**」 |
| **不能攻占、不能易主** | 不在 `getCities()` → AI 目标池 / 攻城 / 占城流程**天然碰不到它**；`cityUpdates` **只写真城** | 主人：「**战场没有主人，易什么主？**」 |

## 16.5 铁律（由上述教训提炼，后续 AI 必守）

1. **剧本写死的数（兵力/武将/地点/结果）一律照做**，引擎默认值只在剧本没写时兜底。
2. **剧本军的一切"主动行为"必须关闭**（交战 / 攻城 / 自行寻目标 / 减兵），由剧本导演独占其去向。
3. **豁免（`scriptMarchExempt`）只在剧本明确决定时解除**，绝不因"要去开打"提前解除。
4. **刷出来的东西必须上豁免**——不许在世界里留下任何不受控的 AI 军团。
5. **改字段前先查该字段在引擎里的既有语义**（`expeditionTargetCityId` 就是活教材）。
6. **UI 表现要自己去看 / 主动去问**，别等主人截图才发现语义撞车。
7. **AI 看不到浏览器时，必须写离线核对脚本**把同一套布局数学复现一遍再出图自检；
   **别凭"应该能看到了"就交付**（§16.3 第 23 条）。
8. **东西要摆在主人指定的那一页**：据点 → 第一页「据点形态评估」，建筑素材 → 「建筑鉴赏」（§15.9.8）。
9. **getter 读状态前先确认状态已赋值**：`firstWaypointId` 应在 `scriptBattleData` 赋值后读，或直接读入参 `fb`——别经过依赖旧状态/尚未赋值的 getter（§16.2 第 29 条）。
10. **战术技能全部随机、无专属**：任何武将都不许「定专属战术技 / 起典故契合的四字专属技」（AGENTS.md 铁律一）。
11. **兵力/坐标/称谓/T级凡史料有数的，一律按史料取值**，规则里写了就别问（AGENTS.md 决策总纲 2026-09-12）。
12. **四模式必分清再动手**：战略=大地图层（行军/攻城/军团尸体 `CORPSE_DISPLAY_MS`），战术=13层战斗（尸体烙图+残局 `FOLLOW_SWITCH_DELAY_MS`）；剧本=历史事件驱动（`isScriptArmy`，武将无战略技/不扣兵），乱斗=沙盒自主攻伐（名将战略技仅跟拍）。改码前先判是哪个。
13. **立绘与线路（行军路线/道路）由主人亲自处理**，AI 禁止设定/新增/改动；行军路标不许乱加据点，用附近已有据点连接。
14. **剧本模式下乱斗的自主攻伐与募兵一律停**（分模式）：`ENABLE_HISTORICAL_EVENTS` 为真时，`aiController` / `recruitmentSystem` 不跑，其他势力「老老实实等着」。
15. **剧本写死胜负的战斗，13 演出判负不得覆盖写死结果**：`getScriptedWinner()` 优先于演出判负，否则主角被销毁、下一场衔接断（§16.2 第 33 条）。
16. **判断「移动成功」要看「军团真的动起来了吗」（`!isIdle()`），不是看函数返回值**：`moveLegionToCity` 会把「已触发攻城（被 `scriptMarchExempt` 豁免 skipped）」也当成功返回 true，剧本军停在紧挨敌城的野战场上永远不动（§16.2 第 34 条）。
17. **剧本刷兵点要对齐野战处理器的对阵位（`BATTLE_OFFSET`），不要刷在 `location` 正中**：处理器开战会把两军分别拽到 `lng∓0.14°` 对阵位，守军刷在正中一开战就被拽（路网里会真走起来「转圈」）；刷在守方对阵位（`loc.lng + BATTLE_OFFSET`）距离 0 → 即时抵达一步不挪。偏移量从 `MultiLegionFieldBattle` 导出复用，不另写常量（§16.2 第 35 条）。

# 十七、剧本模式 vs 乱斗模式设计（2026-09-12 主人定「你去设计剧本模式吧」）

> 主人原话（逐句）：「我像把游戏分两种模式，一个是剧本模式，一个是乱斗模式……你现在把这两个都给我搞混了。」「1，开局UI二选一，2，怎么省市怎么来，肯定不能攻伐。」

## 17.1 四种模式（两个维度，勿混）

| | **战略**（大地图层 zoom≤10） | **战术**（13层 zoom13） |
|---|---|---|
| **剧本模式** | 剧本军团按事件行军/战斗（`isScriptArmy`） | 剧本野战进 13 层（写死胜负） |
| **乱斗模式** | 乱斗军团自主攻伐/募兵 | 乱斗战斗进 13 层 |

- **战略 / 战术** = 战斗**层级**：战略是大地图（行军/攻城/选目标/军团尸体 `CORPSE_DISPLAY_MS`）；战术是 13 层微观战斗（尸体烙图 `DEATH_ANIM` + 残局 `FOLLOW_SWITCH_DELAY_MS`）。
- **剧本 / 乱斗** = 游戏**模式**：剧本是历史事件驱动；乱斗是沙盒自主攻伐。

## 17.2 顶层开关与开局二选一

- 顶层 `GAME_MODE ∈ { 'script', 'brawl' }`，开局 UI 二选一。
- 剧本：`ENABLE_HISTORICAL_EVENTS = true`、`SANDBOX_MODE = false`。
- 乱斗：`ENABLE_HISTORICAL_EVENTS = false`、`SANDBOX_MODE = true`。

## 17.3 剧本模式规则（完整清单）

1. **历史事件驱动**：`HistoricalEventManager` 按事件（-334 → -333 → …）驱动，战斗结束立即衔接下一事件。
2. **其他势力冻结**：`aiController` / `recruitmentSystem` 停（不攻伐、不募兵），老老实实等着。
3. **战场打完才显示形态**：`bf_*` 战场平时**只有地名**，该场战斗结束（打完了才叫战场）才显示**战场形态**。
4. **剧本军团身份**：`isScriptArmy`（无战略技、不扣 15 秒减兵）+ `scriptMarchExempt`（不自主寻敌/攻城/交战）。
5. **兵力按史料重置**：每场按 `fieldBattleData.attackerTroops/defenderTroops` 开战，不继承上战损。
6. **写死胜负**：`presetResult`（剧本写死，不走引擎推演）。
7. **战后真城易主**：`cityUpdates` 让**真城**易主；🔴 **战场永不写 `cityUpdates`**（战场没有主人，且它已不是据点）。战场放 `SCEN_STATUE_ALEXANDER` 雕像。

## 17.4 乱斗模式规则（完整清单）

1. **沙盒自主攻伐**：`aiController`（行为树选目标/追击/攻城）+ `recruitmentSystem`（募兵）全套跑。
2. **名将战略技仅跟拍军团生效**（`generalHasStrategicEffect`）。
3. 募兵选将、选目标、回援/收复、军团自主行为全套跑。

## 17.5 战场显示时机（主人 2026-09-12 定死，同日追加细化；后经「战场独立化」换载体，**规矩不变**）

> 主人原话③（同日追加）：「**战场没有势力不用插旗**」「**战场据点兵力不是0，是没有兵力**，战场又不驻军。」

> 万一缺少武将了，可以安置一个武将，但是不能出征，纯属剧情需要。**」
