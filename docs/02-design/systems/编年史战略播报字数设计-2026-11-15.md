# 编年史战略播报字数与合并规范（2026-11-15）

> **核心口径**：
> 1. **两段结构**：编年史每场事件统一收口为 **「战略播报（战略地图移动期念）＋ 战术播报（战术场景 `Scene13` 内念）」** 两段。
> 2. **战术播报不动**：固定 **`89–144` 字**，原样保留，不改动。
> 3. **连接＋战略合并为单一「战略播报」**（字数按移动时间、不封顶，见第三节 2026-11-16 新规则）：取消独立的「衔接播报」，将 **「承接上一场事件的时间/格局过渡」与「本场战役的纪年、双方与战略背景」融合成同一种战略播报**，字数严格按每场在战略地图上的实际移动时间定制，彻底消除「军团已到城下还要罚站干听半分钟」的问题。

## 一、问题诊断与语音/字幕硬指标

### 1.1 现行「干听罚站」根因
- **现行字数**：主线 1,022 场原先每场挂「衔接播报（89–144 字）＋ 战略播报（89–144 字）」，两段合计 **178–288 字（场均 238.8 字）**。
- **语音语速**：`SpeechAnnouncer.announceBriefing`（`rate = 0.92`，含句逗停顿）实测中文朗读速率约为 **`3.8 字/秒`**（约 228 字/分钟）。场均 239 字需念 **63 秒**。
- **开战门禁**：`PlayerQuestSystem.onHostReachFirstBattle` 规定战略播报未念完不许进战术场景（`classicBriefing.isBusy()` 时军团驻足等候）。因此凡战略移动不足 60 秒的战役（占全主线 **68.5%**），军团抵达战场后都必须原地干等，短途战甚至罚站 **50–60 秒**。

### 1.2 字幕条单屏上限
- 底部双行 18px 字幕条单屏舒适上限为 **`144 字`**（极限 `160` 字，见 `tools/classic-briefings/briefingLib.mts`）。
- 🔴 **144 是一屏的上限，不是一条战略播报的上限**（2026-11-16 主人定）。字数超过 144 就分成多屏，一屏一段，`ClassicBattleBriefingRunner` 念完一段自动接下一段，段数不限。

## 三、战略播报字数按移动时间定（2026-11-16 主人定，取代原 S1–S5 五档与 233 字封顶；同日加屏间留白 5 秒与 5 分钟上限）

> 原五档表让移动 65 秒以上的场次一律封顶 233 字，长途后半程没有解说。主人定：播报只有两种，战略播报字数跟移动时间对应，战术播报固定 89–144 字。

| 项 | 规则 |
|---|---|
| 屏间留白 | 屏与屏之间停 **5 秒**（`ClassicBattleBriefingRunner.SCREEN_GAP_MS`），音乐回升让观众看地图；留白期间仍算在念，到站照样等整条念完 |
| 最长 | 一条战略播报最多占 **300 秒**移动时间（含留白），约 6 屏、820 字；更长的路程后半段交给音乐和地图 |
| 字数上限 | **可念秒数 × 3.6 × 0.92 × 0.9 ≈ 可念秒数 × 2.98**，可念秒数 ＝ min(移动秒数, 300) − 5 ×（屏数 − 1）。3.6 是朗读速度（字/秒）；0.92 让军团到站前几秒念完；0.9 吸收实际移动比离线测算快一成的偏差（主人定：宁可早念完，不要到了干等） |
| 字数下限 | 上限 × 0.8 |
| 保底 | 上限最少 45、下限最少 38（原地开战也要报纪年和双方）；移动 15 秒以内的场次会比移动时间多念几秒 |
| 屏数 | 放得下上限的最少屏；一屏一段、每段 ≤144 字 |
| 单段区间 | 多屏时总区间平分后上下各放宽一成，单段最多 144 字 |
| 首战 | 不再特例，同样按扣掉开卷导语后的剩余移动秒数套公式 |
| 多屏写法 | 按顺序：承上 → 这几年天下发生了什么（同时期其他地区大事，跨洲赶路场次尤其要写）→ 主将来历 → 史载行军路线与途经地；**最后一屏固定写本场**（公元纪年、季节、交战双方、开战缘由）。不许注水 |

- 算法代码：[apply-strategic-quota-by-time.mjs](../../../tools/chronicle/apply-strategic-quota-by-time.mjs)（`strategicQuota`），就地改写现行字数表与 GG 任务单清单。
- 现行字数表：`剧本模式/02_播报文案/编年史主线1022场_战略播报字数设计表_按史实日期重排_2026-11-16.json`（按史实日期重排后的顺序与移动秒数）。

## 五、写作硬红线与引擎字段收口

### 5.1 文案硬红线（与全库口径一致）
1. **必备双要素**：除 `#1 evt_0001` 外，每条战略播报前半必须**自然承接上一场事件**（交代前战结局、数年间局势推移或为何换到当前统帅），后半必须**点明本场公元纪年（如「公元前五四六年夏」「公元二〇八年冬」）、交战双方政权/主将与开战缘由**。
2. **严守政权与地名规范**：禁「朝 / 王朝」（「朝鲜」除外），一律用政权本名或「皇族姓氏＋国号」（李唐、赵宋、刘汉等）；禁「古城 / 古都 / 旧都」及近代词、后人结局剧透词。
3. **语音纯净度**：禁括号、引号、阿拉伯数字、全角分号 `；`；不写具体兵力数字（避免与面板 1–2 万兵力钳制冲突）；战略播报末尾不得剧透战术交锋经过，也不得与同场战术播报开头四字复读。
4. **字数严卡逐场台账**：每场总字数、段数、单段字数都必须落入逐场台账给定的闭区间内；每段一屏、最多 144 字。

### 5.2 引擎与真源数据收口方式（后续回写时执行）
- **真源存储**：合并后的单段或双段文本统一写入真源的 `战略播报`（双段之间以换行 `\n` 分隔，导入器按行切为 `strategic: [第1段, 第2段]`）；原独立 `战争编年史_衔接播报_2026-11-14.json` 仅保留 `开卷导语` 与 `收官播报`，不再向每场事件追加 `ev.bridge`，避免双份叠加。
- **战术播报**：真源中的 `战术播报`（`89–144` 字）一字不动。
