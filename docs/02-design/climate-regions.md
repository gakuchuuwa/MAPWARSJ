## DE 背景图分配机制（对照说明）

DE 官方 179 张地图（rms）不是 179 套素材——是 **terrain style（地形风格）机制**：

1. 每张官方地图指定 1 个 terrain style（温带/沙漠/雪/热带/丛林/冻原/稀树草原/草原）
2. style = 全套地面贴图（terrain textures）+ 树组 + 装饰组 + 配色（colorcorrection 19 套）
3. rms 里 `#const BASE_TERRAIN <id>` 定主地形，`create_object` 对象组（AESTHETIC_FLAT/SOLID_OBJECT/FALLEN_TREE 等）按 style 取成员

**我们的同构实现**：16 主题 = 16 个「style」，每个 = baseTerrain + groundTiles + trees（3 季）+ flatDecor + solidDecor + waterPlants + beachTerrain——结构与 DE style 一一对应；
季节 = DE colorcorrection 的 Spring/Summer/Autumn/Winter；
19 套配色中 Night/Evening 等 8 套时间氛围需昼夜系统（暂无，已记录）。

# 战术模式底图分配（2026-08-24 主人定稿）

> 起因：底图「做不出帝国时代那种美感」。查下来根因不是画得不好，是**分配错了**——
> 底图曾用 18 个 DE 主题 × 季节 × 海拔 × 水系枚举出 1728 种组合，
> 那套主题是 DE 用来抽随机地图的，**跟真实地理没关系**（DE 的「地中海」是长得像地中海的图，
> 不是地中海气候）。现在改成：**按真实气候数据决定每个地方用哪张底图**。

## 0. 三条铁律

1. **底图只能是纯地表材质**。森林是树的组合（第二层），不做底图。
   但「矮树丛」系列（矮树丛／丛林／叶子／积雪）是**森林里没有树的地面**（林下落叶层），可以做底图。
2. **农田、道路、牧场不是底图**，是第二层配属，铺在底图之上。
3. **雪原、冰原不是地理类型，是季节状态**。西伯利亚夏天是针叶林地、冬天才是雪原，
   同一个地方不该占两个类——把季节混进地理分类，冬天的类会把那些地方永久吃掉。

## 1. 数据源

**WorldClim v2.1**，10 arc-min（约 18km 网格，2160×1080 覆盖全球），**CC BY 4.0 可商用**。
引用：Fick & Hijmans 2017, Int J Climatol 37:4302-4315。

用到 5 个变量 + 海拔：年均温、最冷月最低温、最暖季均温、年降水、降水季节性。

> ⚠ 现成的 Köppen 分类图（Beck 2023, gloh2o.org）是 **CC BY-NC 禁商用**，没用。

原始栅格在 `scratch/climate/`（约 66 MB，不入库，重建时重新下载）。

## 2. 攻城战底图 —— 7 张

**城郊是被人踩踏碾压的裸土**，草早没了。而且**城必然建在宜居处**（有水、能耕种），
所以砾石、盐壳、岩石这些不宜居的地面不会出现在城外
（楼兰建城时罗布泊有水，等地裂成龟裂盐壳，城已废弃几百年）。

| 底图（DE 官方中文名） | 用在哪 | 城池占比 |
|---|---|---|
| 泥地 | 极旱绿洲城 — 敦煌、和田、吐鲁番、巴格达 | 3.4% |
| 泥地 2 | 黄土城 — 黄土高原、河西、青藏河谷、中亚 | 6.9% |
| 泥地 3 | 温带城 — 中原、日本、朝鲜、欧洲 | 26.9% |
| 泥地 4 | 红土城 — 印度、伊朗高原、澳洲 | 17.8% |
| 泥地，污泥 | **黑土/水稻土城** — 江南、东北、乌克兰 | 8.1% |
| 泥地，大草原 | 草原城 — 蒙古、中亚草原 | 5.5% |
| 雪地，地基 | 雪原城 + 冬季长期积雪区 | 冬季 → 大幅上升 |

**「泥地，污泥」是黑土**，不是热带泥。黑土是温带腐殖质土（东北/乌克兰/北美大平原/潘帕斯），
江南的水稻土长期淹水同样呈青黑，归此类。热带雨林的土是**红壤**（铁铝氧化），是「泥地 4」。
这两者曾被用反。

## 3. 野战底图 —— 19 张地理类型 + 4 张季节状态

野战是**荒野原貌**，零人居痕迹。

**草地系（5）** 按降水从湿到干：草地1（>1000mm）／草地2（600~1000）／草地3（500~600）／草，丛林（湿热）／草地，干枯（300~500）

**林地系（4）** 林下地面：矮树丛（温带）／矮树丛，丛林（热带）／矮树丛，叶子（针叶林）／矮树丛，积雪（冬季林区）

**荒漠系（5）**：砂质沙漠／沙漠，流沙／裂开的沙漠（干涸盐湖）／沙砾，沙漠（戈壁）／沙砾，默认（高山砾石）

**地中海（冬雨夏干）**：土是石灰岩风化的红棕土 terra rossa，走「泥地 4」；
更干的一端（<500mm，雅典/突尼斯/大马士革）走「泥地，大草原」。
判据看**降水季节分配**（`bio15` >35）而不是总量。

**裸土系（4）**：泥地2（黄土荒原）／泥地4（红土荒原）／泥地，污泥（黑土荒原）／泥地，大草原（萨凡纳）

**湿地系（2）**：湿地，沼泽／湿地，浅滩　**山地（1）**：岩石

**季节状态（4）**：雪地／雪（松软）／矮树丛，积雪／冰原（水域层用）

## 4. 判定顺序（顺序即优先级）

**极端地形 → 干湿 → 温度带**。三条经验：

- **干旱压倒温度**：乌兰巴托降水 282mm 是草原，别因为冬天 -28°C 判成针叶林
- **高海拔压倒干旱**：青藏年降水 300~400mm，先判干旱会全变「黄草原」，但高原地表是砾石冻土
- **湿热区先判草地再分林地**：反过来先判林地，「草，丛林」会一张都用不上

## 5.5 城池数据的唯一来源

🔴 **全量导出是 `CITIES_V2`（942 座 / 23 个文化区）。**

`cities_v2.ts` 里还有 `T0_CAPITALS` / `T1_MEDIUM_CITIES` / `T2_STRATEGIC` / `PERIPHERY`
四个分数组，但**它们拼起来只有 362 座、全是东亚 14 区** ——

## 5.6 树的分配 —— 三层（2026-08-24）

主人定：**一个底图一种树**，同一张图上不混种；没用上的树靠**地区替换**和
**季节变体**循环用掉（"日本有樱花树和银杏树，替换使用，尽量都用上"）。

代码在 `src/ui/scene13/TreeAssignment.ts`，查询顺序：

1. **地区覆盖**（`REGION_TREES`）—— 经纬度框 + 限定底图，先匹配到的先用。
   同一张「泥地3」，日本长樱花、中原长榆槐、不列颠/巴尔干/意大利各长各的。
   🔴 表是**顺序敏感**的：小框必须排在大框前面，否则被大框先吃掉。
2. **底图默认**（`TREE_BY_BASE`）—— 26 张底图各有一棵默认树。
3. **兜底** —— 橡树。

拿到树之后再套**季节变体**（`SEASON_VARIANT`）：橡树→秋橡→雪橡，
白桦→黄桦→冬桦，松→雪松，战役大树→银杏(ST_G)→白枯树(ST_I)。
针叶／棕榈／热带树不登记，四季同形。

**能当树用的素材共 40 种**，全部用上（跑 `npx tsx tools/audit-tree-assignment.mts` 验收）。
不在内的三个：`JUNGLE` / `RAINFOREST` 是**地面草丛**不是树，`PINE` 那张是
枯死的褐色松，只配沙漠，别当针叶林用。

### 5.6.1 密度（`DENSITY_BY_BASE`）

🔴 主人定：**「不要太密，毕竟是战场，主要表现的是军团」**。
调之前实测均值 104 棵/图（温带到 160），树把战场糊满了；现在 **20 棵/图**。

两个数：`forestCover`（林块占**可用地**的比例，密度主体）+ `stragglers`（林外孤树）。
换算基准：forestCover 每 1 个百分点 ≈ 落地 7 棵。
🔴 **改完必须重跑 `npx tsx tools/audit-tree-density.mts` 实测**，别照公式算——
树先按预算生成，再被间距、走廊、屏幕外三道剔除，账面和落地差得远。

梯度比绝对值重要：旧表温带 159 / 沙漠 42，只差 3.8 倍，等于没分气候；
现在林地 50 / 草原 6.6，差 7.6 倍。

### 5.6.2 攻城战 vs 野战（两条真实性规则，主人 2026-08-24 定）

| 规则 | 为什么 | 实现 |
|---|---|---|
| **攻城战的树更少** | 城郊的林子早被砍去做梁柱、烧柴、修攻城器械，剩下的地开成耕地牧场。城下从来不是林子，是清出来的开阔地 | `treeDensityFor(tile, isSiege)` 打 0.6 折 |
| **攻城战不出枯树** | 城郊立着的枯木早被拾去当柴烧了 | `pickTree` 把 `DEAD_TREE` 换成活树；「荒原枯荣伴生」那段攻城战整段跳过 |

🔴 **植被看自然环境，不看地面被踩成什么样。**
攻城战底图是「城郊被人踩踏碾压的裸土」，是人为改造的结果，不代表植被条件。
所以树种和密度都查**当地的野战底图**（`vegetationTile`），攻城战只在数量上打折。

不这么做的后果实测过：**149/942 座城的攻城战树比野战还多**——
因为攻城底图那 7 张全是宜居地的泥土，天然比当地实际的戈壁/流沙/干草原「湿润」。
攻城战的「树更少」必须由折扣负责，靠底图差异会翻车。

### 5.6.3 树不许长在守方城池上

攻城战的城池（石基 + 城门前硬化石路，`Scene13WarLayer.applyDefenderCityRoad`
和 `addGateFoundation`）在 `generateEnvironment` **之后**才铺，环境层不知道它在哪。

## 5.6.10 地表变体必须同色系

🔴 [2026-08-24 主人拿 DE 真图对比：「图1 是你画的，图2 是 DE 的」]

DE 的地面变化是**同色系、低对比、边界几乎看不出**（浅黄绿铺在绿草上）；
我们是**深褐斑铺在浅黄底上**，一眼就是几块补丁。

**实测**：149 种「底图×变体」组合里 **63 种 RGB 色差 >45**，
最夸张 `pal → sr2` 色差 **132**、`ds2 → gr4`（黄土上铺黑土）色差 78 共 698 格。

根因：变体贴图取自 DE **主题**表（`theme.groundTiles`），和底图不同源——
底图按真实气候查表选，主题按 biome 选，两套并行必然对不上。

三处一起改：

| | 原来 | 现在 |
|---|---|---|
| 变体贴图 | 主题表（按 biome） | **`DecorFit.GROUND_VARIATION_BY_BASE`**（按底图，同色系） |
| alpha | 0.75 | **0.45** |
| blur | 无 | **18** |

改完：色差 >45 的组合 **63 → 0**，最大色差 36。

那张表是**按贴图平均 RGB 算出来的**，每张底图取色差最小的几张，注释里标了实测色差。
候选池只放外观确认过的贴图（`fm2`/`o_rd3`/`rm2`/`gr8` 这些没看过的一律不用），
牧场 `pm1`/`pm2` 不进表（只在攻城战出现，走另一条线）。

⚠️ **冬季雪原除外**：DE 的冬季地面就是「雪 + 露土枯草斑块」，那个高对比是**有意的**，
由 `isWinterSnow` 分支单独管，别拿同色系去套。

验收：`npx tsx tools/audit-ground-variation.mts`（色差 >45 直接报错）

### 5.6.11 DE 的地表分层：**碎块铺满**，不是撒斑块

主人 2026-08-24 追问「这个草的比例改了吗」，顺着查到 DE 的真正机制。

权威：`gamedata_x2/F_seasons.inc` 定义 `LAYER_A/B/C/E/F`，
`AfricanClearing.rms` 等 638 处 `create_terrain LAYER_x` 使用它。

```
create_terrain LAYER_A {
  base_terrain    LAYER_B
  land_percent    100        ← 铺满
  number_of_clumps 1000      ← 上千个小碎块
  spacing_to_other_terrain_types 0
}
```

| | DE | 我们（改前） | 我们（现在） |
|---|---|---|---|
| clumps | **1000** | 14 | **45** |
| 每片 | 小碎块 | 8~18 格 | 10~22 格 |
| 覆盖 | 铺满（分层交错） | 5~12% | 25~45% |
| 观感 | 细密斑驳 | 几块孤立补丁 | 斑驳 |

按面积换算：DE 20736 格用 1000 clumps → 我们屏内 2111 格约 100 clumps，取 45。

#### 🔴 关于色差，前一节的结论要修正

实测 `F_seasons.inc` 里 LAYER 组内两两色差：**中位 41，43% 超过 45**
（最大的几对是 `for↔sno` 185、`ds3↔sno` 153，都是雪；去掉雪也有 `ds3↔pal` 81、`ds4↔pal` 73）。

**所以 DE 本来就用大色差，我把上限压到 36 是过度矫正。**
但不能因此放开——差别在**铺法**：

> **小斑块 + 大色差 = 补丁；碎块铺满 + 大色差 = 斑驳质感。**

DE 敢用大色差，是因为它铺满 + 上千碎块 + blends 咬边；
我们只铺 5~12% 时必须同色系。现在提到 25~45% 覆盖，色差仍保守（≤36），
观感已经对了，就先不放宽——**放宽色差前必须先确认覆盖率和咬合到位**。

## 5.6.14 地面「一道暗带 + 一道亮带」

🔴 [2026-08-24 主人在 atlas 里看到，问「我是不是删除，还会出现？」——**会**，
这不是个别图的问题，是渲染参数，删一张下一张照样有]

### 根因不是贴图渐变

另一个 AI 诊断说「DE 地形贴图自带垂直明暗渐变（沙漠 129→97 / 146→156），
平铺时亮底边接暗顶边跳成条纹」，建议对 84 张素材做亮度归一。**实测不成立**：

| 查的 | 实测 |
|---|---|
| 84 张地形贴图全量 | 顶底总落差**全部 <14**；接缝跳变只有 3 张 >15（fc3/fc2/rc3，都不在用的 26 张里）。`des` 顶 154/底 153、`pal` 168/167 |
| 高程趋势（82 张） | 「上高于下」占 41%，随机，无固定方向 |
| 代码 | 全项目无 `createLinearGradient`/`vignette`/整屏渐变遮罩 |

**照那个方案改素材，等于为一个不存在的问题把 84 张贴图弄脏。**

### 真根因：`ELEV_SHADE_DARK` 拉满

`Scene13GroundPainter.ELEV_SHADE_DARK = 0.40`（压暗 40%），
而**注释写的是「约 −20%，与 DE 坡面对比同量级」——注释和值差一倍**。

`addMicroRelief` 是 **20~50 格的低频波**，一个波峰就横跨整屏，
整条坡同时把强度 m 拉到 1 → 屏幕上就是一道贯穿的暗带 + 一道亮带。

实测（atlas 34 张里 **17 张**中招）：

| 图 | 中段 | 顶部暗带 | 底部亮带 |
|---|---|---|---|
| `ds2 配 OAK` | 146 | **88**（146×0.60=87.6，正是 0.40 拉满） | 156 |
| `ds2 配 PALM` | 147 | 92 | **180** |

改成 `DARK 0.40→0.24`、`LIGHT 0.32→0.18`（回到注释说的量级）：

| | 改前 | 改后 |
|---|---|---|
| `ds2 配 OAK` 顶部 | 88 | **112** |
| 明暗差 >25 的图 | **17/34** | **3/38** |

坡面立体感还在，但不会糊成一条带。

### 🔴 真正的根因：光照方向的**屏幕纵向分量**

降 `ELEV_SHADE_DARK` 只是把带压淡（26→13），带还在。主人追问「怎么还有啊」后又查了三轮，
最后定位到 `ELEV_LIGHT_DIR_X/Y` —— **那是网格空间的方向，不是屏幕空间的**。

等距投影：网格 x → 屏幕 `(+32,+16)`，网格 y → 屏幕 `(-32,+16)`。原值换算：

```
0.95×(32,16) + 0.32×(-32,16) = 屏幕 (20.2, 20.3)   纵横比 1.01
```

**屏幕上是 45° 斜光，纵向分量和横向一样强。**
而一屏只容得下 2~3 个高程波长，屏幕纵向的大缓坡**必然存在**
（实测 51% 的图「屏幕上/下带与中段平均高程差 >0.35」），
于是被渲染成横贯全屏的明暗带。

改成 `(0.92, -0.39)` → 屏幕 `(41.9, 8.5)`，**纵横比 0.20**：纵向坡不再产生明暗差，
横向坡照旧有立体感。

| | 改前 | 降 DARK 后 | 改光照方向后 |
|---|---|---|---|
| 最大明暗差 | 26 | 25 | **13** |
| 差 >15 的图 | 4/45 | 4/43 | **0/30** |
| 平均差 | — | — | **5.8** |

#### 排除过但**不是**根因的（每条都实测过）

| 假设 | 实测 |
|---|---|
| 地形贴图自带垂直渐变（另一个 AI 的诊断） | 84 张全量，顶底落差**全部 <14**；`des` 顶 154/底 153 |
| blends 咬合遮罩 | 遮罩按**一格**平铺且只在边界带起作用，不影响主体 |
| canvas 半透明像素透出黑底 | alpha 全 255，半透明像素 **0.0%** |
| `height_limits` 硬绑高度带 | 改成软约束后差值几乎没变（25→25） |
| `ELEV_SHADE_DARK` 太大 | 降 0.40→0.24 只把带压淡，没消除 |

验收：`npx tsx tools/audit-terrain-shading.mts`
（屏幕纵横比 >0.45、DARK >0.30、LIGHT >0.24 任一超标直接报错）

## 5.7 冬季积雪判定

积雪**只认 world-base 的冬季标志**（B 通道，来自 WorldClim 实测最冷月气温），
和底图同源，一处真相。`isSnowArea(lat, elev, biome, lng)` 传了经度就走这条路；
不传（单测/兜底）才回落到旧的纬度估算——那套估算对「温带中高纬」一律返回 true，
是硬伤的来源，别拿它当判据。

**阈值 `WINTER_SNOW_TC` 两次放宽的账**（判据 = 最冷月均温）：

| 值 | 症状 |
|---|---|
| -12 | 莫斯科 -10.4°C、雪期四个月，判不出雪 |
| -8 | **乌普萨拉(瑞典) -3.4°C 判成无雪**，整个斯堪的纳维亚、北海道、东北欧都卡在 -3~-8 |
| **-3**（现值）| 气候学上稳定积雪（积雪期 60+ 天）的界限 |

南方安全边距很大：江南 0.6°C、川蜀 2.3°C、罗马 8°C、雅典 10°C、岭南 9.9°C。
改完 942 座城有 56% 冬季积雪（40~50°N 82%、20~30°N 11%、20°N 以下 0%）。

🔴 曾经的硬伤：**罗得岛、克里特岛(诺索斯)、底比斯这些爱琴海城冬天结冰**。
地中海从不结冰。`audit-winter-snow.mts` 内置 15 个人工核对点专门拦这个。

## 5.8 水域

### 海（`buildCoastline`）

三带，从外向内：

| 带 | 贴图 | 说明 |
|---|---|---|
| 外海深水 | `waterTerrainForTheme` 按气候取色 | 地中海 wt5 蓝绿 / 北欧 wt2 深蓝 / 热带 river_clean_green / 沙漠 wt_yellow2 含沙黄 / 冬季 ic2 |
| 近岸浅滩 | `sh2` | 能看见水下沙底的清透浅水 |
| 沙滩 | `beachTerrainForTheme` | bch / bc2 / bc3 / bc4 / des / ds2 / beach_wet / ice_beach |

🔴 曾经的硬伤：**整片海从岸铺到屏幕边缘都用 `sh2`** —— 全世界的海都只有齐腰深，
而且地中海、北海、南洋、北极一个颜色。那 11 档气候水色只对河湖生效，对海一点用没有。

**海恒在左侧**（`sideLeft = true`）：攻方破浪抢滩、守方陆地坚守。

### 水军战斗（主人 2026-08-24 定）

> 「如果是水军的攻城战，做用左边是海的图。先不做水军野战，水军野战保持战略地图模式。」

## 7. 踩过的坑

| 坑 | 后果 | 教训 |
|---|---|---|
| 用全局调色滤镜救观感 | 做完几乎没差别 | 观感问题先量事实，别拿估的参数糊近似 |
| 底图用了森林贴图 | 6 个主题的底图是 `for`/`fo2`，等于整张图都是林子 | 底图只能是纯地表材质 |
| 温度判据排在干旱之前 | 蒙古草原判成针叶林 | 干旱压倒温度 |
| 干旱判据排在高海拔之前 | 拉萨判成黄草原 | 高海拔压倒干旱 |
| 雪线公式取 4800m | 整个青藏判成雪原，雪原占陆地 35% | 雪原只用温度判（最暖季 <5°C） |
| 「低海拔+多雨」判沼泽 | 杭州、广州、京都全成沼泽 | 沼泽取决于地形低洼，气候判不出来，手工点名 |
| 用坡度角判裸岩 | 18km 网格把坡度平均掉，`arctan(500/18500)=1.5°`，一张都判不出来 | 直接用相邻格高差 |
| 红土判据只看降水 | 把常年湿润的岭南、南洋也吃了 | 红土要有明显旱季（降水季节性 >75） |
| DE 的主题当地理用 | DE 的「地中海」只是长得像，不是地中海气候 | DE 的**搭配法则**可以学，**地区映射**不能抄 |
| 城池数据拼分数组 | 只读到 362 座、全东亚，工具打开清一色中国城 | 全量只有 `CITIES_V2`；两边读同一份数据必须对账 |
| 只看降水总量不看季节分配 | 罗马(760mm/季节性41) 和不莱梅(679mm/季节性16) 判成同一种土，整个地中海沿岸被当成德国 | 干湿**分配**和总量一样重要，`bio15` 降水季节性必须进判据 |
| 只用东亚的城肉眼验收 | 西方误判一次都没发现 | 验收点必须跨洲 |
| 草原底图默认树给了金合欢 | 布拉格、蒙古长出非洲稀树草原的树 | 默认树要挑**全球安全**的（橡树），有地域性的走地区覆盖 |
| 用 `as never` 断言掩盖 `generateEnvironment` 的参数名写错 | 量出「全局 2 棵树」的假数据，还差点照它去调参 | 类型报错是在救你，别断言掉；参数名是 `width`/`height` |
| 攻城战密度指望靠底图差异实现 | 149/942 座城攻城战树反而更多 | 攻城底图全是宜居泥土，比当地真实环境湿润；折扣要显式打 |
| 地表变体取自主题表 | 黄土上铺黑土（色差 78）、沙漠上铺草地（色差 132），屏幕上是几块深色补丁 | 变体必须与底图**同色系**，色差 ≤30；两套体系并行（底图按气候、变体按 biome）必然对不上 |
| 把「网格空间的方向」当成屏幕方向 | 光照 DIR(0.95,0.32) 投影到屏幕是 45° 斜光、纵横比 1.01，屏幕纵向大缓坡被渲染成横贯全屏的明暗带 | 等距投影下**网格方向 ≠ 屏幕方向**，凡是方向性参数都要换算到屏幕再判断 |
| 只压强度不改方向 | DARK 0.40→0.24 把带从 26 压到 25，几乎没用 | 带的成因是**方向**，压强度只是让它变淡 |
| 注释和常量值差一倍 | 注释写「约 −20%」，`ELEV_SHADE_DARK` 却是 0.40，照注释理解就查不出问题 | 注释只是某次实测的快照，**判据看值本身**（AGENTS.md「别看注释」） |
| 变体 alpha 0.75 + 无 blur | 不透明硬边 = 一块贴上去的补丁；DE 的边界看不出 | 低对比要靠 alpha + blur 一起，光换贴图不够 |
| **照一张截图目测定密度** | 从主人发的 DE 截图数「一屏 18~22 处岩石」就把石头调到 10~16，实测总数飙到 34 个/屏、**超 DE 密度 5~10 倍**。那张是**战役地图（手工摆放）**，不是随机地图 | 密度只认 `.rms` 里的 `number_of_objects` + 地图尺寸**实算**；截图不能当基准，先分清是随机图还是战役图 |
| 拿 DE 数字不做尺寸换算 | DE 全图 20736 格，我们一屏 2111 格，差 10 倍 | 引用 DE 任何数量前，先把两边的 tile 数量出来 |
| 林块预算极小时仍强制生成 | `perClumpTarget` 的 `Math.max(4,…)` 兜底，让安第斯高原铺出 8 格林地地表却没长树，屏幕上一块孤零零的深色菱形斑 | 预算不够就整个不要，干旱区本来只有散树 |
| 伴生碎石写死 ROCK1/2/3 | ROCK3（橙褐沙漠岩盘）出现在德国温带、俄罗斯雪原 | 伴生素材从该底图配的列表里取 |
| 文化专属素材挂在气候主题上 | 十字架墓碑挂 `europe_mediterranean` 后，智利的图卡佩尔照样长十字架——那是「地中海气候」不是「欧洲」 | 气候主题管草木，文化物件按经纬度判 |
| 装饰表不看季节 | 寒带的夏天地上撒了 883 块冰 | 素材有季节属性的，撒之前过一道季节闸 |
| 地面副色用异色系 | 灰砾石斑块在橙土上是个突兀的圆 | 地面变化用同色系深浅；碎石用岩石精灵表现 |
| 斑块贴图与底图同名 | 库斯科 14 片里 9 片白铺 | 下笔前先比一眼底图 |
| 积雪按纬度估，不看实际气温 | 罗得岛、克里特岛冬天结冰——地中海从不结冰 | 有气候数据就查数据，估算只配当兜底 |
| 整片海用同一张浅滩贴图 | 全世界的海一个颜色、且都只有齐腰深；11 档气候水色形同虚设 | 「有一张能用的贴图」不等于「分配到位了」，要按气候查一遍 |
| 拿 `isWaterTile` 验收海面 | 它只认参与**动态波纹**的 wt 系，不认浅滩 sh2，把「全部出海」误报成「86/86 没出海」 | 借用别处的判据前先看它的定义，函数名像不代表语义同 |
| 为工具的显示问题去改引擎 | 差点因 `render_cities.mts` 的菱形羽化留缝（简化渲染，无 blends 咬合）去动 buildCoastline | 先分清是工具还是引擎——工具头注释写了「简化渲染」 |
| 地区框之间留了空隙 | 库斯科(-13.5°N)掉在安第斯框(南界-20)和中美框(北界2)中间，秘鲁高原长出亚洲松 | 相邻框的边界要**接上**，别各画各的 |
| 树的可用地只排除了水和走廊 | 平均 3.8 棵树长在守方城墙和城门前的石路上 | 城池在环境层之后才铺，位置只有 WarLayer 知道，必须显式传 `keepClear` |
| 地区框的 `bases` 漏填一张 | 江户是 ds4 不是 ds3，日本长出橄榄树；济州、奄美、台南同理 | 框只差 0.2 度或少一个底图就整片漏掉，只能靠脚本扫全量城池发现 |
