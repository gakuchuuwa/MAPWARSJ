# 13 战斗 v2 规范 —— 一人一精灵 · 无编队 · 分批投入

> 状态：**定稿实施中**（2026-08-11 主人拍板）
> 取代：`scene13-choreography-spec.md` 的编队部分（三幕时间轴与「无运行时决策」铁律保留）
> 适用范围：**仅 13**。8/9/10 一个像素不许动。

---

## 0. 前提：13 是一个新游戏

主人 2026-08-11 明确：**不要按现在的模式设计，13 是新游戏。**
因此本规范不继承 30s/60s 时长档、不继承 9 编队、不继承「战斗要短以免拖住战略层」。
战略层在 13 期间等着，这不是 13 要解决的问题。

---

## 1. 三个数，其余全是推导

| 常量 | 值 | 怎么来的 |
|---|---|---|
| 单兵绘制尺寸 | **137.8 px** | `75 × 1.4 × (84/64)`，与现在完全一致，不改 |
| 每方同屏人数 | **180**（18 列 × 10 排） | 半屏 1920×540 ÷ 站位间距 103.35×55.12 |
| 每波时长 | **4 s** | 一波要看得出「压上→交战→打光」，再短就是闪 |

推导：

```
波数     = ceil(本方兵力 / 180)
战斗时长 = 波数 × 4s          ← 什么时候打完什么时候算，不再是常量
```

| 兵力 | 波数 | 时长 |
|---:|---:|---:|
| 5,000 | 28 | 1.9 分钟 |
| 10,000 | 56 | 3.7 分钟 |
| 30,000 | 167 | **11.1 分钟** |
| 100,000 | 556 | 37 分钟 |

### 1.1 为什么不缩小单兵

屏幕面积是硬约束：1080p 装得下 360 个 138px 的兵，这是几何不是性能。
分批把「同屏要装多少人」从总兵力解耦成每波 180 人，**尺寸问题就此消失**。
2026-08-11 实测的一屏容量表（138/70/40/30/20/12px → 360/1450/4320/7700/17300/48000 人）
留档备查，但在本方案下用不上。

### 1.2 为什么不需要任何渲染优化

同屏 360 人 = 每帧 360 次 `drawImage` ≈ 0.4 ms。
2026-08-11 实测这台机器（GTX 1660 Ti）的墙在 **约 4000 次 `drawImage`/帧**
（跨过去从 4ms 跳到 24ms，6 倍断崖；与精灵尺寸无关，是调用次数不是填充率）。
360 离墙有 11 倍余量，**因此不做编队块预渲染、不做 WebGL 实例化、不做视口裁剪**。
这些手段只有走「小而多」路线（数千~数万精灵同屏）才需要，留档在本节备查，不要提前实现。

## 2. 取消编队

编队当初是**决策粒度**的优化——9 个编队各自寻敌比 66 个兵各自寻敌便宜。
剧本法删掉了全部运行时决策，**没有决策要省了，工具就该扔**。

（帝国时代、三国群英传都是每兵独立、上千同屏、没有编队。
2026-08-11 我一度说「帝国时代上限 200」，那是默认值不是引擎上限，主人已纠正。）

**因此删除**：`squadTroops` / `squadStates` / `squadOffsets` / `slotPlanAt` 的格位角色表 /
`SCENE13_FLANK` / `solveScene13Advance` 的「前排格位」概念。

---

## 3. 阵型：按兵种分带

不再有 3×3 格位。每一波的 180 人按兵种连续铺开：

```
        ← 战线宽 18 列 →
排 0-1  枪 盾 枪 盾 …        近战带（顶在最前）
排 2-3  枪 盾 枪 盾 …
排 4-5  骑 骑 …（两端）      骑兵带（占两翼，中段留空）
排 6-9  弓 弩 弓 弩 …        远程带（最后）
```

带内每个人的位置 = `f(他在本波里的序号 i, 幕, t)`，一个公式到底，没有分支。
角色分工由「他在第几排」决定，不需要角色表。

---

## 4. 波次时间轴

第 k 波（k = 0,1,2…）在 `t ∈ [4k, 4k+4)` 秒内演完，四个阶段：

| 阶段 | 占比 | 内容 | 动作 |
|---|---|---|---|
| 入场 | 25% | 从己方后方走进战线位置 | MOVE |
| 咬合 | 15% | 两军前缘压到重叠位（沿用 `SCENE13_CONTACT_RATIO`） | MOVE |
| 交战 | 45% | 原地互搏，按曲线逐人倒下 | ATTACK |
| 收尾 | 15% | 残余退出/倒毙，下一波已在入场 | DEATH/MOVE |

- 相邻两波**重叠 15%**：上一波收尾时下一波已经在入场，画面不会空。
- 全部是 `f(t)`：没有寻敌、没有碰撞、没有运行时决策。这条铁律从 v1 继承，不许破。

---

## 5. 阵亡：逐人

胜负仍由八环在 t=0 锁定，本规范**不碰引擎**。
每一波投入 180 人，本波结束时按「该波应损失比例」决定倒下多少人，
从最前排往后逐个 DEATH。粒度从 v1 的 3,333 人一跳变成 **1 人一跳**。

## 6. 已知待办（不在首版）

1. **悬念节奏**：11 分钟里血条平滑下滑会腻。需要给波次编排（某波打崩、某波顶住、援军入场）。
   首版先跑通，节奏单独做。
2. **语音播报 / Cut-in 频率**：现按 30s 战斗调的，11 分钟里会太稀疏。
3. **援军加时**：`+10s/只` 在时长推导化之后失去意义，改为「援军兵力并入总兵力 → 自动加波数」。
4. **火焰三幕**（0%/40%/80% 点燃）按进度比例走，无需改。
