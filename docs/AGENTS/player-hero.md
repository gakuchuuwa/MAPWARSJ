# 玩家乱入者 · 规则细则（AGENTS.md 外置）

> 主人 2026-09-09 定：**「这是一个获得兵模的游戏」**。玩家的成长线不是数值，是**收集兵模**。
> 本文件是玩家系统的规则真源。代码在 `src/player/`，13 里的加成在 `src/ui/Scene13WarLayer.ts`。

## 一、玩家是谁

- 玩家是**乱入者**，不是关羽。
  🔴 [2026-09-09 主人定「赶紧删除」] **玩家系统已彻底不引用 `guanyu` 素材**：
  兜底 key 是 `PLAYER_FALLBACK_HERO_KEY = 'antiquity_scout_cavalry'`（`PlayerConfig.ts`），
  九个官阶全部解析到古典斥候骑兵，升上去穿什么只由**收到的兵模**决定。
  之前 `heroKeyForRank` 的兜底是 `'guanyu'`，玩家一升斥候、兵模还没收到时就顶着绿袍赤兔跑。
- 单骑期**不进军团管理器**；随军后**必进 13**（战术模式）。
- 官阶九级：平民 → 斥候 → 探马 → 先锋 → 将军 → 元帅 → 公侯 → 国王 → 皇帝（`PlayerConfig.ts`）。

## 二、兵模奖励（核心机制，2026-09-09 主人定）

### 2.1 加入军团 = 换兵模 + 得兵模

**玩家加入一个新军团时，模型立刻变成该军团三排编成里随机的一种，并永久拥有这个兵模。**

- 抽取范围 = **玩家所加入的那支军团的三排编成**，不是文化区默认表。势力有专属番号编制就用专属的。
- 抽中即换上：加入哪个军团，就顶着那个军团的兵打仗。
- **除非玩家亲手换过兵模**：玩家在面板上手动选过一次之后，就以他选的为准，后续加入新军团不再自动顶掉他的选择（仍然照常**获得**新兵模进收藏）。

### 2.2 官阶决定能收到几种（四档）

🔴 **池子 = 该军团的四种兵模：三排 + 船。** 每档从池子里**随机**抽一种没收过的。

| 官阶 | 该军团已收到几种 |
|------|------------|
| 平民 | 0（还没入伙，用兜底形象古典斥候骑兵） |
| 斥候 | 1 |
| 探马 | 2 |
| 先锋 | 3 |
| 将军及以上 | 4（该军团收齐，含战船） |

- 抽到船就进 `learnedShips`，抽到兵就进 `learnedUnits`，同一个池子、同一条阶梯。
- 计数只数**这个池子里的**，别处收的不占名额，也不会被顶掉。

### 2.3 终身保留（凑卡玩法的根）

**这是一个凑卡游戏 —— 收集所有兵模**（主人 2026-09-09 原话）。已获得的**永不回收**：
军团战败、脱离势力、改投他家、掉阶，一律保留、一律仍可选用。

「离开军团后要重新升级」指的是：`detach()` 会 `resetMerit` 把功勋归零、官阶掉回去，
要重新往上爬才能收**下一个军团**那四种 —— **不是**把已收的清空。

> 曾有三处会把它清光，全部已删，别再写回来：
> ① `factionId` 为空就清空（军团战败 → detach 清 factionId → 奖励当场蒸发）；
> ② 换势力清空重学；③ 掉阶按总数截断。

### 2.4 海上兵模（2026-09-09 主人定）

**初始海上兵模是独木舟 `CANOE`（`PLAYER_START_SHIP_KEY`）。海上画什么船，按有没有势力分两种：**

| 情况 | 海上画什么 | 玩家能不能选 |
|---|---|---|
| **有势力** | **该势力的舰队兵模** —— 入伍了用所在军团的船，没入伍按势力文化区取舰队船 | ❌ 不可选，玩家自己那条不显示 |
| **无势力**（单骑独行） | 玩家自选：独木舟 + 已获战船 | ✅ 面板下拉 |

- 拥有：船是该军团**四种兵模里的第四种**，按 2.2 的档位随机抽到即入 `learnedShips`（终身保留）。
  取 `host.navalShipAssetLock ?? getCultureNavalShip(军团文化区, 势力)`。
  已获战船**只在无势力时**才影响画面，有势力时它只是收藏。
- 唯一入口 `PlayerHero.shipKey`，单骑渡海与随军渡海**两条路都读它**，别再各写各的。
- 血训：原来单骑渡海写死 `MERCHANT_SHIP`（商船），与「初始是独木舟」的定案对不上，一直没人发现；
  随军渡海则是无条件抄军团的船。两处都已归并到 `shipKey`（2026-09-09 修）。

## 二·四、自动选择兵模（面板开关，2026-09-10 主人定）

面板上的「🎲 自动选择兵模」（`PlayerHero.autoPickUnit`，存档保留）：

| 开关 | 有势力 | 无势力 |
|---|---|---|
| **开**（默认） | 按凑卡玩法：加入军团时换成**该军团**的兵模 | 已获形象按 **骑兵 → 战车 → 象兵 → 步兵** 自动优选 |
| **关** | 都不自动换，只用玩家在面板上手选的那个（关掉后任何官阶都可手选） |

- 优先级函数 `factionlessAppearancePriority`（`PlayerConfig.ts`）：0 骑兵 / 1 战车 / 2 象兵 / 3 步兵 / 4 其他。
  实测分类：骑兵 173、战车 11、象兵 16、步兵 204、攻城器械等 29 垫底；弓骑算骑兵、象弓与弩炮象算象兵。
- 🔴 **面板「陆战」下拉不得按官阶禁用**（2026-09-11 主人报「我的兵装打不开」）：
  原实现是「自动兵模开着时，官阶 >= 斥候才能手选」，于是**掉阶回平民**（§2.3 明定兵模终身保留）
  的玩家下拉被 `disabled`、点不动。判据只留一条：**手上有兵模（`learnedUnits.length > 0`）就能手选**。
  「自动兵模」只管「加入军团时自动换」，不挡手选；关掉它本就不自动换（见上表）。
  实测：平民 + 2 件兵模 + 自动兵模开 → 改前 `disabled=true`（点不动）／改后可选，手选第 2 项 → `selectedUnit=1`、`heroKey` 即刻生效。
- 🔴 **无势力优选只在无势力时跑**（`syncMoveProfile` 里 `!this.factionId` 那道闸）——
  加入势力后必须让位给凑卡玩法，否则玩家永远顶着骑兵、拿不到军团发的兵模。
- ⚠️ 旧的隐式锁 `manualUnitPick`（「亲手换过就永久不再自动换」）**已废弃**，只为读旧存档保留，
  不再参与任何判据。主人要的是一个看得见的开关，不是"点过一次就变脾气"。

## 二·五、找武将：认人不认城（2026-09-09 主人定）

主人原话：**「到了城里总是没人就换武将了，能不能改为直接去找武将？无论在不在城中。」**

- 选目标时**不再排除「已率军在外」的武将**（原来 `pickAutoCity` 里 `if (away) continue`，
  于是玩家赶到城里扑空、当场换人，反复空跑）。选将优先级不变：兵最多 → 名将 → 双行，同档才比远近。
- 武将带兵在外 → 玩家**追出去**（`PlayerHero.travelToArmy` + 每帧 `stepChase`）：
  锚点取**军团正在去的那座城**（追落脚点比追当前坐标省路，也保证追得上——军团停下攻城时必然会合），
  取不到才退回军团脚下最近的城。够近了触发野外会面。
- 已经在路上、到城扑空 → **就地转追**，不再换目标。
- 野外会面谈的是**直接入伍**（`joinMarchingArmy`）：军团现成的，不用起兵，其余与城中「随军出征」同口径。
### 就近寻将（开关，默认关）

主人 2026-09-09：**「自从添加了就近寻找武将，就再也不去其他文化去了」**，故改为玩家面板上的开关
（`PlayerHero.nearbyFirst`，存档保留，面板「📍 就近寻将」）。

选将顺序**两种模式完全一样**，只有最后一步不同：

```
有武将档案 → 兵最多 → 名将 → 双行 → 擅攻 → [就近 关：同档均匀随机 / 开：同档取最近]
```

为什么关掉就跑得开：实测开局 **1085 座据点有锚定武将**，最优档「名将 + 双行」有 **85 座**，
散在全世界；而开局全图兵力一样，「兵最多」筛不掉任何城 —— 同档集合就是这 85 座。
就近于是永远选到出生地旁边那一座，玩家再也不出门。关掉 = 在 85 座里均匀随机。
（探针：`scratch/probe_quest_pick.mts`）

> ⚠️ 随机必须**显式**从同档集合里取。别指望 `compareGeneralsByPriority` 的随机比较器
> —— 它只在四项全平时返回 `Math.random()-0.5`，比较器不自洽，`sorted[0]` 不是均匀随机。

- 三个必须清干净的边界：① 追击途中路过的锚点城**不触发城中对话**（`chaseArmyId` 闸门，
  `handleArrive` 与 `travelToCity` 的「已在城下」早退路径**两处都要**）；② 规划失败（无路可达）
  当场放弃追击，否则「无路可达」每帧刷屏；③ 玩家手点据点 / 入伍 / 读档 一律 `cancelChase()`。

## 二·六、面板随势力开合（2026-09-10 主人定）

| 玩家状态 | 军团面板 / 军情面板 / 玩家面板 |
|---|---|
| **没有势力** | 自动**展开** |
| **加入势力** | 自动**缩小** |

**开局也算**：玩家开局没势力 → 三面板展开。

🔴 **唯一实现在 `PlayerHUD.refresh()` 的势力分支**（`lastPanelFactionId`）。
初值 `undefined ≠ null`，所以**开局第一次 refresh 就应用一次**；之后只在势力变化或退出 13 时再应用。

> ⚠️ 别在 `PlayerHero` 或别处再写一份 —— 2026-09-10 我重复写过一次（`applyFactionPanelLayout`），已删。
> ⚠️ 与「开播时面板自动最小化」的关系：**这三个面板归势力规则管**，开播不再强收它们
> （开播那一下只把 `lastPanelFactionId` 置回 undefined，让势力规则重新裁决）。
> **右下角时间面板不在这三个之内**，仍由 `StreamModeToggle` 按开播收起。

## 三、玩家在 13（战术模式）的加成

主人 2026-09-09 原话：**「不要加攻击力，要加攻击频率、血、防；不死才是硬道理，不然玩家一直死就没意思了，要给人感觉玩家是战斗到最后一个的那个人。」**

| 常量（`Scene13WarLayer.ts`） | 现值 | 作用 |
|------|------|------|
| `HERO_ATTACK_RATE` | 2.0 | 装填 ÷2，出手频率翻倍。**单刀伤害不变** |
| `HERO_HP_MULT` | 3.0 | 最大血量 ×3 |
| `HERO_DAMAGE_TAKEN` | 0.3 | 受伤只剩三成，等效「防」 |

铁律：

1. **不加攻击力。** 快只体现在出手次数上。
2. **不叠官阶 `powerMult`。** 那份已经走第九环进了所属军团战力，再乘一遍就是「名将算两遍」那种重复。
3. **不去改 `WAR_TYPES` / 不往 `statsFor` 分表里加防。** `heroKey` 是玩家当前所选的已学兵种，动分表会让**同兵种的所有小兵**跟着变硬。免伤必须挂在「挨打这一刻」，那是唯一只影响玩家一个人的位置。
4. **玩家永不真死，只落马重整**（`heroDown`：退回本方后方、回满血）。任何新增的伤害路径都必须走 `heroDown`，不许直接 `pushCorpse`。
   - 血训：守方箭塔那条伤害路径原本直接 `pushCorpse`，玩家被箭塔射死会**变成尸体永久离场**。攻城战占九成、守方满墙箭塔，这就是「玩家一直死」的大头（2026-09-09 修）。
