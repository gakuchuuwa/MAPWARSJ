# 建筑风格判定与代理规则（2026-10-18 定）

> 本页是「据点建筑风格怎么判、缺分支怎么办、不许再犯什么错」的单一口径。
> 以后所有 AI 改 `buildingStyle` 前先读本页；与 `AGENTS.md` 顶部「历史判定铁律」配套。

## 一、核心原则

1. **按历史上真实建成的实体建筑判**，不按当前武将、势力、旧值或「保持现状」判。
2. **据点定义武将，不是武将定义据点。** 先定据点本身代表哪个政权 / 时代 / 建筑形态，再据此配武将；武将与据点冲突时改武将，不反改据点。
3. **不许把历史选择题丢给主人。** AI 查证、给依据、自己下结论；只可问「缺哪条史料」，不问「你要 A 还是 B」。
4. **不为一个据点新建文化系统。** 66 分支固定；缺分支时用现有最接近分支，明确标「代理」，不得冒充精确。
5. **建筑风格牵动文化 / 军团 / 武将时，优先只改城堡外观，不随便改 `buildingStyle`。** 例如奥农多加：`buildingStyle` 仍 `AMERICA`（文化/军团不变），城堡外观用 `VIKI_CASTLE_AGE3` 覆盖。
6. **项目键名必须写真实存在的键。** 不存在的键（如 `POLYNESIAN`、`CHIMU`、`IROQUOIS`、`TEUTONS`、`GANDHARA` 等）不得写进数据。
7. **注释必须写「按史」+ 依据。** 禁止「按当前势力保持」「武将裁决」这类理由。

## 二、判定顺序

1. 这个据点历史上是谁建的、谁住、谁修、实体建筑是什么？
2. 它代表哪个时段 / 政权？是本土政权、殖民城、十字军城、商站、军堡还是烽燧？
3. 在 66 分支里找**同建筑形态**的分支；没有就找最接近的大区代理。
4. 只改 `buildingStyle`；如果会带歪文化/军团，改用**城级城堡外观覆盖**。
5. **先按建筑风格安排武将 + 精锐**：武将文化、精锐番号必须和据点风格/历史同源。
6. **再看武将时代 + 建筑风格，安排军团**：从现有军团里选对应时代/文化的军团；不新建军团，不沿用旧势力遗留军团。
7. 注释写清：精确 / 代理 / 覆盖，三种状态必须区分。

## 三、缺分支时的处理

- **精确存在**：直接写对应键。
- **只有大区代理**：写现有最接近键，备注写「代理，不是精确」。
- **代理会带歪文化/军团**：保留原 `buildingStyle`，只加城级城堡外观覆盖。
- **禁止**：为了一个据点新增文化分支、重编文化/军团、把不存在的键写进数据。

## 六、容易再犯的错误（禁止）

1. **把「武将当前是谁」当建筑风格依据。** 错；先看据点本身。
2. **把不存在的键当已有键。** 例如 `POLYNESIAN`、`IROQUOIS`、`CHIMU`、`GUARANI`、`SIAMESE`、`YAN`、`DALI`、`GANDHARA`、`TEUTONS`、`SLAVS`、`ROMANS` 都不是 66 现有键。
3. **把旧键名当字面历史。**
   - `WEI` = 河朔，不是曹魏。
   - `KHITAN` = 河西（边墙要塞），不是辽式/契丹。
4. **只改 `buildingStyle` 把文化/军团带歪。** 先判断是否该用城堡外观覆盖。
5. **写「按当前势力保持」「按武将定」这类非历史理由。**
6. **为一个据点新增文化系统/军团/武将。** 一个据点不配一整套。

## 八、2026-10-19 补充：建筑风格 / 势力 / 武将分离 + 多层遗址仲裁

### 1. 三个字段分开判（库曼/俄罗斯/保加利亚分不清的根因）

- **`buildingStyle`**：只看据点当地、该建筑层的营造传统；**不看占领者、殖民者、驻将、当前势力、军团**。
- **`factionId`**：该建筑层对应的历史政权/部族（谁实际统治）。
- **武将 / 精锐 / 军团**：按 `factionId` + 时代匹配；**只有改了势力，才需要换武将/军团**。
- **禁止**：用地理大区（例如 `region: 'CUMAN'`）或当前势力倒推建筑风格。

### 2. 多层遗址仲裁（同一据点有多层历史时）

1. 有**城墙 / 宫殿 / 寺庙 / 民居等建筑遗存**的那一层 → 定为该据点的建筑风格。
2. 只有**毡帐 / 营地 / 无建筑**的游牧层 → 不占“城”的风格；只能另作城寨/营地。
3. 游牧层与定居城先后重叠 → **定居城按城判，游牧层另设城寨**；不得混成“库曼风格的俄国城”。

### 3. 库曼 / 俄罗斯 / 保加利亚 的硬口径

- **CUMAN（库曼）**：只用于库曼/钦察的**游牧营寨**；不得用于萨莱、喀山、萨莱楚克、萨拉托夫等定居城。
- **BULGARIANS（保加利亚）**：只用于**多瑙保加利亚**（索非亚、特尔诺沃、普雷斯拉夫）；伏尔加保加尔/喀山用 `CENTRAL_ASIA`。
- **俄罗斯定居城**：建筑风格 `SLAVIC`；势力/武将按时代配（例：1590 萨拉托夫 = 俄国边地，扎谢金，萨拉托夫骑）。
- **中亚绿洲 / 金帐城市**：建筑风格 `CENTRAL_ASIA`（撒马尔罕、布哈拉、萨莱、喀山、萨莱楚克等）。
- **战场只用在剧本里，独立于据点（`bf_*`）**；地图上不把战场做成营寨/stockade，也不按无人战场建军寨。
- **战场和据点一样有道路**（道路端点同样可接 `bf_*`）；迁移/新增/删除战场时必须一并处理道路端点，不能以“战场没有道路”为理由跳过。道路归属仍按血训归主人，AI 只报告或按授权处理。

## 九、据点 ≠ 只算城（2026-10-22 主人定）

> 🔴 **主人原话（2026-10-22 逐字照录）**：
> **「我们说的是据点，不是说只加城。草原上没城，聚集的地方就是据点。」**

1. **据点定义**：`CITIES_V2` 里的「据点」不等于有城墙的城 —— 草原/游牧的**毡帐营地、木栅营寨、聚落、聚集地**同样算据点（`type` 按体量用 `stockade` / `pass` / `small_city` 等）。
2. **判「某文化有没有据点」**：只看该 `buildingStyle` 名下有没有 `CITIES_V2` 条目，**不看是否有城墙、也不看名字里有没有「城」**。
3. **新增这类据点**：同样要「符合历史 + 真实地理 + >40km + 配史实武将/军团」，按一据点一整套处理（城条 + 道路 + 武将文化/时代/生卒/世纪/档案 + 势力编制）。
4. 例：瓦良格的**拉多加、白湖**以 `stockade`（营地层）落数据；匈人/库曼若以后补点，也只能补游牧营寨类据点，不得拿定居城冒充。
