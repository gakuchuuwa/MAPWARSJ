# 军团铁律 · 不许有幽灵军团

> 🔴 [2026-09-18 主人定]「把这个规则写下来，永远记住，不要再搞这种幽灵军团了。不要乱写保底机制。」
> 验收：`npm run legion:ghost-audit`（必须 0 处）

## 一、幽灵军团是什么

**幽灵军团 = 某处引用了一个军团名，但这个名字在三层真源表里查无此军。**

三层真源表（`getLegionCompositionByName()` 只认这三层，顺序固定）：

| 层 | 文件 | 当前支数 |
|---|---|---|
| 一级 · 母体 | `src/types/CultureFormations.ts` → `BASE_16_LEGION_NAME_BY_REGION` | 16 |
| 二级 · 文明 | `src/data/level2Civ59Legions.ts` → `LEVEL_2_CIV_59_LEGIONS` | 59 |
| 三级 · 自定义 | `src/data/level3CustomLegions.ts` → `LEVEL_3_LEGIONS` | 122 |

三层都查不到 → 返回 `null`。后果两边不一致：

- **军团编辑器**：`liveComp ?? getDefaultSlotsForMode(mode)` 兜底，凭空画出一支
  「近卫步兵 ×3 + 近卫步兵 ×3 + 弩兵 ×3」的 3+3+3 方阵，还带战力数字，
  看上去像一支真军团，但三级列表里点不开、找不到。
- **游戏里**：`applyLegionCultureComposition()` 静默回落到**据点文化区**的军团，
  打出来的是另一支部队。

**判据**：已登记的 197 支军团里，**没有任何一支**用 `square` 阵型，也没有任何一支的编制是
近卫 ×6 + 弩兵 ×3。所以在任何界面上看见 3+3+3 的「近卫步兵 ×6 + 弩兵 ×3」，
**它一定是幽灵，不是军团**。

## 二、军团是怎么选出来的（唯一链路）

```
势力 FACTION_COMPOSITIONS[factionId].legionName   ← 有番号军团就用它
  └─ 查不到 → 据点所属**文化区** CULTURE_LEGION_NAMES[region]
       └─ 再查不到 → 幽灵（禁止出现）
```

🔴 **不是按建筑风格选军团**。建筑风格（`resolveCityDeBuildingStyle`）只决定城池长什么样，
与军团编制无关。文化区现有 171 个，不是 78 个；军团 197 支，与建筑风格不是一一对应。

## 三、铁律

1. **写军团名之前先确认它已登记**。往 `FACTION_COMPOSITIONS` / `CULTURE_LEGION_NAMES`
   里写一个名字，必须在三层表里真实存在——要么用现成的，要么先去三层表登记。
2. **不许拿"顺手编个名字"当占位**。`古典时代东南亚军团` / `城堡时代东南亚军团` /
   `古典时代希伦军团` 这类名字全仓从来没有过，写上去就是幽灵。
3. **不许再加新的保底兜底**。查不到就应该在审计里报红、当场修数据，
   不是再写一层"猜一个默认编制"把问题盖住。`getDefaultSlotsForMode()` 只许留给
   编辑器**新建军团时的空白模板**，不许用来伪装成已有军团。
4. **改动前后各跑一次** `npm run legion:ghost-audit`，必须 0 处。

## 四、修复一处幽灵的两条合法路径

- **归拢**：把引用改成一支**已登记**、且史实上对得上的军团
  （例：`KHMER` 原挂查无此军的【城堡时代高棉军团】→ 改挂二级表里自己声明 `region=KHMER`
  的【封建时代吴哥军团】）。
- **登记**：确实需要这支军团，就在二级/三级表里正式落盘（编制按史实定，九格总和 = 9），
  再让引用指过去。

两条都不做而留着名字，就是幽灵。
