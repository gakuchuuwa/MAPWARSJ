# 14文化四维平衡 —— 完整分析报告

## 一、核心设计原则

**军团属性绑军团，据点属性绑城池，不随攻守方切换。**

| 属性 | 绑定对象 | 何时生效 |
|------|----------|----------|
| 军团攻 | 军团（legion） | 军团参与战斗时 |
| 军团速 | 军团（legion） | 军团行军时 |
| 据点兵 | 城池（city） | 据点季产驻军时 |
| 据点防 | 城池（city） | 城池驻军防守时 |

## 二、审议提案时发现并纠正的关键问题

### 问题：提案说"守城军团也吃据点防"

提案原文："守城的军团和驻军都吃防的系数"。

**这是错的。**

当前代码 `CultureCombat.ts` 的判断逻辑：
```
isGarrisonUnit(unit) → unit.unitType === 'city'
  → city → 取据点防（TIER_TABLE[1]）
  → legion → 取军团攻（TIER_TABLE[0]）
```

这个逻辑是对的。如果改成按"攻方/守方"分配，会出现悖论：一个巴蜀军团跑到中原守城，它到底吃巴蜀的据点防还是中原的据点防？按提案逻辑会乱。

**结论：不采纳。维持现有 entity-type 判断，不改 CultureCombat 核心逻辑。**
