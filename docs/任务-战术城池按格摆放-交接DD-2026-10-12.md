## 1. 背景：为什么要做

DE 的建筑严格按格子摆放：地面是等轴菱形格，建筑占整数格、互不重叠，城墙逐格相连。我们之前的城池用比例系数（`baseSize × 0.075`、纵向 ×0.58，圆环随机半径）排，**既不吸附格子、也不按占地格数排**，所以建筑互叠、压墙、城门与墙错位。大城已改成按格。

## 2. 格子的定义（唯一出处）

| 量 | 值 | 出处 |
|---|---|---|
| 一格（等轴菱形） | **96 × 48 px**（2:1） | `Scene13GroundLayerGL.ts` 的 `DE_TILE_W/H`、`TAC_TILE_W/H` |
| 地图 | 120 × 120 格；半幅 5712 × 2856 px（`TAC_MAP_HALF_W/H`） | 同上 |
| 格坐标 (i, j) → 屏幕 | `x = (i − j)·48`，`y = (i + j)·24` | 以城心为原点 |
| 格心 | **整数 (i, j)** | 约定：奇数边长的建筑中心在整数点，偶数边长的在半整数点 |

- `TerritorySystem.ts` 里另写了一份 `DE_ISO_TILE_W/H = 96/48`（不依赖 UI 层），**两处必须同改**。
- `src/systems/battlefield/spawnPlan.mjs` 的 `cellFromOffset` 里也写了 96/48（`.mjs` 纯模块不能 import），同样要同改。
- 注意：**地面贴图本身是 16:9 矩形格**（`Scene13GroundLayerGL.cellToScreen`：`x = (gx−N/2)·96`，`y = (gy−N/2)·48`），这是主人定的「保留长方形」，**不要改**。城池的格子是它上面叠的**等轴菱形格**，只管建筑与城墙。

## 4. 做法一：城墙按格逐件生成（`cityWallShared.ts: buildFortifiedRingOnGrid`）

先算账（主人要求「先计算：四个城门、四个城垛、八段城墙，每段多少个」）：

```
一边 = 角楼 + 墙 seg 格 + 城门 4 格 + 墙 seg 格 + 角楼
      => 角到角 L = 2·seg + 5 步
```

- **城门 4 格** = 门本体 2 格 + 两头门塔各 1 格（DAT：门本体 2×1 格；素材 `_meta.json` 的 `span_dx=72, span_dy=36` ＝ 门心到门塔心 1.5 格）。
- 城门要居中 ⇒ 两侧墙段**等长**。若每边墙圈是 26 步（原做法），扣掉门剩 21 格奇数，必然一边 10 一边 11、不对称。**所以 L 必须是 `2·seg + 5` 的奇数。**
- 大城：`seg = 11` ⇒ `L = 27`，全城 **4 门 + 4 角楼 + 8 段 × 11 = 88 件墙**（面板显示 `墙/门 92 件` ＝ 88 + 4 门；角楼 `POST` 另计 4）。
- 墙圈占 `i, j ∈ [a, a+L]`，`a = −⌊L/2⌋`；四个角楼落在 `(a,a)(a+L,a)(a+L,a+L)(a,a+L)`，都在格心上；门心在距起点 `seg + 2.5` 步（**半整数点，两格之间**）。
- 圈心在 `(a + L/2, a + L/2)`，屏幕 y 偏 `(2a + L)·24`（L 奇数时偏半格）——地面铺装与容器尺寸要用它居中。

**四条边的朝向（不镜像，关键）：**

| 边 | 走向 | 墙段/城门素材 |
|---|---|---|
| 左上边（西角 → 北角） | ↗ | NE |
| 右上边（北角 → 东角） | ↘ | SE |
| 右下边（东角 → 南角） | ↙（与 ↗ 同一走向） | NE |
| 左下边（南角 → 西角） | ↖（与 ↘ 同一走向） | SE |

🔴 **绝对不许镜像。** 旧做法是「东北向素材 `scaleX(-1)` 顶替东南向」，外加 50% 概率整圈再翻转（`rnd() < 0.5`）。等轴素材的侧面与阴影按单一朝向绘制，镜像后门塔接墙处错位，**露出门塔自带的一块平墙面，看着像缺一个城垛**——主人发现「只有巴黎缺一块」就是因为巴黎刚好被随机翻转。DE 给 16 种风格各画了 NE / SE 两套墙段与城门（`{STYLE}_WALL_FORTIFIED_NE/SE`、`{STYLE}_GATE_FORTIFIED_NE/SE`，各 `_meta.json` 的 anchor 略有不同），用对的那套即可。

**每件的对位**（`TerritorySystem.ts: buildDeBigCityGridHtml` 里的 `ring.pieces.forEach`）：
- 宽度取 `DE_SPRITE_BOX_W[素材目录名]`（素材原生框宽，不乘任何系数）；
- 对位点取 `DE_SPRITE_ANCHOR[素材目录名] = [anchor_x, anchor_y, box_h]`，折成 `pctX = anchor_x / box_w × 100`、`pctY = anchor_y / box_h × 100`；
- `transform: translate(calc(-pctX% + 件.x px), calc(-pctY% + 件.y px))`，`left:50%; top:50%`，**无 scaleX**；
- `z-index = 500 + 件.y`。

> 锚点的语义：DE 里素材锚点 = 该建筑占地**中心**落在地面上的那一点。所以只要「锚点对齐格心 / 占地中心」，素材就对齐了格子。不要再用画框中心定位（城堡会差 120 多像素）。

## 5. 做法二：城内建筑按格摆放（`TerritorySystem.ts: buildDeBigCityGridHtml`）

1. **3 × 3 个位，位距 `PITCH = 5` 格**（≥ 最大占地 4 + 1 格路）。个位中心 `(ci, cj) = (5·c, 5·r)`，`r, c ∈ {−1, 0, 1}`；按屏幕 y 升序（与战略版同序，保证选建筑的顺序一致）。
2. **吸附到整格**：占地边长 `s`，占地左上格 `a0 = round(c0 − (s−1)/2)`，占地中心 `t = a0 + (s−1)/2`（i、j 各算一次）。
3. **不重叠的证明**：每个方向上三个个位的格范围互不相交（−1 个位 ≤ −3、0 个位 −1…2、+1 个位 ≥ 4），所以任意两栋 i 范围或 j 范围必有一个不相交。
4. 屏幕位置 `px = (ti − tj)·48`、`py = (ti + tj)·24`，用 `placeBuilding(dir, src, boxW, s, ci, cj, flip)` 摆；建筑可随机镜像（`deHashString(cityId + '|bldg|' + b + '|' + i) & 1`），**镜像时 `pctX` 取 `100 − pctX0`**（锚点跟着镜像，否则建筑会横移）。
5. 城堡（`centerCastle`）占中心个位 4×4，用 `native.castleW` 与素材锚点。
6. 地面：`featheredPolygonGroundDiv`，菱形顶点 = 墙圈四角 `[0, ringCy−rY] [rX, ringCy] [0, ringCy+rY] [−rX, ringCy]`，`rX = L·48`、`rY = L·24`。容器 `W = 2rX + 400`、`H = 2(rY + |ringCy|) + 600`（战术侧的 `deCity.width/height` 取自这里，攻方出生距离等随之放大——已确认可接受）。
