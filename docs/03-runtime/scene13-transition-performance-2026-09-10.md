# 战略／战术切换性能修复（2026-09-10）

## 已定位的问题

4K 完整游戏测试中，战场画布下方的战略地图仍参加浏览器绘制和合成。主线程 JavaScript 火焰图无法反映全部等待：Chrome trace 的 GPU 栅格化、提交和合成占据大量时间。

同页、同一无水战斗的对照实验：每组 5 秒，原状态 14 帧；仅将地图 visibility 设为 hidden 后 253 帧；恢复后 11 帧。数据：`scratch/transition-ab-phases.jsonl`；浏览器跟踪：`scratch/transition-trace.json`。这是测试环境实测，不能当成所有设备的帧率保证。

## 实现

- Scene13 战场底图确实就绪、已绘制后，暂时隐藏被覆盖的地图；保持 DOM 尺寸和镜头状态，退出恢复原有 visibility 值和优先级。地形加载失败时继续显示原地图，不能黑屏。
- 素材准备期间先显示就绪的战场画面；部队部署、战斗时钟仍等必需素材到齐才启动。
- 地图隐藏期间，GlobalUnitRenderer 和 VegetationLayer 跳过绘制；返回时补绘，时间戳不累积整场时差。
- 兵种势力色在 SpriteTintWorker 中处理，共用 MaskTintPixels 算法，返回可直接 drawImage 的 ImageBitmap，省掉 PNG 编码／再解码。保留异常回退。
- 每个兵种只为实际出场方染色；双方使用同兵种时，各自准备正确的颜色。动作可用性按士兵所属方检查。
- 行走、攻击的下载与染色优先；后用动作在必需素材就绪后加载。在途去重支持将排队任务提升为优先任务。
- 地形缓存最多 8 张图，重复进入／调整窗口复用已解码图；过期图片回调不能覆盖新战场的地形。

## 验证

- `npx tsc --noEmit --pretty false`，不运行构建。
- `node scratch/test_tint_async.mjs`：原算法对照、真实素材像素一致、Worker 与回退、同步读取安全、缓存与并发去重。
- `node scratch/test_tint_priority.mjs`：开场任务优先，提升已有任务不重复处理，结束后队列释放。
- `node scratch/test_scene13_transition_regression.mjs`：单方／双方素材、重复加载、地图隐藏／恢复、残局保留、缺地形保护。
- `node scratch/test_terrain_cache.mjs`：复用地形图片、像素一致、失败可重试、过期回调不覆盖当前地形。
- `node scratch/verify_transition_final.mjs`：完整游戏 3840×2160，首次攻城、重复攻城、野战、带水攻城；检查素材完整、攻城器械仍为 9 个、退出恢复。最新结果在 `scratch/transition-final-results.json`。

首次载入仍包含网络读取、图片解码与染色等待；它和开战后的持续顿挫应分开衡量。性能测试使用独立浏览器并屏蔽 Vite HMR，以免其它任务保存文件重载页面污染结果。测试场景直接调用游戏现有场景入口，不改战斗规则或存档。

## 最后一轮完整游戏采样

浏览器启动后等待后台初始化 45 秒，再使用全新兵种染色缓存进入第一场。四场连续执行，4K 分辨率；稳定帧率统计就绪后最后 5 秒。

| 场景 | 必需素材就绪 | 战场接管画面 | 稳定 FPS |
| --- | ---: | ---: | ---: |
| 首次无水攻城 | 4.13 秒 | 1.37 秒 | 59.4 |
| 重复无水攻城 | 0.18 秒 | 0.18 秒 | 60.0 |
| 无水野战 | 0.16 秒 | 0.56 秒 | 60.0 |
| 带水攻城 | 0.21 秒 | 1.56 秒 | 35.8 |

四场素材缺失为 0、等待计数归零、没有素材超时；攻城器械均为 9 个，退出均恢复地图及原暂停状态。首次加载受后台初始化、磁盘/网络读取影响，不承诺固定秒数。带水大场景仍比无水场景吃显卡，本次约 36 FPS，不宣称所有场景均达 60 FPS。
