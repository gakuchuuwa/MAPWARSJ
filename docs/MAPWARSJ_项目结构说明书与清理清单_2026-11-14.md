## 一、一分钟看懂你的项目是怎么跑起来的

这个项目之所以看起来文件繁杂，是因为历次 AI 协作把**「游戏本体 + 9 个网页可视化编辑器 + 自动备份/直播后台 + 史料文档 + 一次性试验垃圾」**全部混放在了同一个根目录下。剥离掉临时文件后，真正的工程骨架非常清晰，只有 **5 大模块**：

1. **游戏主程序（线上与本地核心）**
   - 入口页面：`index.html` + `style.css` → 加载 `src/main.ts`。
   - 核心源码：`src/` 下共 28 个职责分明的业务子目录（`map` 战略底图、`world` 世界与据点、`roads` 陆路、`sea` 海路、`legion` 军团、`combat` 战斗、`events`/`story` 编年史事件与播报、`live` 直播交互等）。
   - 静态资源：`public/`（线上实际读取立绘 `assets/`、城池 `cities/`、建筑 `SUCAI_BUILDING/`、兵模 `SUCAI/`、瘦身特效 `SUCAI_FX/`、压缩音效 `sfx/*.aud`、河流矢量 `data/ne_10m_rivers_lake_centerlines.geojson`）。
2. **本地开发服「五合一」后台（运行 `npm run dev` 或双击 `start_server.bat` 时同时启动）**
   - ① `vite`：启动游戏前端与 `vite.config.ts` 内置的本地文件保存接口（`/api/save-city`、`/api/save-roads` 等）；
   - ② `node auto_backup.cjs`：每小时自动做一次 Git 提交备份，每 3 天自动推送到 Vercel 线上部署；
   - ③ `tools/PortraitMatting/app.py`：本地 Python 立绘自动抠图服务；
   - ④ `tools/siteMapWatcher.mjs`：站点与资源变动监听服务；
   - ⑤ `tools/youtube-live/server.mjs`：YouTube 直播弹幕指令与观众积分后台（密钥与观众账本存在 `.local/`）。
3. **8 个本地网页可视化编辑器（只在你本地改数据时用，线上 Vercel 不打包）**
   - 根目录下的 `legion-editor.html`（军团编辑器）、`skill-editor.html`（武将技编辑器）、`battlefield-editor.html`（战场编辑器）、`portrait-tuner.html`（立绘调校器）、`batch-manager.html`（批量导入管理）、`six-slot.html`（武将技六槽管理）、`de-wiki.html`（帝国时代2 DE 兵种百科）、`quick-battle.html`（快速战术测试），外加 `public/stockade-wall-editor.html`（城寨围栏编辑器）与 `public/sfx-lab.html`（音效实验室）。
4. **自动化校验与无头推演标尺（`scripts/` + `tools/` + `scratch/` 部分脚本）**
   - 用于检查据点、年代、军团编制合规性与模拟推演战力平衡（如 `scripts/guard.mjs`、`scripts/sim/headless.ts`）。
5. **策划总则与史实资料仓（`AGENTS.md` + `docs/` + `史料/`）**
   - `AGENTS.md` 是每次 AI 会话自动读取的最高规则；`剧本模式/` 存放 2526 场引擎全库、主支线读本与全部 GG 任务交付（旧目录 `docs/战争编年史（纯史实重写）/` 已于 11-16 删除）；`史料/` 存放纯本地参考史书。

## 二、四大「防误删红线陷阱」（必看！名字像临时文件，删了必出故障）

在动手清理前，以下 **4 处文件/目录** 名字看似临时缓存或备份，但实际上被代码硬编码依赖，**绝对不能整包删除**：

### 陷阱 1：`scratch/` 目录 **绝对不能整目录删除**
- **运行时硬依赖（删了线上打包与游戏直接崩溃）**：`src` 中的势力分级逻辑（`factionTierClassify.ts`）在编译和运行时直接读取 `scratch/` 下的 **4 份 JSON 数据**：
  - `scratch/ethnic_homeland_audit.json`
  - `scratch/regime_capital_audit.json`
  - `scratch/family_state_audit.json`
  - `scratch/county_seat_audit.json`
- **开发服与命令硬依赖**：`vite.config.ts` 会直接调用 `scratch/build_portrait_canonical.mjs`；`package.json` 里有 **40 多条 `npm run` 检查命令** 指向 `scratch/audit_*.mts` / `.mjs`；`.gitignore` 还专门保护了 6 个核心跑分验证脚本（`verify_leader_hunt.mts` 等）。
- **正确做法**：保留 `scratch/` 目录及上述 JSON/审计脚本，**只清理里面超过 102 MB 的 `.jsonl` 运行日志和带 `_` 前缀/日期后缀的一次性导出表**（详见第四节）。

### 陷阱 2：根目录的 `auto_backup.cjs` 与 `.auto_deploy_state.json` **正在服役**
- `package.json` 的 `npm run dev` 命令写死了并发执行 `node auto_backup.cjs`。一旦删掉它，你本地启动开发服会直接报错退出。`.auto_deploy_state.json` 记录上次自动部署到 Vercel 的时间，也应一并保留。

### 陷阱 3：根目录的 `.local/` 隐藏文件夹 **存有直播核心资产**
- 内含本机 YouTube 直播密钥、断线恢复游标、付款记录与观众积分账本。因为涉及密钥隐私，`.gitignore` 和 `.vercelignore` 都排除了它（云端 Git 仓库里没有备份），**一旦在本地误删将无法恢复**。

### 陷阱 4：`public/data/ne_10m_rivers_lake_centerlines.geojson` **是全图河流唯一数据源**
- `public/data/` 下的其他 `.geojson`（如 47 MB 的 `roads_filtered.geojson`）只是道路编辑器的本地底稿，唯独这份 `ne_10m_rivers_lake_centerlines.geojson` 被 `GameMap.ts` 在游戏启动时实时加载。删掉它会导致整张地图所有河流消失。
