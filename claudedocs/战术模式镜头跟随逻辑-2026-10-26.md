# 战术模式镜头跟随逻辑（2026-10-26 现状，供复查）

代码全部在 `src/ui/Scene13WarLayer.ts`，另有 `src/player/PlayerScene13Control.ts` 的缩放滑条。行号以 2026-10-26 当前文件为准。

## 一、主人要求（2026-10-26 原话整理）

优先级：**交战的玩家 > 交战的主将队 > 交战的士兵 > 移动的玩家 > 移动的主将队 > 移动的士兵**。
玩家阵亡后跟交战的主将队；没有就跟交战的士兵；期间玩家一交战就切回玩家；无人交战才跟移动的玩家 / 主将 / 士兵。

## 二、镜头状态量

| 字段 | 含义 |
|---|---|
| `tacticalZoom` | 缩放倍率（滚轮 / 滑条改） |
| `tacticalPanX/Y` | 平移，**屏幕像素**，相对屏幕中心。画面中心对应的世界点 = `worldCX - panX/zoom`, `worldCY - panY/zoom` |
| `userInteractingTimer` | 玩家手动操作后的「不自动跟随」倒计时，秒 |
| `skillCamTimer` / `skillCamX/Y` | 「看计策落点」倒计时与落点 |
| `camWatchMan` | 六档里第 2/3/5/6 档当前盯着的那个兵（粘住用） |

## 三、每帧流程（`step()` 内，约 7929–7982 行）

前提：`step()` 第一行 `if (this.over) return;`，所以**战斗结束后（残局待命期）镜头不再自动动**。块本身只在 `useGroundGL && canvas`（新战术模式）时跑。

```
if userInteractingTimer > 0:           # 手动操作后 9 秒内
    userInteractingTimer -= dt          # 完全不自动跟随
else:
    if 玩家活着且 foe≠null: skillCamTimer = 0   # 玩家交战立即取消计策镜头（10-26 修）
    if skillCamTimer > 0:               # ① 看计策落点 9 秒
        skillCamTimer -= dt
        目标 = (skillCamX, skillCamY)
    elif heroMan 存在（本场有乱入者，含阵亡复活中）:
        目标 = pickCamTarget(heroMan)   # ② 六档，见第四节；返回 null ⇒ 本帧不动
    elif 攻城战 或 有 deCity:           # ③ 无乱入者的攻城战：锁城池中心
        目标 = (worldCX, worldCY)
    else:                               # ④ 无乱入者的野战
        目标 = 双方所有 foe≠null 的活兵重心；没有就全体活兵重心
    有目标时:
        desiredPan = (worldC - 目标) * zoom
        pan += (desiredPan - pan) * min(1, 1.5*dt)   # 指数平滑，约 0.67 秒走完 63%
        clampTacticalPan()                            # 不许露出地图边
```

## 四、六档选择 `pickCamTarget(hero)`（约 1397–1433 行）

- **只看玩家这一方**（`m.f === hero.f`），排除攻城武器（`siegeW`）和死人（`hp<=0`）。
- 「交战」= `m.foe != null`；「移动」= 活着且 `foe == null`。
- 「主将队」= 该兵所在出兵口 `spawns[m.lane].commander === true`（每方第 10 口，`idx >= 9`，2085 行）。玩家自带精锐口 `commander:false`，算「士兵」。
- 档位：0 交战玩家 / 1 交战主将队 / 2 交战士兵 / 3 移动玩家 / 4 移动主将队 / 5 移动士兵；6 = 本方全灭。

```
bestTier = 玩家活着 ? (玩家 foe ? 0 : 3) : 6
遍历本方所有非玩家活兵，取最小档 → bestTier
bestTier 为 6 → 全部重置，返回 null（镜头原地不动）

# 换档缓冲（10-26 修）：camTier = 已认定的档
lost = camTier 未定 / camTier 是玩家档但玩家死了 / camTier 是兵档但盯的兵死了
if bestTier == camTier:        清掉待切
elif lost 或 bestTier == 0:    camTier = bestTier（立即切：玩家交战、跟的人没了）
else:                          bestTier 连续保持 CAM_SWITCH_HOLD(1.5 秒) 才 camTier = bestTier

camTier 为 0 或 3 → 跟玩家
否则:
    camWatchMan 活着且在 camTier → 继续跟
    camWatchMan 活着但掉出 camTier（丢目标）不满 1.5 秒 → 仍跟他
    否则从 camTier 里挑离「当前画面中心」最近的；camTier 已空 → 直接落到 bestTier 再挑
```

注意：「待切」期间若 bestTier 又变成别的档，计时从 0 重来。

## 五、`foe` 到底是什么（「交战」的判据，约 6926–7010 行）

- `foe` 是**索敌锁定的目标**，不是「已经贴身在打」。半径 `SIGHT = max(兵种视野≈160, 远程射程×1.15+40)`；城门未破时第二波起的守军 `SIGHT = REACH`（只认够得着的）。
- 目标可以是敌兵，也可以是**建筑**（城门 / 城墙 / 箭塔，`'sprite' in foe`）。所以攻方兵在砍墙、攻城时也算「交战」。
- 每 0.2 秒重搜一次；丢目标有 1.44 倍距离迟滞（`canKeepTarget`）。
- 部署期（`deployT > 0`）大家不动，基本都是 `foe == null`。

## 七、复查发现的问题

> 2026-10-26 已修：第 1、2、4、5 条（见上文流程）。第 3、6、7 条未动。

1. **计策镜头压过「玩家交战」**：`skillCamTimer` 在六档之前判断，9 秒内玩家开始交战也不切回玩家，与「期间如果玩家战斗，就切回玩家」冲突。修法：玩家 `foe` 非空时清零 `skillCamTimer`。
2. **六档切换没有迟滞**：只要有一个更高档的兵出现（例如一名主将队兵视野里锁到一个敌人 0.2 秒），镜头就立刻飞过去；他丢目标又飞回。开战前后、交战边缘最明显，看起来像镜头来回甩。可加「新档持续 ≥ N 秒才切」或「切走后至少停留 N 秒」，但玩家交战（第 0 档）应保持立即切回。
3. **「交战」判据偏宽**：`foe` 在视野半径内锁到目标就算，包括还在走过去的兵和砍墙的兵。如果主人说的「战斗」是「真的在出手」，判据应改成 `foe` 且在 `REACH` 内（或 `fightT > 0`）。
4. **缩放时画面中心会漂**：滚轮 / 滑条只改 `tacticalZoom` 不改 pan，而 pan 是屏幕像素 ⇒ 画面中心世界点 `worldC - pan/zoom` 随缩放变化；之后 9 秒又不自动跟随，玩家会看到「一缩放镜头就偏走」。修法：缩放时按比例缩放 pan（`pan *= newZoom/oldZoom`）保持中心不动。
5. **在战场上单击一下也冻结跟随 9 秒**：`onDown` 按下即设 `userInteractingTimer = 9`，不区分点击和拖拽。修法：真的移动了鼠标才计。
6. **主将队 / 士兵只算本方**：敌方主将队、敌方士兵永远不会被跟。主人原话没说哪一方，按「玩家这边」理解，需确认。
7. **有乱入者的攻城战不再锁城池中心**：第 ③ 支只在没有乱入者时走；有玩家时全由六档决定。这是本次改动的预期结果，列出供确认。
