## 四、槽位（Slot）记录：**60 字节**

日志：`Slot[%2d]: mOffset=(%f, %f), Depth=%d, DesCat=%s`
反编译实测（`FUN_1410d9e34` 写槽）：步长 **0x3C = 60 字节**，字段偏移实测如下。

| 偏移 | 字段 | 实测来源 |
|---|---|---|
| +0x00 | unit id（初始 `0xFFFFFFFF` = 空槽） | `*(u32*)(slot) = -1` |
| +0x04/+0x08 | **mOffset(x, z)**（从全局表 `0x144363230`/`0x144363238` 取） | 写槽代码 |
| +0x1c | 一个 id（`func_140d6acc0`→`func_1416041f0` 得到） | 写槽代码 |
| +0x20/+0x24/+0x28 | 状态/计时相关（初始 0；`+0x24` 在匹配器里与阈值比较） | 写槽 + 匹配器 |
| +0x2c | **DesCat / 分类**（6 例 switch 0..5） | 写槽代码 |
| +0x30 | `0xFFFFFFFF` | 写槽代码 |
| +0x34 | `1` | 写槽代码 |
| — | **Depth**（前后排深度） | 日志串里有，静态偏移未逐一钉死 |

## 五、排布算法（核心，`FUN_1410da2d0`，3932 B）

对**每个分类**（循环 `uVar24 = 0..5`）各算一次，算法如下：

```
count = 该分类的单位数            // 日志: Category '%s' has %d units
① 选 COLUMN 还是 LINE：
   COLUMN（列）：numLines = ceil(count / numColumns)
       收紧条件：while (numColumns > numLines / 2) numColumns--     // 列不能比行宽
   LINE（横）：  numColumns = ceil(count / numLines)
       收紧条件：while (numLines > numColumns / 2) numLines--        // 行不能比列高
   （调用方可以指定 numColumns；指定 -1 时用 RNG 随机一个列数）
② lineWidth = numColumns × 该单位的间距      // fVar30 = *(float*)(unit+6)
   日志: COLUMN/LINE, numColumns=%d, numLines=%d, lineWidth=%f
③ 记录“最宽的一类”：widest = max(lineWidth)
④ 拿最宽的那一类重算所有分类的列/行（日志:
   "We have a widestLineIndex of %d (%s), redoing column and line sizings"
   → "Category '%s' is the widest line" → "REDONE numColumns=%d, numLines=%d, lineWidth=%f")
   ⇒ 效果：所有分类的正面宽度对齐，阵型看起来是一个整块
⑤ 把每槽的 mOffset 写进 60 字节槽记录（带上 Depth 与 DesCat）
```

**关键点（和我们的做法根本不同）**：
- **列/行数不是查表，是按人数与单位间距现算**，还带"长宽比约束"（列 ≤ 行/2 或 行 ≤ 列/2）；
- **有一个"最宽线回算"的第二步** —— 先各自排，再统一正面宽度重排一次；
- **每个单位参与计算的是它自己的间距**（`unit+6` 的 float），不是全局常数。

## 六、槽位 ↔ 单位 匹配（`FUN_1410d7230`，514 B）

日志：`UnitID[%2d]=%d (%s, ID=%d), Speed=%f, UnitRadius=%f`

反编译实测逻辑：

```
遍历该组所有单位：
   cat = 取该单位的分类（FUN_1410d95f0）
   若要求分类 != -1 且 cat != 要求分类 → 跳过          // 槽位只收同类
   若在排除名单里（另一个列表，按 slot+0x24 比阈值）→ 跳过
   取该单位位置（虚函数 +0x568），算与槽位 mOffset 的距离
   if (距离 < 当前最优) { 记下这个单位 }               // 取最近
⇒ 结果：每个槽位挑“同类 + 最近”的单位
```

## 八、与我们的差距（结论）

| | DE | 我们（现状） |
|---|---|---|
| 阵型来源 | **9 种引擎阵型**（Horde/Column/Line/Phalanx/Box/User Defined/Plan/Staggered/Flank） | 七种中国古典阵（方/雁行/鱼鳞/鹤翼/锥形…），tier 表 |
| 分组依据 | **按 6 个战斗分类**（Attacking Rams/Mobile/Body/Ranged/Long Range/Protected） | 按**格位**（前/中/后 × 9 slot） |
| 排布 | **按人数与单位间距现算** 列/行，并做「最宽线回算」统一正面 | 固定 9 格位坐标 |
| 槽位记录 | 60 字节／槽（mOffset / Depth / DesCat / 状态机） | 无（无槽位状态机） |
| 单位↔槽 | 同类 + **最近**（用速度/半径） | 编制表写死 |
| 接敌入口 | 单位**上报** `EnemySighted`/`UnderAttack` | 组/军团按半径扫（`HUNT_ENEMY_LEGION_RADIUS`） |
| Horde | **单独下令路径**（horde-style） | 无 |

**⇒ 「行军阵型模仿 DE」要补的三层，按依赖顺序：**
1. **分类层**（6 类）＋ **槽位记录**（60 字节那套字段）；
2. **排布层**：COLUMN/LINE 现算 + 最宽线回算 + 每单位间距（本篇已给出算法与地址）；
3. **下令/上报层**：`commandHorde` 与 `EnemySighted/UnderAttack` 上报链（要和寻敌（③）、攻城（④）接起来）。
