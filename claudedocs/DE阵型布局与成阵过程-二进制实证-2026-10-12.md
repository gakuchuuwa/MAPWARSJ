## ② 分类与阵型枚举（复核第一刀，全部对上）

### 2.1 分类枚举：6 个，**索引即引擎次序**（这是本题「分类相对顺序」的答案）

`0x1410DCF40` 是 `category → 名字串` 的 switch（`cmp edx,5; ja`，跳表 `0x1410DCF9C`）：

| 索引 | 名字串 | 串 VA | 依据 |
|---|---|---|---|
| 0 | `Attacking Rams` | `0x14408CB88` | `0x1410DCF9C` case0 → `lea rax,[rip+0x2FAFC26]` |
| 1 | `Mobile` | `0x14408CB98` | case1 |
| 2 | `Body` | `0x14408CBA0` | case2 |
| 3 | `Ranged` | `0x14408CBA8` | case3 |
| 4 | `Long Range` | `0x14408CBB0` | case4 |
| 5 | `Protected` | `0x14408CBC0` | case5 |
| 其它 | `Unknown` | `0x14408CBD0` | `ja` 分支 |

> **「分类之间的相对顺序由引擎索引 0..5 决定」＝ 已证实。**
> 依据：主排布函数的**外层循环就是 `for cat = 0..5`**，且每一轮去组的分类链表里找 `listNode[+0x10] == cat` 的记录：
> `0x1410DA3D0 cmp [rsi+0x10],r12d` / `0x1410DA69A inc r12d` / `0x1410DA6A1 cmp r12d,6` / `0x1410DA6A9 jl 0x1410da3c0`。
> 也就是说 **0..5 的先后＝分类在纵深上的先后**（除非"最宽线回算"改写各自的列/行；见 §3.3）。
> ⚠️ 但**语义上的前后**由谁定（是"Rams 在最前"还是"最前=索引 0"）本次**未找到**直接证据 —— 主函数只是按索引顺序推进 `depth` 累加器。**推断**：索引小的排在前（纵深小）。依据：`xmm7`（累加纵深）从 0 起、按 0→5 递增，且 `+0x2C`（总纵深）单调增。**未证实**。

## ③ 排布算法（`FUN_1410DA2D0`）逐段

### 3.1 入口与参数（**实测**，含调用点）

唯一调用点 `0x14110D443`，参数实测：

| 参数 | 寄存器/栈 | 调用点实际值 | 依据 |
|---|---|---|---|
| `param_1` = `int*` 组对象 | `rcx` | `rdi`（group） | `0x14110D33D`（另一路径）/`0x14110D43B` |
| `param_2` = `longlong` 组 | `rdx` | `rdi` | `0x14110D43B mov rdx,rdi` |
| **`param_3` = 指定的列数** | `r8d` | **`0xFFFFFFFF`（= -1）** | `0x14110D431 mov r8d,0xffffffff` |
| `param_4` = **阵型类型** | `r9d` | **`2`（Line）** | `0x14110D42B mov r9d,2` |
| `param_5` = 出参结构 | `[rsp+0x20]` | `&[rbp-0x10]` | `0x14110D437 lea rax,[rbp-0x10]` |
| **`param_6` = 双倍步进(Flank)** | `[rsp+0x28]` | **`0`** | `0x14110D427 mov [rsp+0x28],eax`（eax=0） |
| **`param_7` = 偏斜(bias)开关** | `[rsp+0x30]` | **`1`** | `0x14110D41F mov [rsp+0x30],1` |
| **`param_8` = 阵型类型（同 param_4）** | `[rbp+0x170]` | 由调用点写入 r9d=2 | `0x1410DA405 cmp [rbp+0x170],1` |

> 栈参换算已实测：`rbp = 入口 rsp - 0x138`、`sub rsp,0x1F8`，故
> `[rsp+0x28]→[rbp+0x160]=param_6`、`[rsp+0x30]→[rbp+0x168]=param_7`、`[rsp+0x20]→[rbp+0x170]=param_8`。
> 依据：`0x1410DA2DF lea rbp,[rax-0x138]`、`0x1410DA2E6 sub rsp,0x1F8`。

> 🔴 **重大实测：`param_3`（列数）与 `param_4`（阵型类型）在函数体内根本没被使用。**
> 全函数 3933 字节里，`r8d` 只出现在 `0x1410DA330`（序言存参）、`0x1410DAC26`/`0x1410DB04B`/`0x1410DB0C5`（三处当 0 清临时变量），
> `r9d` 只在 `0x1410DA370 test r9d,r9d` 的入口守卫；**既没有 `cmp r8d,-1`、也没有以 `r9d` 为索引的跳表**。
> ⇒ **调用方给的"阵型类型"和"列数"对本次布局不生效**；实际形状完全由 **(RNG 摇出的行数) + 单位数 + 各分类 step** 决定。
> 依据：全函数反汇编扫描（`_da_main.txt`，1063 条指令）；入口守卫 `0x1410DA36A test r8d,r8d / 0x1410DA370 test r9d,r9d`。
> ⚠️ **推断**：阵型类型的区分可能在**其他函数**里（`0x1410D9CC0`/`0x1410DBBD0`/`0x1410D9E34` 等早期分支）先做完，
> 到了这个函数只剩"排布"一件事。**待确认**（列入 §⑦）。

**已证实**：`param_3 = -1` ⇒ 走 §3.2 的 **(B) LINE 分支**，即"行数由随机数决定、列数倒推"。
其余调用路径（`0x14110D2A4` 那条，`r9d=1`、`r8d=<柱状比例>`）走 **COLUMN 分支**。

### 3.2 第一步：每个分类各自算 列数 / 行数 / lineWidth

> 🔴 **先立两个栈数组的名字（全篇统一，避免 Ghidra 伪代码的错名误导）**：
> 序言 `push rbp..r15`（8×8=0x40）+ `lea rbp,[rax-0x138]` + `sub rsp,0x1F8` ⇒ **`rsp = rbp - 0x178`**。
>
> | 本报告用名 | 指令级地址 | Ghidra 伪代码里的错名 | 含义（本次钉死） |
> |---|---|---|---|
> | **`colCnt[cat]`** | `[rsp + cat*4 + 0x68]` = `rbp + cat*4 - 0x110` | `auStack_1d0[cat]`（**错名**） | **numColumns**（列数 = 正面宽） |
> | **`lineCnt[cat]`** | `[rbp + cat*4 - 0x78]` | `auStack_1b0[cat]`（**错名**） | **numLines**（行数 = 纵深方向） |
>
> **依据**：三处 `numColumns` 都写进 `[rsp+…+0x68]`：`0x1410DA470`、`0x1410DA5D6`、`0x1410DA7C4`；
> 三处 `numLines` 都写进 `[rbp+…-0x78]`：`0x1410DA489`、`0x1410DA5C6`、`0x1410DA7B8`。
> 且写槽循环的行上界取自 `[rbp+r15-0x78]`（`0x1410DAC2B`），槽数取自 `[rsp+r15+0x68]`（`0x1410DAC38`）。
> **Ghidra 给这两个数组起的名字恰好是反的**，读旧伪代码 `group_form.txt` 的人务必以本表为准。

外层 `for cat = 0..5`（`0x1410DA3C0`–`0x1410DA6A9`）。对每个分类记录 `rsi`：

* `count = rsi[+0x14]`（单位数，`0x1410DA42B mov r15d,[rax]`，rax=rsi+0x14）
* `step  = rsi[+0x30]`（本分类的步距，见 §3.6）

**(A) `param_3 >= 0`（调用方给了列数）→ 代码走到 `0x1410DA532`，打印的是 `COLUMN` 串** — `0x1410DA44D` 起：

```

if (colCnt[cat] < 1) colCnt[cat] = 1            ; 0x1410DA476 jg / 0x1410DA478
lineCnt[cat] = ceil(count / colCnt[cat])        ; 0x1410DA484 idiv r14d → 0x1410DA489 mov [rbp+rbx-0x78]; +0x1410DA491 inc
while (lineCnt[cat] <= colCnt[cat]/2) break;    ; 0x1410DA497..0x1410DA4A1  cmp r14d,eax / jle 0x1410DA4F4

        if (colCnt[cat] < 1) { colCnt=1; lineCnt=count; break; }   ; 0x1410DA4E4
        lineCnt[cat] = ceil(count/colCnt[cat]);
        if (lineCnt[cat] > colCnt[cat]/2) break;                   ; 0x1410DA4DD cmp r8d,eax / jg 0x1410DA4B0

打印 0x1432A0570 "COLUMN, numColumns=%d, numLines=%d, lineWidth=%f"   ; 0x1410DA532；实参 [rsp+0x38]=numColumns, [rsp+0x40]=numLines
```

**(B) `param_3 == -1`（调用方没给）→ 代码走到 `0x1410DA641`，打印的是 `LINE` 串** — `0x1410DA55D` 起：

```

                                                ; → 0x1410DA580 mov [rbp+rbx-0x78]

while (colCnt[cat] <= lineCnt[cat]/2) break;    ; 0x1410DA5A7..0x1410DA5B1 cmp r14d,eax / jle 0x1410DA604

        if (lineCnt[cat] < 1) { lineCnt=1; colCnt=count; break; }   ; 0x1410DA5F4
        colCnt[cat] = ceil(count/lineCnt[cat]);                     ; 0x1410DA5D6 / 0x1410DA5E0
        if (colCnt[cat] > lineCnt[cat]/2) break;                    ; 0x1410DA5ED cmp r8d,eax / jg 0x1410DA5C0

打印 0x1432A05D0 "LINE, numColumns=%d, numLines=%d, lineWidth=%f"     ; 0x1410DA641；实参 [rsp+0x38]=edi=colCnt, [rsp+0x40]=r14d=lineCnt
```

> ⚠️ 注意 (B) 分支里 `lineWidth` 用的是 **`edi` = `colCnt`**（`0x1410DA604 movd xmm0,edi`），
> 而 `edi` 在循环中被反复重置为"`count / lineCnt` 的上取整"= `colCnt`。**两分支的 lineWidth 都是"列数 × step"。**

> 🔴 **标签 vs 语义（实测，必须记牢）**：
> | 分支 | 指定项 | 收紧约束（代码里真正的） | 打印的串 | lineWidth |
> |---|---|---|---|---|
> | (A) `param_3 >= 0` | `numColumns = count/param_3` | `numLines <= numColumns/2` ⇒ 保证 **numColumns ≤ 2·numLines** | `"…COLUMN…"`（`0x1410DA532`） | `numColumns × step` |
> | (B) `param_3 == -1` | `numLines = count/rand` | `numColumns <= numLines/2` ⇒ 保证 **numLines ≤ 2·numColumns** | `"…LINE…"`（`0x1410DA641`） | `numColumns × step` |
>
> (B) 会把"行"压得比"列"小 → 形状是**横宽长条**，但打印串写的是 `LINE`（自洽）；
> (A) 保证列不超过行两倍 → 形状**偏竖**，打印串写的是 `COLUMN`（自洽）。
> **⇒ 两个串与各自算法是一致的，不存在"串写反"**。本次抓到的真实调用走 **(B)**（`param_3 == -1`，见 §3.1）。

**结论（已证实）**：
1. **两个分支的收紧条件互为镜像**：(A) 保证 `numColumns ≤ 2·numLines`，(B) 保证 `numLines ≤ 2·numColumns`。=> 禁止 1×N / N×1 极端长条（除非 count 太小）。
2. **`ceil` 的 +1 修正是真的**：`0x1410DA491 inc edi`（A）、`0x1410DA5A1 inc edi`（B）、`0x1410DA7CD inc edi`（REDONE）。
3. **`lineWidth = numColumns × step`**：三处都是 `movd xmm0,<numColumns>` 再 `mulss [rsi+0x30]`（`0x1410DA4F4`/`0x1410DA604`/`0x1410DA7FB`）。
4. **随机数调用 `0x140A82E00` + `0x142D6E453` 在 (A)(B) 两个分支里都出现**；
   (A) 分支即使调用方给了列数也**照样先摇随机数当除数**（`0x1410DA44D`→`0x1410DA46A idiv ecx`）——**为什么不用 `param_3` 未证实**（列入 §⑦）。
5. `count` 恒为 `rsi[+0x14]`（该分类记录的单位数），`0x1410DA42B mov r15d,[rax]`。

**最宽线**：每个分类打印后都执行

```
w = (float)colCnt[cat] * step                   ; 0x1410DA66A movd xmm0,r14d(=colCnt) → 0x1410DA672 mulss [rsi+0x30]
if (widestCat == -1 || maxLineWidth < w) { maxLineWidth = w; widestCat = cat; }  ; 0x1410DA67B cmp edi,-1 / 0x1410DA680 comiss xmm0,xmm7 / 0x1410DA683 jbe / 0x1410DA68D movaps xmm7,xmm0
```
（`widestCat` 存在 `[rsp+0x58]`，初值 `-1` @`0x1410DA39E`；`maxLineWidth` 存在 `xmm7`）

### 3.3 第二步：「最宽线回算」（REDONE）—— **门是 `总行数 > 1`**

循环结束后：

```

                lineCnt[i]--;                                       ; 0x1410DA7EA dec ebx
                if (lineCnt[i] <= 1) break;                         ; 0x1410DA7E5 cmp ebx,1 / jle

```
* 分类没有单位时：打印 `0x1432A06B0 "      Category '%s' has 0 units"`（循环 0x1410DA698–0x1410DA6B0，`lVar21==lStack_190` 时）或 `0x1432A0548 "      Category '%s' has 0 units"`（0x1410DA3DE–0x1410DA414）。
* **分类顺序不被 REDONE 改写**（REDONE 只改各分类自己的列/行），**仍未找到**任何按"宽度"重排分类的代码。
* **REDONE 的形状语义**（用上表名字读一遍就通了）：`lineCnt = ceil(sqrt(w/maxWidth))`、`colCnt = ceil(count/lineCnt)`，
  于是**行数被"正面宽度不能超过 maxWidth"反推出来**，列数再把宽度拉伸到接近 maxWidth；
  收尾循环 `colCnt*lineCnt - count > colCnt` 的含义是**"最后一行空槽数不得超过一行有多少槽"**（避免出现一个几乎空的尾巴行）。

### 3.5 第四步：写组头（**这就是「深度怎么叠加」的载体**）

> 注意 `+0x1C` 存的是 **maxCols**、`+0x20`/`+0x2C` 存 **totalLines** —— 与第一刀「一个 id」的说法不同，第一刀只是没读到。
> `+0x2C` 后被状态机当作"总行数"用（`0x14110B148 cmp ecx,[r15+0x2c]`）。

**★ 每行账本 `group_descriptor[+0x128]`（stride 0x20）** —— 这次一并钉死了它的存在与用法（依据 `0x14110B056 mov r15,[rsi+0x128]`）：

| 行记录偏移 | 字段 | 依据 |
|---|---|---|
| `+0x00` | `slotCountInThisLine` | `0x14110B096 cmp dword [rdi+rax],esi`（rax=`[r15+0x30]`） |
| `+0x08` | `slotId[]` 指针（指向该行各槽的 **槽序号**） | `0x14110B0C2 mov rcx,[rdi+rcx+8]` → `0x14110B0CC mov edx,[rcx+r13*4]`（取第 r13 个槽序号） |
| `+0x10` | `f32` 初值 `0x7F7FFFFF`（FLT_MAX），随后被写入"该槽最近单位距离" | `0x14110B084 mov dword [rdi+rax+0x10],0x7f7fffff`；`0x14110B120 movss [rdi+rbx+0x10],xmm0` |
| 行记录基址 | `[r15+0x30]`（即"行表自身的描述符"） | `0x14110B080 mov rax,[r15+0x30]` |
| 行数上界 | `r15[+0x2C]` = **totalLines** | `0x14110B070 cmp dword [r15+0x2c],r12d / jle` |

> 即：`group[+0x128]` 是一个"每行一条账本"的表，每条 32 字节，里面存**该行有哪些槽（槽序号）**以及**每槽到最近单位的距离**。
> §5.3 的 `slot[+0x14]`/`[+0x18]` 之所以要被当成"单位位置"来算距离，是因为**实际单位位置表在 `group[+0xF8]`（stride 0x30，`+0x1C` 存槽序号）**，`0x14110B0DA imul rdx,rax,0x3c` 用槽序号去索引 60 字节的槽表 —— 三者串起来的链是：
> **行账本(`+0x128`) → 槽序号 → 槽表(`+0x10`, 0x3C) → 单位账本(`+0xF8`, 0x30) → 单位对象**。

**(c) 里两个槽字段的值**：`slot[+0x14] = depthAccum`、`slot[+0x18] = 0.5f × step`。
依据：`0x1410DADA8 movss [rax+r13+0x14],xmm7`；`0x1410DADAF movss xmm0,[r14+0x30]` → `0x1410DADB5 mulss xmm0,xmm11`（xmm11=0.5f，`0x1410DAB38`）→ `0x1410DADBE movss [rax+r13+0x18],xmm0`。
> ⚠️ **这两个字段的类型/用途在别处被当"坐标"读**（状态机算距离），与这里当"纵深值"写**冲突**；
> 见 §④ 表内说明与 §⑦-13。**本次不替它选一个说法**。

**⇒ 结论（已证实）**：
* **纵深是一个"跨分类不重置"的累加器**：`depthAccum`（xmm7）**只在布局开始时清一次 0**（`0x1410DAAE8 movaps xmm7,xmm13`，xmm13=0），
  之后每写完**一行**就 `+= step`（Flank 时 `+= 2*step`），循环回到 `0x1410DAB50` 取下个分类时**不清零**
  （该处只有 `0x1410DB054 mov ecx,[rsp+0x58]`、`0x1410DB058` 等，无 `xorps xmm7`）。
  => **分类 i 的起始深度 = Σ_{j<i} (lineCnt_j × step_j)**，即**严格按分类索引 0..5 依次向后叠**。
  **这就是「分类之间相对顺序由引擎索引 0..5 决定」的机制层证据。**
* **步进量 `step` = 分类记录的 `+0x30` = `2 × 单位碰撞半径`**：
  `0x1410D4418 call 0x1410EEF50`（半径）→ `0x1410D4420 addss xmm0,xmm0` → `0x1410D442A movss [rbx+0x30],xmm0`；
  半径函数内部 `movss xmm0,[type+0x358]; mulss xmm0,[obj+0x78]`（失败时返回全局默认半径）。
  ⇒ **同一分类里 `step` 由该分类中"碰撞半径最大的单位"决定**（`0x1410D43DE cmp [rdi],ecx / 0x1410D43E0 jge` 是取大）。
  ⚠️ 主排布函数读的是**分类记录**的 `+0x30`（`rsi+0x30` / `r14+0x30`），不是单位对象的 `+0x30`。
* **`2.5f`（`0x143201174`）的用途**：只在偏斜项里当基准常数（`xmm8`，`0x1410DAB41`），**不参与深度叠加**。

**偏斜项精确式**（`param_7 == 1`）：
```
bias = 2.5f - (float)colCnt[cat] / (float)totalLines       ; 0x1410DAE2B..0x1410DAE43（divss xmm1,xmm0; movaps xmm2,xmm8; subss xmm2,xmm1）
if (slot[+0x08] > 0) slot[+0x08] += bias else slot[+0x08] -= bias   ; 0x1410DAE51 comiss xmm13(=0),xmm0 / jbe 0x1410DAE5D
```
依据：`xmm8 = 2.5f`@`0x143201174`（`0x1410DAB41`）、`xmm13 = 0.0f`（`0x1410DA38E`）、
`xmm1 ← [rbp-0x80]`（= 当前分类已写槽数）、`xmm0 ← [rbp-0x48]`（= totalLines，`0x1410DAA1C mov [rbp-0x48],r14d`）。

### 3.7 写槽位之后的收尾

```
if (group[+0] == 2 || (group[+0]-7) < 2)  bVar29 = (*(int*)param_5[0] == 1);   ; 0x1410DB093..0x1410DB0A2
err = 0; FUN_141108250(group, groupObj, &err, bVar29);                         ; 0x1410DB0C5 call
if (err == 0) {
    for i in 0..slotCount-1: slot[i][+0x00] = -1; slot[i][+0x28] = 0;          ; 0x1410DB0F0..0x1410DB11F
    if (group[+0x18] > 0 && param_5->ptr && bVar29)  FUN_1410D4670(...);       ; 0x1410DB130..0x1410DB159
    else                                             FUN_1410D48B0(...);       ; 0x1410DB166

```
> ⚠️ **`slot[+0x2C]` 到底存"分类"还是"最宽分类"**：反编译写作 `uStack_1e0`（= `widestCat` 跟踪量），

> （因为 `widestCat` 一旦设定就不再更新它自己的值以外的用途）——但**本次未能在指令级证明** `uStack_1e0 == cat`。
> 标注：**推断**（依据：日志字段名 `DesCat` + 写槽循环内 `uStack_1e0` 未被重新赋值）。列入 §⑦。

## ④ DE 槽位记录字段表（偏移/字段/含义/依据）

**记录大小 = 60 字节（0x3C）—— 已实测**：`0x1410DADE5 imul rdi,rax,0x3c`；`0x1410F7AB4 mov eax,0x3c; mul rsi`（扩容）
**槽数组位置**：`group[+0x10]` = 指针，`group[+0x04]` = 当前写入游标，`group[+0x08]` = 容量

| 偏移 | 类型 | 字段 | 含义 | 依据 |
|---|---|---|---|---|
| `+0x00` | i32 | `unitId` | 分配到该槽的单位 id；`-1` = 空槽 | 写：`0x1410DAE04 mov [rdi+rax],r11d(-1)`；清：`0x1410DB100` |

> 依据：`0x1410DA082 movss xmm0,[rdx+rsi+8]`、`0x1410DA08B movss xmm1,[rdx+rsi+4]`、`0x1410DA091 mov eax,[rdx+rsi+0x24]`、`0x1410DA0A2`（取 `+0x2C`）。

### 5.1 下令（两条路径）

### 5.3 每帧更新（`0x14110BA03` 所在的组更新函数）—— 成阵判定

**逐单位就位检查**（`0x14110BA80`–`0x14110BBA1`）：

```

        store band → group[+0x384 + u*8][+0x04]                ; 0x14110BB65 movss [r14+4],xmm1
        store dNear → group[+0x384 + u*8][+0x00]               ; 0x14110BB6B movss [r14],xmm6
```

### 5.5 「什么时候开始接敌」

1. **`slot[+0x2C]` 是否恒等于当前分类索引**（§3.7）。需要追 `[rsp+0x58]` 在写槽循环内的写点。
2. **`FUN_1410D67D0` 的精确语义**（VA `0x1410D67D0`，不属于 group.cpp）。
   已知：`rcx=group`、`rdx=unit`、`xmm2=xmm7=dist`、`xmm3=xmm6=scale`；内部 `call [unit_vtbl+0x220]` 取半径后
   `mulss xmm3,xmm6`、再 `comiss xmm0(=1e-7?),xmm7` 并读 `group[+0xBC]`（`0x1410D67D0` 头 0x50 字节实测）。

4. 分类 0..5 的语义前后顺序：现在只知道"按索引递增叠纵深"，不知道引擎是否在别处把某分类强制放到最前。
   候选调查点：`group[+0x34]`（分类记录里的"子类型数"）与 `+0x38`/`+0x100` 两张宽度/上限表的**初始化者**。
5. **`0x1410D9E34` 的调用者**（本次只拿到它所在函数体，未确认入口）。它由"某分类的首单位"触发 —— 需要找回边。

   （本次只读了 `0x1410F02xx`–`0x1410F09xx` 与 `0x14110BA80`–`0x14110BC6B` 两段）。

    从而决定所有分类的初始形状）。本次只确认了"被 `cvttss2si` 截成 int 且 `<1` 时被钳到 1"。
11. **`0x1410D95F0(unit, 0)` 那 6 个分类的完整判据**（本次只读了头部：RTTI 转换 + `type[+8] == 'F'` 分支 + `switch type[某偏移]`）。

12. **`0x1410DA44D` 分支里"调用方给了列数却仍用随机数"是否为编译器把 `param_3` 的存在形式搞混** ——

13. 🔴 **槽记录 `+0x14` / `+0x18` 的语义冲突（本次最要紧的未决项）**：
    * 布局期（`0x1410DADA8` / `0x1410DADBE`）把 **`+0x14 = 累计纵深`、`+0x18 = 0.5×step`** 写进去；
