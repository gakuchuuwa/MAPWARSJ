## 二、上报消息机制（谁 → 谁 → 怎么办）

### 2.1 发送端（谁上报）—— 实测只有 2 个直接调用点

`FUN_1410f1de0` 的**直接 call 点只有 2 处**（用 `E8 rel32` 全 `.text` 扫描，目标 == 0x1410F1DE0）：

| 调用点 | 所在函数 | 函数大小 | 场景（实测） |
|---|---|---|---|
| `0x140D2F28B` | `FUN_140d2f230` | 107 | **动作完成通知**：`sub edx,0x1F4; je; cmp edx,0x1B; jne` → 只在动作结果 == 0x1F4 或 0x1F4+0x1B(=0x20F) 时才上报；文件名串 `14324BF38 '  Ignoring movement completion notify for non-movement action.'` |
| `0x140D3204B` | `FUN_140d31cf0` | 13555 | **挨打**：同一条 0x1F4 / 0x20F 门槛；同函数内 `143248570 '  I took some damage from Unit #%d, hp=%d.'`、`1432485A0 "    I'm dead, I give up."` |

**两个 call 点前 6 条指令完全相同**，即 DE 只有一条上报调用样式：

```asm
; rdi/rsi = Action 对象；rbx/r14 = 消息对象
mov  rcx,[unit+8]            ; 单位
mov  edx,[rcx+0x210]         ; 组 ID
cmp  edx,-1
je   skip                    ; 没组 → 不上报
mov  rcx,[rcx+0x18]          ; 玩家/拥有者
mov  rcx,[rcx+8]
call 0x141604060             ; 组ID → group 对象（找不到→skip）
mov  edx,[msg+8]
sub  edx,0x1F4               ; 0x1F4 == 512
je   send
cmp  edx,0x1B
jne  skip
send:
mov  rdx,[action+8]
xor  ecx,ecx
mov  r9d,[msg]               ; p1  (实参 = 消息对象第 0 个 dword)
xor  r8d,r8d                 ; p2  = 0
mov  [rsp+0x28],ecx          ; p3  = 0
mov  [rsp+0x20],ecx          ; p4  = 0
mov  rcx,rax                 ; arg1 = group*
mov  edx,[rdx+8]             ; arg2 = 单位 ID（= 单位对象 +0x210 的组ID 旁的字段）
call 0x1410F1DE0
```

### 2.2 消息结构与签名（实测，非猜）

```
void FUN_1410f1de0(group *p1,  int unitId /*param_2*/,  int notifyType /*param_3*/,
                    int p1d /*param_4*/,  int p2d /*param_5*/,  int p3d /*param_6*/)
```
- `param_3` = 通知类型：**0 → `UnderAttack`(VA 0x14408CC40)**，**1 → `EnemySighted`(VA 0x14408CC50)**，其它 → `Unknown`(0x14408CC60)。
- 函数体**只做两件事**：取类型串，调 `FUN_140b6ef80`（通用 logger）**打两条日志**，`return`。
  1. `0x1432A0DC0` = `"notify: entered with NotifyType=%s, p1=%d, p2=%d, p3=%d"`
  2. `0x1432A0DF8` = `"NOTIFY: Unit #%d sends %s p1=%d, p2=%d, p3=%d."`（`%d` = `param_2` 单位 ID）
- 🔴 **`FUN_1410f1de0` 没有 callee（`### callees:` 为空），即它不转发、不入队、不改任何 group 状态。**
  ⇒ 名字叫 notify，**实质上是一个打印口**；「收到后 group 做什么决策」不在此函数里。
- 🔴 **payload 实测全 0**：上游两个调用点把 `p1d/p2d/p3d` 都压 0（`p1d` 取 `[msg]`，在挨打/动作完成这两条路径上其值未证实非 0）。
  ⇒ **消息本身不带「敌人是谁」**；要判断威胁只能靠 group/单位自己再查（见 §三 group 侧的 `attacker` 复检循环）。

### 2.4 上报链全图（谁 → 谁 → 怎么办）

## 三、目标选择判据（含伪代码）

### 3.1 group 侧 UTS 轮询 —— `FUN_14110c7d0`

汇编实读（`0x14110CB03`–`0x14110CC90`）：

```asm
; rsi = 发起单位, r15d = 起始索引, edi/esi = 计数
  mov r13d, r15d                 ; r13 = 分类索引 k
cat_loop:                         ; for (k = start; k < 6; k++)    ← cmp r13d,6 @0x14110CC84
  mov rbx,[rsi+0x1D8]             ; 分类表头（双向链表）
find_node:
  cmp [rbx+0x10], r13d ; je found ; 节点 +0x10 == 分类号
  mov rbx,[rbx]                   ; next
  cmp rbx, head ; jne find_node
  jmp next_cat                    ; 没有该分类 → 下一个
found:
  test rbx,rbx          ; je next_cat
  cmp  [rbx+0x14], r15d ; jle next_cat   ; 该分类单位数 <= 起始 → 跳过
  mov  rax,[r14]                  ; 单位 vtable
  movaps xmm7,xmm8                ; xmm8 = 0
  maxss xmm7,[rbx+0x2C]           ; xmm7 = max(0, node+0x2C)   ← node+0x2C 是该分类的"宽度/阈值"
  mov  rcx,r14
  seta dil                        ; dil = (node+0x2C > 0)
  call [rax+0x610]                ; 谓词(单位)   ← 影响下面选哪个常数
  test eax,eax ; je ...
  mov  rax,[r14]
  mov  rcx,r14
  movss xmm6,[rbx+0x2C]           ; xmm6 = node+0x2C
  call [rax+0x248]                ; xmm0 = 我的射程(attackRange)
  addss xmm0, xmm11               ; xmm11 = 浮点常数，实测 0x14320D518 → 见 §四
  comiss xmm6, xmm0 ; jbe ...     ; 阈值 <= 射程+常数 → al=1
  ; ---- 选基准 xmm6 ----
  ; 若 dil(阈值>0) 且 al  → xmm6 = xmm9   (0x1432064A4 = 0.0)
  ; 若 dil 且 !al         → xmm6 = xmm8   (0.0)
  ; 若 !dil               → xmm6 = xmm10  (0x1432062BC = 0.25)
unit_scan:                         ; for j in [r15, node+0x14)
  mov  rcx,[global]              ; 0x144114100 区的全局对象
  call 0x140d6acc0               ; → 单位表
  mov  rdx,[rbx+0x20]            ; 节点 +0x20 = 单位 ID 数组
  mov  edx,[rdx+rbp]             ; 第 j 个单位 ID
  call 0x141617db0               ; ID → 单位对象
  test rax,rax ; je next         ; 无效 → 跳过（计数不增）
  mov  rdx,r14
  mov  rcx,rax
  call 0x14124E620               ; d = 距离/射程(该单位, 我)
  subss xmm0, xmm6               ; d -= 基准
  comiss xmm7, xmm0 ; jae hit    ; if (xmm7 >= d) → 命中
next:
  inc edi ; add rbp,4
  cmp edi,[rbx+0x14] ; jl unit_scan
  jmp next_cat
hit:
  ; 找到了！
  mov rcx,rsi ; call 0x1410DCF40   ; 取分类名 → 日志
  ; 日志 0x1432A0FF0 = "   We have a UTS that's in range, Category=%s."
  ; 备份 ID 数组 → [rsi+0x1D8] 区
  mov  eax,[rsi+0x140]
  and  eax,0xFFFFFFEF        ; 清 bit4
  or   eax,0x8               ; 置 bit3
  mov  [rsi+0x140],eax       ; ← 单位标志位：bit3=1, bit4=0
  mov  r9d,[r14+8]
  call 0x14110A210           ; 开打（极小转发）
next_cat:
  inc r13d ; cmp r13d,6 ; jl cat_loop
```

**判据小结（实测，不加解释）**：
1. 遍历 **6 个阵型分类**（`cmp r13d,6`，与阵型分类 6 类同一套 0..5）；
2. 每个分类：节点 `+0x10` = 分类号，`+0x14` = 单位数，`+0x20` = 单位 ID 数组，`+0x2C` = 该分类的**距离阈值/宽度**；
3. 阈值先与「我的射程 + 常数」比一次，用来**选基准值**（0.0 或 0.25）；
4. 逐个单位算 `0x14124E620(单位, 我)`，**减去基准**后与 `max(0, 阈值)` 比较，`阈值 >= 差` 即**命中**（首个命中就跳出，即"最近优先"）；
5. 命中后：**打日志 `We have a UTS that's in range, Category=%s`**、置单位标志位 `[unit+0x140] &~ 0x10 | 0x8`、调 `FUN_14110a210` 开打。

### 3.2 group 侧 BUTS 分类统计 —— `FUN_1410dc3a0`

汇编实读（`0x1410DC3A0` 起）：外层遍历分类链表，每个节点取 `+0x10`(分类号)/`+0x14`(单位数)：
- `+0x14 == 0` → 日志 `0x1432A0793 "   BUTS: '%s' has zero units"`（参数 = 分类名，`call 0x1410DCF40` 取得）；
- `+0x14 != 0` → 日志 `0x1432A07B0 "BUTS: '%s' has %d units"`（`%d` = 单位数）；
- 然后逐单位（`[node+0x20]` ID 数组 + `0x141617DB0` 查对象）取 **`[obj+0x78]` 浮点**（`movss xmm7,[rcx+0x78]`，经 `call [vtable+0x210]` 之后）参与与 UTS 相同的 `0x14124E620` 距离比较。

### 3.3 单位侧「找目标 / 能不能打」—— `FUN_140cfe6f0` 内实测的判定序列

来自反汇编（调用点已列 §一），按出现顺序：

```asm
; 1) 目标有效性 + 可达性
call [vtbl+0x408]                  ; (targetId, 0, 0.0, 0, 0, 0)  0x140CFFA66
  ; 失败 → 日志 0x143248F70 "Either invalid target (%d) or not able to path to it, stopping."
; 2) 又一档（带 pathable 结果码）
call [vtbl+0x408]                  ; xmm2=0.0                    0x140D000CB
  ; 失败 → 日志 0x143248FC0 "Either invalid target (%d) or not able to path to it (%d), stopping."
; 3) 目标命中 → 取新目标
call 0x140CF8AC0                   ; 从候选里取目标
  ; 成功 → 日志 0x143248ED8 "      Found a new target id=%d."
; 4) 资源类目标（"Found a new target id=%d." 同一段）
call 0x14096D8F0                   ; 距离
movss xmm1,[0x143225F98]           ; 25.0
comiss xmm1,xmm0 ; jb 放弃          ; 25.0 < 距离 → 放弃
; 5) 打到就绪
movss xmm2,[0x143203860]           ; 0.1
call [vtbl+0x408]                  ; 0.1 余量再次确认
```

> 🔴 **注意（避免误读）**：`0x143225F98`(25.0) 那一段的日志是 **`Found a new target id=%d.` / `Going to gather id %d.` / `I'm a gatherer but I don't have a target type, failing search.`(0x143249060)**
> ⇒ **25.0 是"资源/采集目标"的取舍距离，不是接敌距离**。已按事实归入 §四并标注用途。

### 3.4 aisearch.cpp 的接敌层

见 §1.3：**未找到**。aisearch 区段内的函数全是编组（control group ≤60）、单位批处理（`numUnits`/`unitID`）与日志辅助。

## 五、「已证实 / 推断 / 未找到」三档

### ✅ 已证实（有反汇编或字节级依据）

1. `FUN_1410f1de0` 是**纯日志口**：无 callee，两条日志串 `0x1432A0DC0` / `0x1432A0DF8` 实测为
   `"notify: entered with NotifyType=%s, p1=%d, p2=%d, p3=%d"` 与 `"NOTIFY: Unit #%d sends %s p1=%d, p2=%d, p3=%d."`。
2. 类型枚举 **0=`UnderAttack`(0x14408CC40)、1=`EnemySighted`(0x14408CC50)、其它=`Unknown`(0x14408CC60)**。
3. 全 `.text` 里**只有 2 个直接 call 点**：`0x140D2F28B`（`FUN_140d2f230`，动作完成）、`0x140D3204B`（`FUN_140d31cf0`，挨打）。

6. `MasterCombatObject.cpp` 的 6 个 assert 点**全部**是 `weapon_offset_x/y/z` 的取值/赋值，与攻击判定无关。
