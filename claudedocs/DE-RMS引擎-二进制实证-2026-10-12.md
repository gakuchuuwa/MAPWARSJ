## 一、一句话结论

**DE 的随机地图引擎就在 `AoE2DE_s.exe` 里**，是一套 **7 模块流水线**（1 个脚本控制器 ＋ 6 个生成器），整片类名/方法名/调试串都留在二进制里（**184 条**，其中 **167 条**能在代码里反查到引用点），连**源码路径都没剥**：

```
F:\Agents\PhoenixBuilders-08\p4\portland_group\Aoc\Source\Game\RandomMap\RandomMapScriptControllerBase.cpp
F:\Agents\PhoenixBuilders-08\p4\portland_group\Aoc\Source\Game\RandomMap\Modules\ObjectGenerator.cpp
```

- `portland_group` / `PhoenixBuilders-08` = DE 的构建代号与 build 机路径（**PVCS 风格**，不是 git）。
- 引擎代码集中在一片：**VA 0x14135D000 – 0x14138E000（约 1.1 MB，618 个函数）**，外加解析器的少量代码在 0x14137F000–0x14138D000、控制台变量在 0x1401B08D4。
- **确定性是对外承诺**：每个模块跑完都打一行 `(RandSync) module completed with random: %d`，并有 `(RandomMapSync)` 前缀的整套日志 —— 多人/回放要靠它对齐随机数状态。
- 🔴 **命令是靠哈希认的，不是靠字符串比的**：解析器对每个标识符算 **djb2-XOR 哈希**（`h = 5381; h = h*33 ^ c`），再拿哈希去查 `std::unordered_map`。**所以镜像里永远不会有 `create_land` 这类命令名**（见 §7.2，已在反编译代码里逐行证实）。

- `base_size` ＋ `clumpiness_factor` ＋ `zone` ＋ `area` 是 **land 的四个几何参数**；

- `mPlaceOnForestZone` / `mForestGroupIds` / `mDistancesToForest` 是**「放在林区上／离林区多远」**这一整套；
- `mMinConnectedTiles` 是**连通格数下限**。

## 四、流水线与确定性（RandSync）

日志串（全部有代码引用）：

| 日志 | 串 VA | 引用点 |
|---|---|---|
| `(RandomMapSync) Initiating random map script (rms) generation.` | 0x1432C24E8 | 0x14138819A |
| `RGE_Random_Map_Module::generate()` | 0x1432C1738 | 0x141362D55 |
| `(RandSync) Random Seed at moment: %d.` | 0x1432C17C8 | 0x141362E86 |
| `(RandomMapSync) Post Init:` | 0x1432C17A8 | 0x141362E03 |
| `(RandomMapSync) Map after generating module %s:` | 0x1432C1808 | 0x141362FE9 |
| `(RandSync) module completed with random: %d` | 0x1432C1838 | 0x141363044 |

⇒ **每个模块生成完毕都记录一次随机数状态**（`module completed with random: %d`），并有 `randomize_stack`（0x141363536）单独处理栈的随机化。
**这就是 DE 随机地图多人一致性的机制**：不是「同一 seed 就必然一致」的赌博，而是**逐模块对随机状态做同步断言**。

**✅ 已反编译证实（`RGE_Random_Map_Module__generate` @ 0x141362D10，1258 字节）**：

```c
// 1) 模块表在 module+0x10，是一张链表；先按「模块自己带的 float 字段 module+0x30」升序插入排序
while (plVar6 = plVar4, plVar6 != NULL) { ... *(float *)(*plVar6 + 0x30) < *(float *)(*plVar7 + 0x30) ... }
// 2) 排序后逐个跑：vtable +0x10 = getModuleName，vtable +8 = generate(输出 Result)
(**(code **)(*module + 0x10))(module, &name);      // 取模块名，用于日志
(**(code **)(*module + 8))(module, &result);       // 跑这个模块
if (result.signal != 0) { *out = /* 把 Result 原样交给上层 */; return; }   // 任一模块失败 → 整条流水线中止
log("Map after generating module %s:", name);
uVar9 = FUN_140903af0(ctx, "generate", 0xcf);      // 记一次 RandSync 值
log("(RandSync) module completed with random: %d", uVar9);
```

**⇒ 结论（与旧文档口径不同的三条）：**
1. **模块顺序不是写死的调用链，而是运行时按一个 float 字段排序** —— 每个模块自带顺序权重（`module+0x30`），改一个数字就能改流水线顺序；
2. **模块接口只有两个虚函数槽**：`+8` = `generate(输出 Result)`，`+0x10` = `getModuleName()`（返回类名，日志用）；
3. **生成器返回 `Result` 对象，一旦带错误信号整条流水线立刻中止**（不是在生成器内部弹错），所以 `(RandomMapSync)` 报错后地图会保持中止态。

### 7.2 ✅ 命令字表之谜 —— 已解开：**djb2 哈希查表**

**`create_land` / `create_object` / `create_terrain` / `land_position` / `terrain_mask` … 这些命令名，在二进制里一个都没有** —— 原因不是「藏在压缩包里」，而是 **解析器根本不比字符串，它比哈希**。

已排除的找法（全部实测）：大小写不敏感扫全文 → 0；UTF-16LE → 0；去掉下划线（`createland`）→ 0；驼峰 → 0；**全 256 个单字节 XOR 密钥**逐个扫 → 0；8 字节指针表 → 0 处；4 字节 RVA 表 → 只有 `.reloc` 里的巧合命中。

**✅ 真正的机制（反编译 `08_Script_Controller__RANDOM_OBJECT_14137fd20` @ 0x14137FD20，6605 字节 = 就是 `do_command`）：**

```c
// 先按 token 类型分流：switch(*pplStack_90)  case 0=结束 1=字符串 2=数字 3=标识符
// 标识符一路（case 3）：
uStack_13c = 0x1505;                       // 5381
if (p != NULL) {
  c = *p;
  while (c != '\0') {
    uStack_13c = uStack_13c * 0x21 ^ (int)c;   // 5381*33^n … 即 h = h*33 ^ c
    p++; c = *p;
  }
}
plVar29 = sub_14137B800(controller + 0x131, &key, &uStack_13c);   // 用哈希查 unordered_map
```

⇒ **这就是「命令名一个都不在镜像里」的原因**：命令表是 **`哈希 → 处理函数`** 的表，源码侧由宏把命令名编译成 32 位哈希；运行时对脚本 token 现算同一个哈希再查表。
⇒ 副产物：**报错带「文件 + 行号」**（`FUN_140A08840(result, 0, "…RandomMapScriptControllerBase.cpp", 0x930)`，0x930 = 2352 行）。
⇒ ⚠️ **未确证的一环**：这张表的键（哈希）**不以 32 位常量形式躺在镜像里**（实测 40 个公开 RMS 关键字的 djb2-XOR 哈希，逐个搜全文命中 0）。最可能是**启动时从一段混淆字符串池现算现建表**（见 7.3），下一步读 0x1443C9E98 一带的初始化代码就能定论。

### 7.3 🔴 新发现：一片「逐块 XOR 混淆」的字符串池 ＋ `random_map.def`

在 RMS 字符串表后面（**VA 0x1432C3510 – 0x1432C3740，约 560 字节**）有一片**混淆过的字符串**：按约 16 字节一块、**每块一个自己的密钥字节**做 XOR。已解出的片段（可复现）：

| 解出的明文片段 | 说明 |

## 九、对 MAPWARSJ 的直接用处

1. **`number_of_groups` 的两级缩放**（地图尺寸 × 玩家人数）——项目文档此前没有这两条；
2. **`base_size / clumpiness_factor / zone / area`** 是 land 的四参数，`group_area` 才是组半径；
3. **`mResourceDelta` 是数量不是位置**；
4. **候选点是「栈」不是「全局随机撒」**：`make_placement_stack` → `GiveRandomTile` → `EnoughAdjacentTiles`；
5. **玩家布点有两套**（随机散布 / 按队伍成组），入口 `do_player_positioning`；
6. **文档要补的一节**：DE 的 actor area（`mActorArea*`）与 forest zone（`mPlaceOnForestZone`/`mForestDistances`）机制。
