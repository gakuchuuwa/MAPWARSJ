## 一、最重要的一条结论（先说）

**DE 的战斗参数（`sn-*`）和我们现在的战斗参数，不是同一类东西：**

| | DE | 我们 |
|---|---|---|
| 参数作用对象 | **单位／战斗小组的实时行为**（反应距离、集结规模、间距、目标模式、计时器） | **战略级军团决策 ＋ 抽象战力结算**（三势环、光环、追击走廊、城池抽签） |
| 行为执行 | 引擎内 A* 寻路 ＋ 逐单位转向 ＋ waypoint 队列 | 沿**道路折线**行军 ＋ 到达后按战力结算一场战斗 |
| 谁在决策 | 引擎内 `UnitAIModule` / `aisearch` ＋ `.per` 脚本规则 | `src/ai/bt/LegionBehaviors.ts` 行为树 |

⇒ **所以「抄参数表」不能 1:1 搬**。真正能搬的是三类：
1. **同构的旋钮**（反应/接敌半径、追击舍弃半径、打不打得过闸门、集结下限）→ **直接换 DE 的值**（见第四节 ✅）；
2. **我们缺的旋钮**（阵型间距、巡逻上限、墙目标模式、攻城优先级）→ **补参数 + 补逻辑**（🔴）；
3. **不同构的**（`sn-local-targeting-mode` 这种逐单位目标模式）→ 只能等**反编译算法体**才能真对齐（🟡）。

### 2.3 阵型本身（不是参数，是枚举）

DE **只有 6 种阵型**（字符串 0x14320EC60–0x14320ECF0，全是明文）：
`Disband Formation` / `Horde Formation`（散兵） / `Box Formation`（方阵） / `Line Formation`（横队） / `Staggered Formation`（交错） / `Flank Formation`（包抄）
＋ 姿态：`AggressiveUnitStance` / `No Attack Stance` / `DefensiveUnitStance`

⚠️ **注意**：DE 的「阵型」是**引擎把一批单位排开的算法**（配合 `sn-group-form-distance` 等间距参数）；我们现在的「阵型」是**每支军团 9 个格位的美术摆位**（见第三节）。**两者不是一回事**——这正是「行军阵型模仿 DE」真正的缺口所在。

## 四、逐条对照表

### ✅ 同构 —— 可以直接把 DE 的值搬过来试（改一个数就能见效）

| DE 参数 | 我们的对应物 | 差异性质 |
|---|---|---|
| `sn-enemy-sighted-response-distance` | `AI.HUNT_ENEMY_LEGION_RADIUS = 0.8` | 同为「接敌反应半径」，只是单位不同（DE=格，我们=纬度） |
| （DE 的追击放弃逻辑） | `HUNT_ENEMY_LEGION_ABANDON_RADIUS = 1.1` | 同构 |
| `sn-attack-intelligence` / `sn-attack-winning-player-factor` | `AI.ENEMY_STRENGTH_MAX_RATIO = 3.0` | 同构（都是"打不打得过"闸门） |
| `sn-initial-attack-delay` / `-type` | `TacticalConstants.PHASE_*`（三幕 0/40%/80%） | 同类（开战节奏），口径不同 |
| `sn-maximum-patrol-distance` | 无（我们有追击走廊，不是巡逻） | 🟡 半同构 |
| `sn-dropsite-separation-distance` | 无（我们没有投放点概念） | 🟡 需先有模型 |

### 🔴 我们没有、DE 有 —— 这是"模仿行军阵型"真正的缺口

| DE 参数 | 缺什么 |
|---|---|
| **`sn-group-form-distance`** | **队形间距**（阵型真正靠它排开）——我们现在阵型是固定 9 格位，**没有"按间距把 N 个单位排开"这一层** |
| `sn-attack-group-gather-spacing` / `sn-attack-group-size-randomness` / `sn-attack-separation-time-randomness` | 集结间距与随机性 |
| `sn-minimum/maximum-attack-group-size` / `sn-number-attack-groups` | 作战小组的规模与数量（我们以"整支军团"为单位） |
| `sn-group-leader-defense-distance` / `sn-group-commander-selection-method` | 组长/主将的护卫与推选 |
| `sn-wall-targeting-mode` / `sn-gate-type-for-wall` / `sn-build-*` | 墙/门的目标模式与筑墙（我们无城墙目标概念） |
| `sn-free-siege-targeting` / `sn-building-targeting-mode` | 攻城单位的目标优先级 |
| `sn-local-targeting-mode` / `sn-sentry-distance-variation` / `sn-max-revenge-distance` | 单位级目标模式的细粒度旋钮 |
| `sn-maximum-patrol-distance` + `sn-enable-patrol-attack` | 巡逻（我们只有追击） |

### 🟡 我们有、DE 没有

三势环／攻防环／名将光环／九格系数、翻盘 luck、三幕结算、追击走廊（45°/1.0）、枪打出头鸟（1.5）、`FAILED_TARGET_COOLDOWN_MS`、`HUNT_BLOCKED_TIMEOUT_MS`。

**这些是主人的设计，不在"模仿 DE"的范围内 —— 本表不动它们。**

## 五、结论：现在能"模仿"到什么程度

1. **能立刻做的（改参数，不动算法）**：把 ✅ 那一栏的 DE 实值抄进来当候选，跑对比看观感。**这一步不需要反编译，也不需要动主人的设计参数**（要动必须先问）。
2. **"行军阵型模仿 DE"的真正缺口**：我们缺 **`sn-group-form-distance` 这一层（按间距把一批单位排开）** 与 **6 种阵型的排布算法**。我们的"阵型"是 9 格位美术摆位，DE 的是引擎排兵 —— **这必须靠反编译 `group.cpp` / `motion.cpp` 才能拿准**（选②/③那条路）。
3. **"寻敌路径模仿 DE"**：我们的寻敌是**战略级选城/选军团**；DE 的是**单位级 A* + influence map**。要真对齐必须反编译 `aisearch.cpp` / `PathingSystem.cpp`（选②）。
4. **"攻城逻辑模仿 DE"**：DE 有 `sn-free-siege-targeting`、`sn-building-targeting-mode`、`GarrisoningMode` 等一整套；我们的攻城是「半径 0.15 + 战力结算」。对齐要么抄参数补分支，要么反编译 `MasterCombatObject.cpp`（选④）。
