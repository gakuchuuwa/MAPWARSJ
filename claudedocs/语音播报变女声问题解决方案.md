# 语音播报「云健男声消失、变成女声」问题 — 根因与解决方案

> 日期：2026-07-20
> 涉及文件：`src/audio/EdgeTtsClient.ts`（新增）、`src/audio/SpeechAnnouncer.ts`
> 相关记忆：`memory/kangkang-voice-registry-broken.md`

## 一、现象

游戏战斗播报原本是云健（浑厚男声），某天起变成女声。期间别的 AI 做过多轮修复
（补女声黑名单、按 URI 识别损坏音色、降调伪装男声、多候选顺延……）都没能真正修好——
偶尔没声、偶尔还是女声。控制台 `[Speech] 使用:` 明明打印男声名（如 Kangkang），实际发声却是女声。

## 二、根本原因：三层全塌，且都不在游戏代码里

排查用二分法逐层验证，最终定位三个独立病因，**没有一个是游戏代码的 bug**，所以怎么改代码、怎么 git 回滚都没用：

1. **系统语音：康康音库损坏。**
   注册表 `HKLM\SOFTWARE\Microsoft\Speech_OneCore\Voices\Tokens\MSTTS_V110_zhCN_KangkangM`
   的 `VoicePath` 指向了 `M2052Yaoyao`（瑶瑶女声音库）。把它改回指向康康自己的音库 → **没声**，
   证明康康音库数据本身已损坏；系统指向瑶瑶其实是「至少能出声」的续命补丁。
   本机浏览器可用中文语音只剩慧慧、瑶瑶两个女声。
   → 这解释了「日志男声名 ≠ 实际发声」：引擎选中康康，音库却是瑶瑶。

2. **浏览器：Edge 撤除了云健。**
   云健/云希从来不是本机语音，而是 Edge 白嫖微软 Azure 的在线 Neural 语音
   （`zh-CN-YunjianNeural` / `zh-CN-YunxiNeural`）。新版 Edge 已把它们从网页 Web Speech
   接口撤除，网页（游戏）再也点不到。

3. **别的 AI 的修复方向错了。**
   那些修复都在「怎么从现有系统语音里挑出男声」上打转——但系统里根本没有能用的男声了，
   再怎么挑都是女声或降调女声。方向错，所以修不好。（这些修复现已转为回落安全网，见下。）

## 三、解决方案：游戏自建云健直连通道

既然云健是微软在线服务，就让游戏**绕过浏览器语音接口、直接连微软那个在线 TTS 端点**
（Edge「朗读」用的同一个 WebSocket）取回云健。

### 关键验证（都在 Node 等价环境证实后才写代码）

- **微软不校验来源**：扩展 Origin / localhost / Vercel 域名 / 空 Origin 四种握手全部 101
  → 浏览器直连可行，**本地 + Vercel 一份代码通吃，无需任何后端**。
- **完整合成正常**：带浏览器 UA → 45360 字节音频、577ms，前两字节 `ff f3`（标准 MP3 帧同步头）
  → 二进制帧解析逻辑正确。
- **无 CSP 拦截**：index.html / vite / vercel.json 均无 `connect-src` 限制。

### 2026-07 有效直连参数（微软会随 Edge 版本更新）

- 端点：`wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1`
  `?TrustedClientToken=6A5AA1D4EAFF4E9FB37E23D68491D6F4&Sec-MS-GEC=<hash>&Sec-MS-GEC-Version=1-143.0.3650.75`
- **`Sec-MS-GEC-Version=1-143.0.3650.75`** ← 突然 403 时的头号嫌疑；权威值看 `edge-tts` 库的
  `constants.py` 里 `CHROMIUM_FULL_VERSION`（`py -3.14 -m pip install --user edge-tts` 装的库）。
- GEC 算法：`ticks = Date.now()/1000 + 11644473600`；`ticks -= ticks % 300`；`ticks *= 1e7`；
  `SHA256(`${ticks.toFixed(0)}${TRUSTED}`).toUpperCase()`。
- 输出格式 `audio-24khz-48kbitrate-mono-mp3`；二进制帧：前 2 字节大端 = 头长度，之后是头，余下才是 mp3。

### 代码结构

- **`src/audio/EdgeTtsClient.ts`**（新增）：封装 WebSocket 合成，`synthesize(text,{voice,rate})→Blob`。
  自带 7s 超时、连不上时 60s 内短路快速回落、同句 LRU 缓存（重复播报零延迟）。
- **`src/audio/SpeechAnnouncer.ts`**：`speak()` 里加「云健优先」通道 `speakViaEdge()`。
  成功→ `new Audio(blob)` 播放，`onplay/onended` 对齐原 `onstart/onend`（驱动 cut-in / 推进队列）；
  **任何失败自动回落到原 Web Speech 候选链**（`speakWithCandidate(0)`），直播绝不哑。
  🔊 云健/云希切换按钮现直接控制 Neural 音色。

## 四、为什么不删「别的 AI 的修复」

女声黑名单、`isReliableLocalVoice`、`isVoiceNameCorrupt`、降调兜底、多候选顺延——
现在全部转为**云健通道的回落安全网**：云健连不上时，这套逻辑尽量避开女声、实在不行降调顶上。
删掉会让回落变哑或变难听，故保留。

## 五、复现排查的方法（给下一个 AI）

1. **别信控制台的音色名**：日志打印的 voice 名 ≠ 实际发声，先怀疑系统注册表 `VoicePath` 是否错接音库。
2. **分层二分**：系统语音（`Add-Type System.Speech` 枚举 + 注册表 VoicePath）→ 浏览器接口 → 直连端点，逐层证伪，别一上来改代码。
3. **验证再写码**：直连可行性用 Node 原生 WebSocket（和浏览器同样不能自定义头）+ `edge-tts` 库（能设头，代表带 UA 的浏览器）两路对照，握手/完整合成都通过再动 TS。
4. **403 先升版本号**：Sec-MS-GEC-Version 对齐 `edge-tts` 的 CHROMIUM_FULL_VERSION，多半就好。
5. **git 回滚是陷阱**：病根在系统/浏览器，回滚只会删掉回落安全网，帮倒忙。
