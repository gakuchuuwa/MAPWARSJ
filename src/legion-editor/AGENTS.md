# 军团编辑器铁律（2026-09-09 主人重申）

**一个军团只能有一种编制。严禁出现一个军团多种编制。**

- 编制按「前排兵种 + 中排兵种 + 后排兵种 + 阵型」判断；三排兵种按顺序一致且阵型一样，就是同一种编制。素材缩放不产生新编制。
- 武将换军团：只改变该武将所属势力的军团归属，套用目标军团已保存的统一编制。
- 编辑军团：改的是这个军团本身，保存必须同步所有使用该军团的文化区、势力和武将，包括未显式填写军团名称、实际跟随文化军团的编成记录。
- 禁止把尚未保存的兵种/阵型修改，通过「套用给一家」写成同名的另一套编制。
- 「另存为新军团」必须使用未被占用的新名称；已有名称只能编辑该军团并全体同步，不得创建同名副本。
- 界面、快捷键、保存接口及后续维护必须遵守同一条铁律；不得用改名或局部覆盖掩盖同一军团的编制冲突。
- 已有编制冲突不得擅自挑一份覆盖；应由用户编辑后保存的编制作为统一结果。

维护保存接口 `vite.config.ts` 和 `tools/culture-formation-save.ts` 时也必须遵守以上规定。

## 保存入口必须分开（2026-09-09 主人要求）

- **保存武将换军团**：保存该武将所属势力的军团归属，使用目标军团已保存的统一编制。
- **保存军团编制**：保存当前军团的三排兵种与阵型，全体使用者同步。Ctrl+S 对应此项。
- **另存为新军团**：用未占用的新名称保存，并给当前武将使用。
- 卡片点击只选择，提示必须明确指出该点哪一种保存，禁止笼统写「点保存」。
